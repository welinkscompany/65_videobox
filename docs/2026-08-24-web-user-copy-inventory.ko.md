# 화면 문구 계측 — 문장형과 키워드형 (2026-08-24)

이 문서는 `codex/videobox-container-compatibility`의 `6718f11df`에서
`apps/web/src`의 사용자 노출 문구를 소스 기준으로 센 결과다. 화면 캡처나 사람의 시각
판단이 아니라, P0-2에서 문구를 바꾸기 전에 모수를 고정하는 계측이다.

## 결론

- 소스 위치 기준 **1,437개**: 문장형 **446개(31.0%)**, 키워드형 **991개(69.0%)**
- 같은 문구를 한 번만 세면 **1,142개**: 문장형 **415개(36.3%)**, 키워드형
  **727개(63.7%)**
- 따라서 "전체 화면은 문장형 문구가 더 많다"는 가설은 맞지 않는다.
- 다만 **출력 화면은 128개 중 75개(58.6%)가 문장형**이라 문장형 비율이 가장 높다.
- **편집 화면은 문장형이 106개**로 절대 개수가 가장 많지만, 전체 582개 중에서는
  18.2%다. 편집 화면의 어려움을 문장형 문구 하나로만 설명할 수는 없다.

## 무엇을 문구로 셌나

기존 `apps/web/src/user-copy-policy.test.ts`의 TSX AST 발견 방식을 기준으로 삼았다.

1. 테스트 파일과 가져온 부품인 `apps/web/src/components/ui`는 제외했다.
2. TSX 본문, `aria-label`, `aria-description`, `placeholder`, `title`, `alt`, 조건 분기의
   정적 문자열을 셌다.
3. 메뉴 목록·상태표·오류표처럼 상수에서 간접 렌더되는 문구를 놓치지 않기 위해,
   비시험 `.ts`와 `.tsx`의 한글 문자열도 후보에 포함했다. `clipNames.ts`,
   `inspectorRegistry.ts`, `editorAssetProjection.ts`, `variantOutputState.ts` 같은 화면용
   변환기가 이 범위에 들어간다.
4. `/`, `:`, `▶`처럼 글자나 숫자가 없는 순수 기호는 문구에서 제외했다. `Ctrl+Z`,
   `fps`, `VideoBox`, `+1f`처럼 화면에서 읽는 글자·숫자는 포함했다.
5. 프로젝트 이름, 시간, 파일명처럼 실행 중 데이터로 들어오는 값은 모수에 넣지 않았다.

이 모수는 **한 시점에 DOM에 동시에 보이는 개수**가 아니다. 성공·실패·로딩 조건 분기는
각각 별도 문구로 세었고, 접힌 패널 안의 문구도 포함했다. 따라서 이 숫자는 화면 밀도나
클릭 수가 아니라, 소스에 준비된 사용자 문구의 크기를 뜻한다.

## 문장형과 키워드형을 가른 기준

- **문장형**: 마침표·물음표·느낌표·말줄임표로 끝나거나, `-습니다`, `-세요`, `-해요`,
  `-있어요`, `-없어요`, `-입니다`, `-됩니다`처럼 완결된 서술·요청으로 끝나는 문구
- **키워드형**: 명사형 제목·상태·버튼, 짧은 행동 표현, 완결 어미 없이 압축한 조작 안내

예를 들어 `완성본을 만드는 중이에요.`는 문장형이고 `완성본 만드는 중`은 키워드형이다.
`드래그하거나 왼쪽·오른쪽 화살표로 한 프레임씩 조절`은 길지만 완결 문장 대신 조작
키워드를 압축한 형태라 키워드형으로 셌다. 이 분류는 "좋아 보이는가" 판단이 아니라
같은 규칙으로 다시 셀 수 있게 만든 운영 분류다.

## B에서 먼저 바꿀 범위

한 번에 전부 바꾸지 않는다.

1. **출력 상태 묶음**부터 시작한다. 문장형 비율이 58.6%로 가장 높고,
   `준비되었어요`·`만드는 중이에요`·`아직 없어요`처럼 키워드로 줄이기 명백한 상태
   문구가 한 파일(`app/OutputsPage.tsx`)에 모여 있다.
2. 상태 제목은 `준비됨`·`만드는 중`·`없음`처럼 줄이되, 실패 뒤 사용자가 해야 할 행동은
   별도 안내로 남긴다. 오류 원인과 다음 행동까지 지우면 오히려 사용성이 나빠진다.
3. 편집 화면은 문구 수가 가장 많지만 문장형 비율은 18.2%다. 따라서 전면 축약보다
   사용자가 실제로 누르는 버튼·상태 묶음을 작은 단위로 골라야 한다.
4. 색·배치·접힘 상태는 이 계측과 다음 문구 변경 범위가 아니다.

## 확인하지 않은 것

- 실제 PC·모바일 화면에서 문구가 보이는 위치와 잘림
- 대표가 버튼을 찾는 데 필요한 실제 클릭 수
- 문구 변경 뒤의 시각적 읽기 쉬움과 사람 승인

위 세 항목은 파일 계측으로 증명할 수 없으며, 목요일 화면 확인 대상으로 남긴다.
