## 3. 원인 (증거 순)

1. **재생 중 미리보기가 자기 자신을 되감는다(확정).** `preview-stage.tsx`의 효과
   `useEffect(() => { … if (media && Math.abs(media.currentTime - mediaSeconds) > 0.001) { … media.currentTime = mediaSeconds; } }, [mode, onPlaybackTimeChange, playbackSec]);`
   재생기가 `timeupdate`로 시각 t를 올림 → `seekPlayback`→`setPlaybackSec(t)` → 다시 그린 뒤 이 효과가 돌 때 재생기는 이미 t+2~19ms → **차이가 1ms를 넘으니 t로 되감는다**. 게다가 `onPlaybackTimeChange`(=`seekPlayback`)가 매 렌더 새 함수라 무관한 렌더에도 효과가 다시 돈다. 결과: 20초에 67~74번 탐색, 매번 최대 8.3초 앞 키프레임부터 다시 해독(해독/그림 3~6.6배), 영상 시간이 52~59번 뒤로 감(= 화면이 "흔들림"), 실제 진행 0.62~0.70배(= "제대로 재생이 안 된다"). 증거: 번들 호출 자리(`Ne.currentTime=Oe`, 효과 deps `[S,l,o]`), setter 스택, 그리고 **그 쓰기만 막으면 모든 지표가 맨 `<video>`와 같아짐**(30fps·1.00·뒤로 0).
2. **재생 머리·시간 글자가 0.3~0.4초마다 한 번씩 뛴다(확정).** React 상태(`playbackSec`)가 `timeupdate`(재생기 기본 ≈4Hz, 되감기 때문에 6.5Hz)로만 갱신되고, 재생 머리는 `style={{ left: … }}`로 그 상태를 따른다. 0907처럼 짧은 영상은 첫 배율이 153px/초라 한 번에 ≈46px씩 뛴다 — 눈금이 1초 간격이라 "1초 단위로 지나간다"로 보일 수 있다(해석 — 대표님 화면 미관찰).
3. **스페이스가 안 먹는 자리가 있다(확정).** (가) 영상 그림을 마우스로 누르면 초점이 `미리보기` 판(`section tabIndex=0`)에 가고, 그 판의 `onStageKeyDown`과 창 전체 처리기가 **둘 다** 재생/정지를 뒤집어 상쇄 → 스페이스를 눌러도 그대로(2번 눌러도 그대로). (나) 타임라인 밖 단추(음소거·도크 단추 등)에 초점이 있으면 스페이스가 그 단추를 누른다(접근성상 의도, 그대로 둔다). 아무것도 안 누른 상태·재생 단추·타임라인 안에서는 된다.
4. **미리보기 밖을 누르면 재생이 멈추고 0초로 돌아간다(확정, 불안정의 한 원인).** `onStageBlur` → `stopActiveMedia()`가 `pause()` + `currentTime = 0`. 재생 단추로 재생 중 타임라인 제목을 누르면 영상 2.2초 → **0초·정지**, 재생 머리도 0. 창 `scroll`도 같은 함수를 부른다(편집기는 창이 거의 안 굴러 실측에선 안 걸림). 0으로 돌아간 뒤 타임라인 상태는 옛 위치를 들고 있어, 타임라인 오른쪽 화살표 한 번에 영상이 0 → 1.6초로 뛰었다.
5. **키프레임 간격 8.3초(확정, 증폭 요인).** 탐색 한 번에 18~48ms(1초 GOP면 4~7ms). 원인 1의 피해를 키우고, 앞으로의 한 프레임 이동·J/K/L·문지르기 반응도 느리게 한다. 단독으로는 재생을 망가뜨리지 않는다(맨 재생 30fps).
6. **재생 빠르기 조절이 없다(확정).** `grep -rn playbackRate apps/web/src` → 0건. J/K/L 키 처리 없음(`L` 눌러도 정지 그대로, `playbackRate` 1).

배제·약함:
- (c) 무거운 다시 그리기: 재생 중 긴 작업 0건, CPU 6~10%, 커밋 7/초, 요청 0~1 — **이 기계에서는 주원인 아님**. 다만 커밋이 재생 시각마다 일어나 작업판 전체가 다시 그려지는 구조는 원인 1의 고리를 돌리는 바퀴다.
- (e) 파일 자체: 고정 30fps·단조 시각·faststart·범위 요청 정상 — 맨 재생 완벽. GOP만 문제(5번).
- 폴링: 미리보기가 최신이면 재생 중 요청 0.

## 4. 대표님 말의 해석과 남는 모호함

- "흔들리고, 제대로 재생이 안 되고, 불안정" = 원인 1(되감기 고리, 0.65배 속도·뒤로 55번) + 원인 4(밖을 누르면 0초로) — 실측으로 설명된다.
- "1초 단위로 지나간다" = 원인 2(재생 머리 0.3초마다 큰 걸음, 0907 배율에서 1초 눈금을 건너뜀) + 원인 1의 멈칫. **대표님 화면(GPU를 다른 모델과 나눠 쓰는 일반 Chrome)에서 멈칫이 1초까지 길었는지는 못 쟀다.**
- "초 단위로 만들면 너무 빨리 재생 → 더 느리게, 단축키로" = 몇 초짜리 장면을 확인할 때 **보는 속도**를 늦추고 싶다는 뜻으로 읽었다 → 재생 빠르기(0.25~2배) + J/K/L + 마지막 값 기억. 기본은 실제 속도(1배)가 맞다(미리보기는 완성본과 같은 속도여야 판단이 맞다).
- 남는 모호함(질문 1개): 늦추고 싶은 것이 **확인할 때만 보는 속도**(완성 영상은 그대로)인가, **장면 자체의 속도**(오른쪽 `속도` 칸 — 완성 영상이 길어짐, 2026-09-04 결정)인가.
