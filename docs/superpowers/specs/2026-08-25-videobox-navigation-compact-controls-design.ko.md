# VideoBox 전역 이동과 조밀한 조작부 설계

작성일: 2026-08-25
상태: 설계 승인, 문서 검토 대기
결정: C 혼합형 — 상단의 이전·경로와 기존 프로젝트 단계 막대를 함께 사용한다.

## 문제와 목표

현재 프로젝트 목록, 라이브러리, 촬영본 정리, 설정은 같은 제품 안에 있으나 화면별 상단 구조가 다르고, 이전 화면으로 가는 공통 동작과 현재 위치 경로가 없다. 전역 목적지는 `전체 메뉴`에만 있어 다음 이동을 예측하기 어렵다.

목표는 승인된 색·주요 배치를 바꾸지 않고 다음을 보장하는 것이다.

1. 어느 화면에서도 현재 위치와 안전한 이전 목적지를 확인할 수 있다.
2. 프로젝트 안에서는 이야기·재료·편집·확인과 내보내기 단계를 계속 확인하고 바로 이동할 수 있다.
3. 전역 목적지(프로젝트, 내 라이브러리, 촬영본 정리, 설정)는 같은 규칙과 문구로 제공된다.
4. 보조 조작부는 작고 일관되게 만들되, 주요 행동의 가독성과 터치 안전성은 유지한다.

## 선택한 구조

### 1. 공통 상단 문맥

`ProductShell`과 전역 화면 셸이 동일한 이동 모델을 받아 다음 순서로 표시한다.

`‹ 이전` → `VideoBox` → 경로 → 프로젝트 단계(프로젝트 문맥일 때) → 화면 이름 → 작업 상태 → 전체 메뉴

- `‹ 이전`은 작은 보조 버튼이다. 브라우저 방문 이력이 있으면 실제 이전 페이지로 돌아간다.
- 직접 주소로 진입했거나 이전 이력이 없는 경우에는 경로의 한 단계 위로 안전하게 돌아간다. 프로젝트 단계는 해당 프로젝트의 시작 화면, 라이브러리는 프로젝트 목록, 촬영본 정리는 라이브러리, 설정은 프로젝트 목록이 기본값이다.
- `VideoBox`는 항상 프로젝트 목록으로 이동한다.
- 경로의 앞 항목은 이동 가능하고, 현재 항목은 읽기 전용 표식이다. 프로젝트 이름을 알 수 없는 전역 화면에는 프로젝트 경로를 억지로 표시하지 않는다.

### 2. 프로젝트 단계와 전역 메뉴

- 기존의 `이야기 → 재료 → 편집 → 확인과 내보내기`는 프로젝트 화면에서 유지한다. 현재 단계에는 `aria-current="page"`를 지정한다.
- `전체 메뉴`는 전역 목적지의 보조 진입점으로 유지하되, 프로젝트·내 라이브러리·촬영본 정리·설정의 이름과 순서를 모든 셸에서 동일하게 한다.
- 라이브러리와 촬영본 정리 안의 서로 연결된 본문 링크는 중앙 라우트 도우미를 사용한다. 원시 URL 문자열을 화면마다 따로 만들지 않는다.
- `return_to`처럼 기존 작업 흐름을 보존하는 이동은 그대로 유지한다. 뒤로가기와 경로 링크는 이 매개변수를 지우지 않는다.

### 3. 버튼 밀도와 설명

버튼을 세 계층으로 나눈다.

| 계층 | 예 | 표시와 크기 | 설명 |
| --- | --- | --- | --- |
| 주요 행동 | 새 프로젝트 만들기, 계속 만들기, 내보내기 | 기존의 읽기 쉬운 글자 버튼을 유지 | 버튼명 자체로 목적을 설명 |
| 보조 행동 | 이전, 전체 메뉴, 프로젝트 전환, 단계 이동 | 작고 일정한 높이의 글자 또는 아이콘 버튼 | 짧은 이름·아이콘이면 툴팁 제공 |
| 도구 행동 | 화면 안의 정리·편집 도구 | 조밀한 버튼군으로 정리 | 아이콘 전용이면 항상 툴팁과 접근 가능한 이름 제공 |

- 모든 버튼을 작게 만들지는 않는다. 주요 행동까지 줄이면 실행 실수와 인지 부담이 커진다.
- 마우스에서는 0.5초 이내의 오버로 설명을 표시하고, 키보드에서는 포커스 시 같은 설명을 표시한다.
- 툴팁은 보조 설명일 뿐 동작명을 대체하지 않는다. 아이콘 전용 버튼에는 `aria-label`을 둔다.
- 터치 화면에서는 오버를 전제로 하지 않는다. 아이콘 단독 사용을 피하고, 터치 목표는 기존 접근성 기준보다 작아지지 않게 한다.

## 구성과 경계

1. `routeManifest`는 화면 이름, 상위 경로, 기본 뒤로가기 목적지를 계산하는 순수 이동 모델을 제공한다.
2. `AppRouter`는 URL·프로젝트 문맥을 이 모델에 넘기며, 직접 진입과 별칭 URL을 정규화한다.
3. `ProductShell`과 새 전역 셸 어댑터는 같은 `NavigationChrome`을 렌더한다. 페이지 콘텐츠는 이동 규칙을 직접 갖지 않는다.
4. `TopBar`는 브랜드·경로·이전·단계·메뉴를 표시할 뿐 URL을 조합하지 않는다.
5. `Tooltip`은 보조 조작부에서 재사용하고, 보이는 라벨과 접근 가능한 이름의 규칙을 한 곳에 둔다.

이 경계로 인해 새 화면을 추가할 때는 이동 모델에 한 항목을 등록하고 셸이 자동으로 같은 문맥을 제공한다.

## 예외 처리

- 브라우저 이력이 없거나 외부 사이트에서 직접 열렸으면 `history.back()`만 수행하지 않고 계산된 안전한 상위 화면으로 이동한다.
- 존재하지 않거나 접근할 수 없는 프로젝트는 기존 라우터의 오류 처리로 보내며, 뒤로가기 기본값은 프로젝트 목록이다.
- 설정 URL의 `project_id`가 있으면 경로에는 설정을 표시하되 해당 프로젝트 단계로 이동할 때만 그 프로젝트 문맥을 사용한다.
- 모바일 메뉴가 열렸을 때는 현재 위치, 포커스 이동, 닫기 동작을 데스크톱과 같은 접근성 규칙으로 유지한다.

## 검증 기준

### 자동 시험

- 경로 모델: 프로젝트·라이브러리·촬영본·설정·직접 진입 각각의 경로와 기본 뒤로가기 목적지를 단위 시험한다.
- 상단: 이전 버튼, 현재 경로 표식, 프로젝트 단계의 현재 상태, 동일한 전역 메뉴 항목을 렌더 시험한다.
- 라우팅: 프로젝트 목록 → 라이브러리 → 촬영본 → 설정 → 프로젝트 단계와 직접 URL 진입을 화면 시험한다.
- 접근성: 아이콘·짧은 버튼의 접근 가능한 이름, 오버와 키보드 포커스의 설명 표시를 시험한다.
- 회귀: `npx vitest run`, `npx tsc --noEmit`을 실행한다.

### 브라우저 확인

- 컨테이너를 `owner-ready.ps1 -Mode Start -Rebuild -WithYujinMemory`로 재생성한 뒤 실제 화면에서 네 전역 화면과 한 프로젝트의 네 단계를 확인한다.
- 브라우저 뒤로가기와 이력이 없는 직접 URL의 이전 버튼을 각각 확인한다.
- 대표님께서 목요일에 실제 화면의 문구 밀도, 버튼 크기, 툴팁 타이밍을 확인한다. 이 확인 전에는 "보기 좋다" 또는 사용자 수용 완료라고 판단하지 않는다.
