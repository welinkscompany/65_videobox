# VideoBox 제작 작업실 전면 개편 설계

- 상태: owner 최종 승인 완료
- 승인일: 2026-08-12
- 대상: 데스크톱 전용 VideoBox 로컬 제작 환경
- 기준 브랜치: `codex/videobox-container-compatibility`

## 1. 결정 요약

VideoBox를 프로젝트 선택 후 유진의 도움을 받아 기획, 자산 준비, 편집, 검토, 가로·세로 출력까지 마치는 **creator-complete 경량 편집기**이자 데스크톱 제작 작업실로 개편한다.

핵심 결정은 다음과 같다.

1. 사용자는 먼저 프로젝트를 선택한 뒤 해당 프로젝트 작업실에서 제작한다.
2. 전역 메뉴는 `프로젝트`, `내 라이브러리`, `촬영본 정리`, `설정`으로 제한한다.
3. 프로젝트 작업실은 `기획`, `자산`, `편집`, `검토`, `출력`의 고정 흐름을 사용한다.
4. B-roll, 음악, 효과음은 개인용 로컬 라이브러리에 누적한다.
5. PC 드래그앤드롭과 Google Drive 가져오기는 하나의 안전한 등록 파이프라인으로 연결한다.
6. 등록 즉시 복사, 중복 검사, 기술 분석, 미리보기 생성, 의미 분석과 검색 색인을 수행한다.
7. 긴 촬영본은 원본을 변경하지 않고 장면과 의미 단위로 나누며, 짧은 촬영본은 가상 시퀀스로 결합한다.
8. 유진은 편집안을 제안하지만 직접 파일, DB, 타임라인 또는 렌더러를 조작하지 않는다.
9. 모든 유진 변경은 `제안 → 미리보기 → 명시적 적용`을 거친다.
10. 하나의 마스터 편집본에서 `가로 16:9`와 `세로 전체본 9:16`을 함께 만든다.
11. `세로 하이라이트 9:16`은 사용자 요청 시에만 만드는 선택 기능이다.
12. CapCut은 필수 후편집 단계가 아니라 선택적 호환·비상 경로다.
13. 완료 기준은 테스트 통과가 아니라 owner가 실제 브라우저에서 영상을 끝까지 제작하고 결과물을 재생할 수 있는가다.

## 2. 기존 결정과의 관계

이 문서는 다음 승인 결정을 유지한다.

- 흰색·주황색 제품 팔레트와 creator 중심 언어
- 프로젝트 상태의 정직한 표시
- 로컬 모델 우선과 모델 출력 불신 원칙
- 유진의 제안·미리보기·승인 경계
- VideoBox DB와 편집 엔진을 최종 상태 권한으로 유지
- 기존 편집 작업대의 자산·미리보기·유진 영역이라는 기본 개념

이 문서는 다음 범위를 명시적으로 갱신한다.

- 모든 자산을 동일한 썸네일 격자로 표시하지 않는다. 영상은 썸네일 격자, 음악·효과음은 파형 목록, 가져오기는 작업 표, 촬영본은 타임라인 중심 화면을 사용한다.
- CapCut 전달을 정상 제작의 종착점으로 보지 않는다. VideoBox 내부 완성을 기본으로 하고 CapCut 호환은 선택 기능으로 둔다.
- 프로젝트별 임시 자산 화면을 개인용 누적 로컬 라이브러리와 프로젝트 참조 구조로 확장한다.
- 기존 자체 편집기의 기본 계약을 유지하면서 가로·세로 연결 출력 변형과 creator-complete 편집 범위를 추가한다.

## 3. 제품 목표와 비목표

### 3.1 목표

- 처음 사용하는 owner도 다음 행동을 별도 설명 없이 찾는다.
- 자산이 수천 개로 늘어나도 페이지 전체가 길어지지 않는다.
- 영상, 음악, 효과음을 앱에서 직접 등록, 미리보기, 검색, 사용, 제거한다.
- 유진과 자연어로 작업하면서도 모든 변경을 사용자가 통제한다.
- 자막과 장면을 중심으로 일상적인 영상 편집을 VideoBox 안에서 끝낸다.
- 하나의 편집 이력에서 가로와 세로 결과를 안정적으로 관리한다.
- 새로고침, 일시적 연결 실패, 작업 재시도에도 중복과 상태 거짓말이 생기지 않는다.

### 3.2 초기 개편의 비목표

- 모바일 편집 UI
- 전문 색보정, 고급 마스크, 복잡한 키프레임, 다중 카메라
- Premiere, Resolve 또는 CapCut의 모든 기능 복제
- 사용권이 불명확한 무료 미디어의 자동 수집·재배포
- 모델이 임의 셸 명령, 파일 경로, DB 쿼리 또는 HTTP 요청을 실행하는 기능
- 채팅에서 단순 동의 표현만으로 편집을 적용하는 기능

이 비목표는 VideoBox 내부 완성을 포기한다는 의미가 아니다. owner가 반복적으로 사용하는 컷, 자막, B-roll, 음악, 효과음, 화면 구성, 검토와 출력에 먼저 집중한다.

## 4. 정보 구조와 제작 흐름

### 4.1 전역 메뉴

1. `프로젝트`: 프로젝트 선택, 다음 작업, 최근 결과
2. `내 라이브러리`: 전 프로젝트 공용 영상·음악·효과음
3. `촬영본 정리`: 긴 원본 분할과 짧은 원본 결합
4. `설정`: 저장소, 모델, 출력, 기본팩, 연결 상태

프로젝트를 연 뒤에는 프로젝트 단계가 전역 메뉴보다 시각적으로 우선한다.

### 4.2 프로젝트 목록

프로젝트 카드는 다음만 보여준다.

- 프로젝트명과 대표 이미지
- 최근 편집 시각
- 현재 단계와 상태
- 완성본 수
- 단일 기본 행동 `계속 만들기`

보관, 복제, 삭제는 `더보기` 메뉴에 둔다. 실패한 상태 조회를 `새 영상 시작`으로 오인시키지 않고 `상태 확인 필요`와 재시도를 보여준다.

### 4.3 프로젝트 작업실

고정 단계는 `기획 → 자산 → 편집 → 검토 → 출력`이다. 단계 이동은 자유롭게 허용하지만 현재 다음 행동 하나를 강조한다. 완료, 진행, 주의, 차단 상태를 텍스트와 아이콘으로 함께 표시한다.

화면 문구는 설명문보다 짧은 작업 키워드를 우선한다. 상세 도움말은 정보 아이콘, 빈 상태 또는 최초 진입 안내에만 표시한다.

## 5. 데스크톱 레이아웃과 디자인 규칙

### 5.1 공통 레이아웃

- 페이지 전체 스크롤을 기본 레이아웃으로 사용하지 않는다.
- 헤더, 프로젝트 단계, 주요 작업 영역을 viewport 안에 고정한다.
- 긴 목록과 타임라인은 각 영역 내부에서만 스크롤한다.
- 패널은 최소·최대 크기를 가지며 사용자가 접거나 크기를 조절할 수 있다.
- 데스크톱 최소 작업 해상도와 축소 시 우선순위를 구현 계획에서 고정한다.

### 5.2 버튼과 상태

- 화면당 주 강조 버튼은 하나다.
- 관련 버튼 간격은 최소 8px, 기능 묶음 사이는 최소 16px다.
- 기본 버튼 높이는 40px 이상이다.
- 아이콘 단독 버튼에는 툴팁과 접근성 이름이 필요하다.
- 선택 상태는 색상만이 아니라 테두리, 아이콘 또는 텍스트로 함께 구분한다.
- 위험 작업은 별도 색상, 정확한 대상명과 확인 단계를 사용한다.
- `미리보기`, `적용`, `취소`의 위치와 순서를 제품 전체에서 통일한다.
- 빈 상태, 로딩, 일부 완료, 실패, 재시도 상태를 서로 다르게 표시한다.

## 6. 개인용 로컬 라이브러리

### 6.1 화면 구조

라이브러리는 세 영역을 사용한다.

- 왼쪽: 종류, 컬렉션, 분석 상태, 즐겨찾기, 휴지통
- 가운데: 검색·필터와 고정 높이 결과 목록
- 오른쪽: 미리보기, 메타데이터, 사용 위치와 행동

영상은 썸네일 격자, 음악과 효과음은 파형이 포함된 조밀한 행 목록을 사용한다. 결과는 페이지 단위 또는 명시적 가상화로 제한하며 페이지 전체가 자산 수만큼 늘어나지 않는다.

### 6.2 등록 파이프라인

B-roll, 음악, 효과음을 PC에서 드래그앤드롭하거나 파일 선택으로 등록한다. Google Drive와 외부 촬영본 가져오기도 같은 파이프라인을 사용한다.

1. 허용 형식, 파일 가독성, 기본 보안 검사
2. 콘텐츠 해시 계산과 중복 탐지
3. VideoBox 관리 저장소로 원자적 복사
4. 컨테이너, 코덱, 길이, 해상도, 방향, 채널 등 기술 정보 추출
5. 영상 썸네일·프록시 또는 오디오 파형·미리보기 생성
6. 장면, 음성, 행동, 장소, 분위기, 음향 의미 분석
7. 사용자 검색과 유진이 공유하는 메타데이터·임베딩 색인 등록
8. `사용 가능` 전환

원본은 변경하지 않는다. 분석 실패는 등록 파일을 삭제하지 않으며 재시도 가능 상태로 남긴다. 다중 업로드는 완료, 분석 중, 중복, 실패 수와 실패 항목 재시도를 보여준다.

### 6.3 검색과 미리보기

한 검색창에서 파일명, 태그와 의미 검색을 처리한다. 종류, 길이, 방향, 해상도, 촬영일, 분석 상태, 즐겨찾기, 프로젝트 사용, 라이선스로 좁힌다. 의미 결과에는 일치 이유를 짧게 표시한다.

- 영상: hover 탐색, 선택 후 소리 포함 전체 구간 재생, 가로·세로 프레임 확인
- 음악·효과음: 파형 탐색, 임의 시점 재생, 반복과 음량
- 공통: 재생속도, 앞뒤 이동, `프로젝트에 추가`와 `편집 위치에 넣기` 구분

### 6.4 삭제와 보존

- 프로젝트 참조 제거와 라이브러리 삭제는 별도 행동이다.
- 타임라인이나 파생 자산이 참조하는 자산은 영구삭제를 차단하고 사용 위치를 보여준다.
- 사용하지 않는 사용자 자산은 휴지통으로 이동하며 복원할 수 있다.
- 영구삭제는 정확한 대상과 복구 불가능성을 확인한 뒤 수행한다.
- 기본팩 자산은 삭제할 수 없고 숨김 또는 팩 비활성화만 지원한다.
- 같은 해시 재등록은 새 복사본 대신 기존 자산을 안내한다.
- 같은 이름이라도 해시가 다르면 별도 자산이다.

## 7. 촬영본 정리

### 7.1 목적과 화면

긴 촬영본을 편집 가능한 B-roll 구간으로 만들고 짧은 촬영본을 의미 있는 시퀀스로 묶는다. 왼쪽 촬영본 목록, 가운데 큰 미리보기, 아래 파형·장면 타임라인, 오른쪽 유진 제안으로 구성한다.

### 7.2 자동 분할

장면, 장소, 행동, 정지·반복, 카메라 흔들림·가림, 음성·환경음, 밝기·품질, 의미 변화를 종합해 구간을 제안한다. 분석 결과는 즉시 원본을 자르지 않는다.

사용자는 구간별 미리보기, 경계 이동, 프레임 단위 조정, 합치기, 다시 나누기와 제외를 수행한다. 품질이 낮거나 렌즈가 가린 구간은 제외 후보로만 표시한다.

### 7.3 가상 결합과 파생 자산

짧은 영상은 원본 파일을 합치기 전에 순서, 구간, 간격과 전환을 가진 가상 시퀀스로 묶는다. 각 구간은 원본과 출처 연결을 유지한다. 사용자가 `독립 파일 만들기`를 선택할 때만 파생 파일을 렌더링한다.

승인한 분할 구간과 가상 시퀀스는 즉시 검색 가능한 B-roll 자산이 된다. 이후 분석 모델이 개선되어도 사용자가 확정한 이름, 경계와 태그는 덮어쓰지 않는다.

## 8. 자체 편집기

### 8.1 화면과 작업 모드

편집기는 왼쪽 대본·자산·자막·장면, 가운데 미리보기, 오른쪽 유진·속성·변경 내역, 아래 고정 타임라인으로 구성한다.

기능을 `내용`, `화면`, `소리`, `마무리` 모드로 묶되 모두 같은 마스터 타임라인을 편집한다. 선택 항목에 필요한 도구만 노출한다.

### 8.2 필수 편집 범위

- 클립 추가, 삭제, 이동, 교체
- 시작·끝 자르기, 분할, 묶기와 순서 변경
- 실행 취소·다시 실행, 자동 저장과 이력 복원
- 타임라인 확대·축소, 맞춤 보기, 스냅과 프레임 이동
- B-roll 덮어쓰기와 길이 조정
- 음악·효과음 배치, 페이드, 트랙·클립 음량, 음소거·솔로
- 자막 내용, 시점, 줄바꿈과 기본 스타일 수정
- 기본 전환과 선택 구간 반복 재생
- 편집 전후 비교

### 8.3 자막 기반 편집

대본이나 음성 인식 문장을 선택하면 연결된 영상 구간을 함께 선택한다. 문장 삭제·이동은 영상 변경 제안을 만들며 적용 전 영향을 미리 보여준다. 침묵, 반복어, 자막·음성 시점 불일치를 찾는다. 원본 대본과 화면 표시용 자막을 분리한다.

## 9. 마스터 편집본과 출력 변형

### 9.1 구조

프로젝트에는 하나의 마스터 편집본이 있다.

- `가로 16:9`: 기본 출력 변형
- `세로 전체본 9:16`: 기본 출력 변형
- `세로 하이라이트 9:16`: 사용자가 요청할 때 생성하는 선택 변형

공통 원본, 기본 컷, 이야기 순서, 대본, 자막 내용, 의미 태그와 승인 기록을 공유한다. 변형은 크롭, 중심점, 확대·이동, 자막 배치, 그래픽 안전영역과 일부 음량만 별도로 저장한다.

`세로 전체본`은 마스터와 같은 내용·순서·기본 길이를 유지한다. 화면 비율 때문에 필요한 클립 경계의 미세 조정은 허용하지만 이야기 구간을 삭제하거나 재배열하지 않는다. `세로 하이라이트`만 마스터 구간을 참조해 길이, 선택 구간과 순서를 별도로 구성할 수 있다. 따라서 전체본은 가로 영상과 내용 정합성을 유지하고, 하이라이트는 별도 숏폼 목적을 충족한다.

### 9.2 전파와 충돌

마스터 변경은 수정하지 않은 변형 속성에 전파한다. 사용자가 변형에서 직접 수정한 속성은 고정 상태로 보호한다. 원본 구간 삭제 또는 큰 변경으로 충돌하면 기존 변형 유지와 새 마스터 기준 재생성을 선택하게 한다. 사용자 변경을 조용히 덮어쓰지 않는다.

### 9.3 비율 편집

미리보기에 `마스터`, `가로`, `세로`, `나란히 비교`를 제공한다. 같은 재생 위치를 비교하고 얼굴, 주요 물체, 자막과 그래픽 안전영역 잘림을 표시한다. 자동 재구도는 제안으로 만들며 장면별 또는 묶음 미리보기 후 적용한다.

## 10. 유진 에이전트

### 10.1 권한 경계

LM Studio 로컬 모델은 자연어 의도, 검색식, 편집 계획과 정해진 형식의 제안을 생성한다. 실제 조회, 타임라인 계산, 파일 처리, 저장과 렌더링은 VideoBox가 수행한다.

유진은 원시 DB, 파일시스템, 셸, 렌더러, 자격 증명 또는 임의 HTTP에 접근하지 않는다. 존재하지 않는 자산·구간, 허용되지 않은 명령과 잘못된 형식은 적용 전에 거부한다.

### 10.2 상호작용 계약

모든 변경은 다음 순서를 지킨다.

1. 사용자 요청 또는 스타터 선택
2. 현재 화면·선택·재생 위치에 필요한 최소 문맥 수집
3. 근거와 영향을 포함한 구조화된 제안
4. VideoBox 명령·리비전·자산 유효성 검사
5. 변경 전후 미리보기
6. 사용자의 명시적 `적용`
7. 원자적 명령 실행과 되돌리기 기록

채팅의 `그래`, `좋아`, `진행해`는 적용 승인이 아니다.

### 10.3 대화 스타터

각 화면과 선택 상태에 맞는 4~6개를 표시한다. `다른 예시`, `전체 보기`, 최근·자주 사용 항목을 제공한다. 스타터 클릭은 실행하지 않고 입력창을 채우며 사용자가 수정 후 전송한다.

스타터는 기획, 자산 검색, 촬영본 분할·결합, 편집, 화면 비율, 검토·출력 범주를 포함한다.

### 10.4 설명과 이력

제안 카드는 대상 구간, 변경 내용, 근거, 불확실성, 영향 항목을 짧게 보여준다. 적용 기록에는 요청, 제안, 실제 명령, 영향 구간, 리비전과 시각을 저장한다. 전체 묶음과 개별 항목 되돌리기를 제공한다.

## 11. 검토와 출력

### 11.1 검토

문제를 `내용`, `자막`, `화면`, `소리`, `자산`으로 묶는다. 문제 선택 시 해당 재생 위치와 가로·세로 상태로 이동한다. 자동 수정 가능 항목도 제안과 미리보기 후 승인한다. 의도한 상태는 이유와 함께 제외할 수 있다.

검토는 프로젝트, 타임라인, 편집 세션과 리비전에 결합한다. 마스터 변경 후 과거 승인을 현재 승인으로 표시하지 않는다. 정적 검사 외에 처음부터 끝까지 재생, 임의 탐색, 전체 화면, 가로·세로 비교와 저해상도 검토본을 지원한다.

### 11.2 출력

기본 출력은 `가로 1920×1080`과 `세로 전체본 1080×1920`이며 하나의 요청에서 함께 선택한다. 해상도 프리셋은 설정에서 변경할 수 있지만 화면 비율 계약은 유지한다. 각 출력은 독립 작업이므로 하나가 실패해도 다른 결과를 보존한다. 세로 하이라이트는 생성된 경우에만 선택지로 표시한다. 자막 파일과 CapCut 호환본은 선택 기능이다.

다음 상태는 출력을 차단하고 구체적 해결 행동을 제공한다.

- 원본 누락 또는 지원하지 않는 형식
- 손상된 타임라인
- 현재 리비전 검토본 없음 또는 검토 후 마스터 변경
- 렌더러 연결 실패
- 저장 공간 부족
- 필요한 라이선스 출처 누락

작업은 진행률, 경과·예상 시간, 현재 단계와 실패 사유를 표시한다. 앱을 다시 열어도 상태를 복구한다. 재시도는 실패 항목만 대상으로 하며 중복 방지 키를 사용한다.

### 11.3 결과 확인

렌더 완료만으로 성공 처리하지 않는다.

1. 파일 존재와 크기
2. 코덱, 해상도, 길이와 오디오 스트림
3. 앱 안에서 가로·세로 실제 재생
4. 시작·중간·끝과 자막·음량·잘림 확인
5. 사용자 `결과 확인 완료`

CapCut 호환 실패는 MP4 출력을 막지 않는다.

## 12. 무료 기본팩과 라이선스

- 설치팩에는 원본 재배포가 명확히 허용되는 CC0 또는 동등 범위만 포함한다.
- 파일별 출처, 저작자, 원문 URL, 라이선스, 취득일, 해시와 라이선스 원문 근거를 기록한다.
- GitHub 코드 라이선스와 저장소에 포함된 미디어 라이선스를 분리해 판단한다.
- 개인 사용은 가능하지만 원본 재배포가 제한되는 자산은 사용자가 직접 내려받아 개인 라이브러리에 등록하는 경로만 허용한다.
- 초기 팩은 화면 채우기용 가짜 데이터가 아니라 실제 미리보기와 출력이 가능한 작은 검증팩이다.

## 13. 실패와 복구 계약

모든 비동기 작업은 `대기`, `진행 중`, `완료`, `일부 완료`, `재시도 가능 실패`, `사용자 조치 필요`, `취소됨`을 표현할 수 있어야 한다.

오류는 작업명, 현재 데이터의 안전 여부, 다음 행동을 함께 보여준다. 서버가 영구 변경을 마친 뒤 응답만 유실한 경우 authoritative state를 재조회한다. 업로드, 가져오기, 분석 등록과 렌더링은 중복 방지 키 또는 동등한 멱등성 계약을 가진다.

자동 저장은 `저장됨`, `저장 중`, `저장 실패`를 표시한다. 브라우저를 닫아도 마지막 정상 편집 위치와 리비전으로 돌아간다. 렌더링과 미리보기 실패가 편집본을 손상시키지 않는다.

## 14. 단계별 구축 경계

이 설계는 하나의 제품 방향이지만 구현은 다음 독립 단계로 나눈다.

1. 작업실 골격과 정보 구조
2. 개인용 라이브러리와 등록 파이프라인
3. 촬영본 정리와 파생 B-roll
4. creator-complete 자체 편집기
5. 마스터·가로·세로 출력 변형
6. 유진 제안·승인 통합
7. 현재 리비전 검토와 안정적 출력

각 단계는 관련 자동 검증과 실제 브라우저 owner 흐름을 통과한 뒤 다음 단계로 간다. 기존 데이터와 현재 편집·출력 기능은 단계별 마이그레이션과 호환 계층을 통해 보존한다. 구체적인 파일, API, 마이그레이션, 테스트와 커밋 단위는 이 설계 승인 후 작성하는 구현 계획에서 고정한다.

## 15. 검증과 완료 기준

### 15.1 자동 검증

- 데이터 마이그레이션과 기존 프로젝트 호환
- 콘텐츠 해시 중복, 프로젝트 간 상태 격리
- 참조 중인 자산 삭제 차단과 휴지통 복원
- 업로드·가져오기·분석의 응답 유실과 재시도
- 타임라인 명령, 실행 취소·다시 실행, 자동 저장 복구
- 마스터 전파, 변형 고정과 충돌
- 검토 승인 lineage와 stale 처리
- 가로·세로 출력의 독립 성공·실패
- 유진의 금지 명령, 잘못된 리비전과 존재하지 않는 자산 거부

백엔드 검증은 저장소가 지정한 `.venv/Scripts/python.exe -m pytest` 절대 경로만 사용한다.

### 15.2 실제 브라우저 검증

- 사이드바·문구·버튼 간격과 선택 상태
- viewport 고정과 영역별 스크롤
- 대규모 자산 밀도, 검색, 필터와 페이지 처리
- 세 종류 드래그앤드롭과 실제 미리보기
- 긴 촬영본 탐색, 분할·결합 미리보기와 승인
- 직접 타임라인 편집, 유진 제안 취소·적용과 되돌리기
- 새로고침 후 동일 편집본·재생 위치 복구
- 가로·세로 나란히 비교와 잘림 경고
- 실패, 일부 완료, 재시도와 삭제 차단

computed style, 스냅샷 또는 테스트 통과만으로 화면 완료를 선언하지 않는다.

### 15.3 Owner 전체 제작 검증

전용 QA 프로젝트에서 프로젝트 생성, 대본 등록, B-roll·음악·효과음 업로드, 자동 분석·의미 검색, 촬영본 분할·결합, 유진 편집, 직접 타임라인 편집, 새로고침 복구, 현재 리비전 검토, 가로·세로 MP4 출력, 파일 검사와 앱 내 전체 재생을 수행한다. 세로 하이라이트는 선택 흐름으로 별도 확인한다.

컨테이너는 `scripts/owner-ready.ps1`로만 조작한다. owner가 실제 결과물을 사용할 수 있어야 완료다.

## 16. 승인 후 다음 단계

이 문서를 owner가 검토·승인한 뒤 Luna가 실행할 수 있도록 구현 계획을 작성한다. 구현 계획은 단계별 파일, API와 데이터 변경, 마이그레이션, TDD RED/GREEN 테스트, 브라우저 검증, 코드리뷰, 갭·역방향·실패 검증, 커밋과 푸시 게이트를 명령 단위로 명시한다.
