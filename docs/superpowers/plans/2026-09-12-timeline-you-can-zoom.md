# 타임라인을 늘리고 줄인다 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 대표님이 타임라인을 **단축키로 쉽게** 늘리고 줄인다. 처음 열었을 때 배율이 **영상 길이에 맞게** 잡힌다.

**Spec:** 대표님 지시 2026-09-12: "타임라인을 늘리고 줄이는 기능도 있어야되. 이건 어느 편집기던지 꼭 필요한 기능이고 이미 다른 편집기는 이미 있어. 그리고 처음에 디폴트 값을 어느정도는 길게 하고 이걸 단축키로 쉽게 늘리고 줄이고를 할수 있어야지"

`CLAUDE.md` §2.1이 캡컷 벤치마킹을 못박았고, 캡컷에는 이 기능이 있다. 범위 충돌 없다.

**Architecture:** **엔진은 이미 다 있다.** 없는 것은 **부르는 자리**다. 새 배율 체계를 만들지 마라.

## 조사 기록 (2026-09-12 실측)

| 잰 것 | 결과 |
|---|---|
| 배율 계산 | **있다** — `zoomAroundAnchor(scale, anchorPixel, nextPixelsPerSecond)` (`timeline/time-scale.ts:88`), 앵커를 고정한 채 배율만 바꾼다 |
| 확대 명령 | **있다** — `timelineNavigation.ts`에 `{type:"zoom", factor, anchorPx}`와 `{type:"zoom", pixelsPerSecond, anchorPx}` 둘 다 |

| 단축키 | **없다.** 편집기 단축키는 `Ctrl+Z`·`Ctrl+Y`·`Ctrl+B`(나누기)·`Delete`(빼기)뿐 (`cutShortcuts.ts`) |

## Global Constraints

- 저장소 최상위 지침은 `CLAUDE.md`. 작업 폴더는 `.worktrees/videobox-container-compatibility`.
- **RED → 실패 확인 → 최소 GREEN → 통과 확인.** 실패를 주장할 때 **시험 이름과 파일**을 대라.
- 프런트는 `apps/web`에서 `npx vitest run <경로>`, 타입검사 `npx tsc --noEmit -p tsconfig.json`. backend는 `.venv/Scripts/python.exe -m pytest`.
- **전체 pytest는 단독으로**(약 55분). 조각을 닫을 때만.
- **새 배율 체계를 만들지 마라.** `zoomAroundAnchor`와 `timelineNavigation`의 `zoom` 명령을 쓴다. 두 벌이 되면 눈금자와 클립이 서로 다른 자리에 그려진다.
- **단축키는 `cutShortcuts.ts`의 규약을 따른다** — 그 파일이 정한 원칙: *"키는 툴바가 정한 것을 그대로 쓴다. 무엇을 할 수 있는지 다시 계산하지 않는다."* 단추와 키가 서로 다른 판단을 하면 안 된다.
- **캡컷과 같은 키를 쓴다**(`CLAUDE.md` §2.1 벤치마킹). 무엇을 골랐는지 근거를 적어라.
- 화면 문구에 개발 용어 금지. 대표님께는 `타임라인`·`장면`·`늘리기`·`줄이기`다.
- **유진 배선은 이 계획의 일부다**(대표님 상시 지시) — 세 겹: 의도 → 적용기 → 프로필 안내문.
- **내장 브라우저는 화면을 안 그린다** — 전이·rAF가 멈춰 있어 멀쩡한 CSS를 결함으로 오진하게 된다. 눈으로 볼 것은 따로 재라.
- 커밋은 각 Task 끝에 하나씩. push 안 한다. **`git stash` 금지**(worktree 공유).

**배경:**

### Task 2: 단축키로 늘리고 줄인다 + 처음 배율

**Files:** `apps/web/src/features/editor/timeline/TimelineDock.tsx`, 단축키 모듈(새로 만들지 기존에 붙일지 판단), 해당 시험

**Interfaces:** Consumes Task 1의 올바른 길이

**배경:**
엔진은 있고 부르는 자리가 없다. 지금 처음 배율이 100px/초로 못박혀 있어 494초 영상은 49,400px가 된다.

**정할 것 셋 — 각각 근거를 적어라:**

1. **키 조합.** 캡컷을 벤치마킹한다. 흔한 관례는 `Ctrl` + `=`/`-`와 `Ctrl`+휠이다. 실제로 무엇을 고를지 정하고, **`Ctrl+B`·`Delete`와 부딪히지 않는지** 확인하라. 맥 키보드도 본다(`cutShortcuts.ts`가 Delete/Backspace 둘 다 받는 이유를 읽어라).
2. **처음 배율.** 대표님이 "어느정도는 길게"라고 했다. 후보 — 전체 맞추기(영상 전체가 한눈에), 또는 고정된 초/화면. **긴 영상과 짧은 영상 양쪽에서 말이 되는지** 재 보고 정하라. 494초와 15초 둘 다 밟아라.
3. **한계.** 얼마나 확대·축소할 수 있는가. 너무 확대하면 픽셀이 터지고, 너무 축소하면 클립이 1px이 된다. 값과 근거를 적어라.

**앵커를 지켜라.** `zoomAroundAnchor`가 앵커를 받는 이유가 있다 — 확대할 때 보고 있던 지점이 화면에 남아야 한다. 마우스 위치나 재생 머리를 앵커로 쓸지 정하고, **확대 후 그 지점이 그대로인지 시험으로 지켜라.**

**단추도 같이 둔다.** 단축키만 있으면 모르는 사람은 못 쓴다. 캡컷에도 눈금이 있다.

- [ ] **Step 1: 실패하는 시험을 쓴다** — 단축키로 배율이 올라가고 내려가며, 앵커 지점이 화면에 남는다
- [ ] **Step 2: 시험을 돌려 실패를 확인한다** (시험 이름과 파일)
- [ ] **Step 3: 통과할 만큼만 고친다**
- [ ] **Step 4: 시험을 돌려 통과를 확인한다** + 타입검사
- [ ] **Step 5: 변형 탐침** — 앵커 고정을 없애면 시험이 빨개지는지
- [ ] **Step 6: 커밋한다**

### Task 3: 유진에게 말해서도 된다
