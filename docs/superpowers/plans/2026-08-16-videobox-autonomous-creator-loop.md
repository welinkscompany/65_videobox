# 자율 창작 루프 — 대표님이 그린 최종 그림과, 거기까지 가는 순서

- 작성: 2026-08-16
- 상태: **기록됨 (recorded). 착수 전. 아래 §2의 결정 세 건이 먼저 필요하다.**
- 기준 HEAD: `62759854d`

## 1. 대표님이 원하는 최종 상태

owner의 말을 그대로 옮긴다.

> 아침에 유진이가 오늘 만들면 좋을 영상 제목을 여러 개 알려준다. 내가 그중 하나를 고르면
> 대본이 자동으로 나오고, 내가 확정하면 영상이 자동으로 제작되고 유튜브에 업로드까지 된다.
> 그리고 과거 영상 데이터를 다시 확인해서 다음 영상을 또 추천한다. 이렇게 돌면서 점점 좋아진다.

중간 단계로 원하는 것:

- 텔레그램에서 유진이와 대화하다가 **대본이 확정되면 그대로 제작까지** 간다.
- 대본을 직접 주는 경우도 같다.
- 완성본 포맷을 **템플릿**으로 재사용한다.

**루프를 한 문장으로:** `추천 → 선택 → 대본 → 확정 → 제작 → 업로드 → 성과 분석 → 다시 추천`

**사람이 남는 자리 두 곳을 owner가 이미 지정했다** — 제목 `선택`과 대본 `확정`.
이 둘은 설계에서 없애지 않는다. 자동화의 목적은 사람을 빼는 것이 아니라
**사람이 판단할 것만 남기는 것**이다.

## 2. 먼저 받아야 할 결정 세 건 — 현재 계획서와 충돌한다

이 그림은 지금 저장소가 못 박아 둔 경계를 **세 군데 넘는다.** 몰래 넘지 않는다.

### 결정 A — 제품 범위를 넓힐 것인가

`CLAUDE.md` §2.1과 `implementation-plan` §4·§8.4는 VideoBox를
**"creator-complete MP4-first 경량 편집기"**로 고정했다. 컷·자막·B-roll·음악·효과음·
변형·검토·MP4 출력까지가 안이다.

**대본 생성, 제목 추천, 유튜브 업로드, 성과 분석은 그 바깥이다.** 넷 다 새 제품 영역이다.

→ 넓힌다면 `docs/decisions/`에 범위 확장 결정을 남기고 §2.1을 고쳐야 한다.

### 결정 B — 유진이의 금지 조항을 풀 것인가

`implementation-plan` §23.3이 유진이 프로파일에 **명시적으로 금지**로 박아 둔 것이 있다.

- **"대본·제목·썸네일·추천 영상의 생성 또는 제안은 현재 제품 범위 밖으로 차단한다"**
- 응답은 `action=null`, `non_authorizing=true`만 허용 — **실행 없음**
- 직접 편집·렌더·내보내기 **금지**

즉 대표님이 원하는 "제목 추천"과 "대본 생성"은 **지금 유진이에게 금지된 바로 그 항목들**이다.
게다가 이 프로파일은 SHA-256으로 고정돼 있어, 바꾸려면 **다시 핀을 박는 절차**가 필요하다.

→ 무엇을 풀고 무엇을 계속 막을지 정해야 한다. 전부 푸는 것은 권하지 않는다(§6 참고).

### 결정 C — 바깥으로 내보내는 것을 승인할 것인가

`CLAUDE.md` §6은 **외부 게시·업로드**를 owner 명시 승인 사항으로 둔다.
유튜브 업로드가 정확히 그것이다. 텔레그램 연결도 유진이를 외부 메신저에 붙이는 일이다.

→ 승인 범위를 문서로 남긴다. "무엇을, 어디로, 누가 눌렀을 때" 나가는지 적는다.

## 3. 이미 있는 것 — 맨땅이 아니다

루프의 상당 부분이 **이미 서 있다.**

| 루프 단계 | 지금 상태 |
|---|---|
| 재료 찾기 | **있음** — 의미검색이 영상·음악·효과음 13갈래로 동작 |
| 대본 → 장면 | **있음** — 편집 세션·타임라인·장면 분할 |
| 제작 | **있음** — 검토 승인 → 렌더 → MP4. 안전장치(낡은 자막·낡은 자산·짧은 오디오) 포함 |
| 결과 측정 | **첫 조각만 있음** — 2026-08-16에 완성본 음량 측정이 들어갔다 |
| 기억 | **있음** — Mem0 자가호스팅, owner 승인됨 |
| 텔레그램 | **껍데기 있음** — 헤르메스 게이트웨이 + `jang-yujin` 프로파일(꺼짐) |
| 유진 스킬 | **있음, 단 말만 함** — 응답 전용 스킬 3개 |
| 권한 통로 | **설계만 있고 배포 안 됨** — §23.2.6 "서명자는 아직 어디에도 배포하지 않았다" |
| 유튜브 | **없음** |
| 성과 분석 | **없음** |

**가장 큰 단일 장애물은 권한 통로다.** 유진이가 VideoBox를 조작할 방법이 없으면
텔레그램도 자동 제작도 전부 말뿐이다.

## 4. 순서 — 왜 이 순서인가

**앞쪽은 승인 없이 지금 할 수 있고 owner가 바로 체감한다. 뒤로 갈수록 승인과 위험이 커진다.**

### 0단계 — 승인 불필요, 앱 안에서 닫힘 (지금 착수 가능)

| # | 할 일 | 왜 지금인가 |
|---|---|---|
| T1 | **포맷 템플릿** — 마음에 든 완성본의 구성(장면 길이, 자막 스타일, 음악 성격)을 저장하고 다음 영상에서 불러 쓰기 | 자동 제작의 "어떻게 만들지"가 여기서 나온다. 템플릿 없이 자동화하면 매번 다른 물건이 나온다 |
| T2 | **추천 카드에 이름 표시** — 지금 전부 `P01-B-01 · 미디어`로 나와 무엇인지 구분 불가 | 사람이 고를 수 없는 추천은 자동화해도 못 고른다 |
| T3 | **대화와 후보 제안 연결** — 2026-08-16 관찰: "음악 추천해 줘"라고 했는데 돌아온 후보에 음악이 없고 영상만 있었다 | 텔레그램에서 대화로 제작을 시키려면 이게 먼저 맞아야 한다 |
| T4 | **품질 지표 축적** — 음량 옆에 자막 겹침·장면 전환 간격 등을 재서 완성본 기록에 남기고, owner의 승인/거부를 라벨로 쌓기 | **자기개선의 재료가 여기서만 나온다.** 지금은 좋았는지 나빴는지 아무 데도 없다 |

**T4가 조용하지만 가장 중요하다.** 5단계(성과 분석 → 추천)는 T4가 몇 달 쌓여야 성립한다.
지금 시작하지 않으면 나중에 시작해도 데이터가 없다.

### 1단계 — 권한 통로 (결정 B·C 필요)

§23.2가 설계해 둔 **짧은 수명 능력 토큰**을 실제로 배포한다.
서명자, gateway 전용 경로, egress allowlist, 감사 기록.

- 유진이가 self-mint 하거나 공유 서명키를 받는 설계는 **금지**(§23.2.6에 이미 명시).
- 토큰마다 `(주체, 프로젝트, 동작)`을 검사한다. 이미 구현돼 있는 계약이다.

**이 단계 없이는 아래가 전부 불가능하다.**

### 2단계 — 텔레그램 유진 (결정 C 필요)

`jang-yujin` 게이트웨이를 켜고, 프로파일에 **제작 착수 권한만** 준다.

- 대화 → 대본 확정 → **제작 시작**까지.
- 검토 승인과 내보내기는 **여전히 사람이 앱에서** 한다(첫 슬라이스에서는).

### 3단계 — 대본·제목 생성 (결정 A·B 필요)

§23.3의 금지 조항을 푸는 단계. **푸는 범위를 좁게 잡을 것을 권한다** —
예: 대본은 생성하되 owner 확정 없이는 어떤 장면도 만들지 않는다.

### 4단계 — 유튜브 업로드 (결정 C, §6 명시 승인)

업로드는 **되돌리기 어려운 바깥 방향 동작**이다. 최소한 이것들이 필요하다.

- 사람 확정 게이트(대표님이 누르는 마지막 한 번)
- 무엇이 언제 어디로 올라갔는지 감사 기록
- 실패·중복 업로드 방지

### 5단계 — 성과 분석 → 다음 영상 추천

유튜브 지표 + T4의 자체 품질 지표 + owner 판단 라벨을 합쳐 다음 주제를 제안한다.

### 6단계 — 아침 브리핑 루프

`추천 → 선택 → 대본 → 확정 → 제작 → 업로드 → 분석 → 추천`이 하루 주기로 돈다.
헤르메스의 cron으로 아침 브리핑을 띄운다.

## 5. 자기개선에 대해 — 무엇이 되고 무엇이 안 되는가

**된다:** 결과를 재고, owner 판단을 쌓고, 그걸 다음 추천의 근거로 쓰는 것.
이건 평범한 피드백 루프이고 위험하지 않다.

**하지 않는다:** 유진이가 자기 코드나 자기 프로파일을 스스로 고치는 것.
프로파일이 해시로 고정된 이유가 그것이다. 품질이 오르는 것과 통제가 풀리는 것은 다르다.

**스킬에 대해:** 헤르메스 스킬로 "이 포맷으로 만든다"를 적어 둘 수는 있다.
다만 지금 유진이 스킬 3개는 전부 응답 전용이라 실행되지 않는다.
**0단계 T1의 템플릿이 같은 목적을 승인 없이 먼저 이룬다.** 스킬화는 1단계 뒤에 의미가 생긴다.

## 6. 지금 권하는 것

**0단계부터 시작한다.** 승인이 필요 없고, 앱 안에서 닫히고, 대표님이 바로 체감하고,
**무엇보다 뒤 단계의 재료를 만든다**(T1은 자동 제작의 규격, T4는 자기개선의 데이터).

그 사이 결정 A·B·C를 정리하면, 0단계가 끝날 때 1단계를 바로 열 수 있다.

## 7. 열린 질문 (owner 결정 필요)

1. 제품 범위를 "영상 편집기"에서 **"영상 운영 도구"**로 넓히는가? (결정 A)
2. 유진이에게 대본·제목 생성을 허용하는가? 어디까지? (결정 B)
3. 유튜브 업로드와 텔레그램 연결을 승인하는가? 게이트는 어디에 두는가? (결정 C)
4. 채널이 하나인가 여럿인가? (5단계 분석 설계가 달라진다)
5. 대본 확정 뒤 **촬영본이 없으면** 어떻게 하는가? 지금은 사람이 채운다.
   자동 루프에서 이 구멍을 어떻게 메울지가 정해져 있지 않다.

**5번이 특히 크다.** 대본이 있어도 그 장면에 쓸 영상이 없으면 자동 제작은 멈춘다.
라이브러리 촬영본으로만 돌릴지, 부족하면 건너뛸지, 사람에게 물을지 정해야 한다.
