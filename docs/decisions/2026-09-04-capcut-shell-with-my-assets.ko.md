# 캡컷 껍데기 + 내 자산 — 제품 방향 확정 (2026-09-04, owner 승인)

## 결정 셋

owner가 이날 세 가지를 정했다.

1. **`속도`는 캡컷과 동일하게 맞춘다.** 배속을 바꾸면 길이가 바뀐다.
2. **사이드바 `내 자산` 구역을 만든다.** (캡컷 `AI로 만들기` 자리)
3. **제품은 B-roll 브이로거용이고, 나중에 월 2~3만원 구독으로 판다.**

## 1. `속도` — 캡컷과 동일

> owner: "속도는 캡컷이랑 동일하게 맞춰."

### 먼저 정정 — 엔진은 이미 캡컷과 같다

기억 메모 `videobox-speed-means-something-different-than-capcut`에 "배속은 영상을
짧게 만들지 않는다"고 적혀 있었는데 **반쪽만 맞다.** 실제로 코드를 읽어 보니
`set_segment_ripple_playback_rate`(`editing_session.py:611`)가 **이미 캡컷과
똑같이 동작한다.**

- `display_duration = source_duration / requested_rate` → 배속이 길이를 바꾼다
- `media_windows`·`content_windows`를 `window_scale`로 같이 줄인다 → 자막·자산도 따라온다
- 뒤 장면들을 `delta`만큼 당긴다 → ripple

그리고 유진의 `set_scene_speed`도 이 함수로 이어진다(`editing_session.py:853`).
화면도 `RightDock.tsx:85`에서 이걸 부른다.

**즉 "동작을 캡컷에 맞춘다"는 새 엔진 기능이 아니라 대부분 화면 일이다.**
앞 계획서에서 이걸 "동작도 맞춰야 한다"고 크게 적었던 것은 과대평가였다.

### 실제로 바꿀 것

| | 지금 | 캡컷 | 할 일 |
|---|---|---|---|
| 이름 | `장면 길이` | **`속도`** | 이름 변경 |
| 모양 | 단추 3개(`기본`·`1.5배`·`2배`) | **`속도 [ ]x` + `기간 [ ]s` 숫자칸 2개(연동)** | 숫자칸으로 |
| 값 | `{1.0, 1.5, 2.0}` 고정 (`RIPPLE_PLAYBACK_RATES`) | 임의 값 | **허용 범위를 넓힌다** |
| 음조 | 없음 | `음조` 토글 | 검토 후 결정 |
| 자리 | 오른쪽 세부 정보 칸 | **속성 띠 `속도` 항목** | 속성 띠로 이동 |

**주의:** 허용 값을 넓히는 것은 엔진 변경이다(`editing_session.py:25`,
`composition_plan.py:23` 두 곳에 같은 집합이 있다 — **둘 다 고쳐야 한다**).
`MIN_SEGMENT_DURATION_SEC` 검사와 렌더 `atempo` 체인(0.5~2.0 범위)도 같이 본다.

## 2. `내 자산` 구역 — 승인

> owner: "내 자산 으로 만든것도 좋아."

캡컷 사이드바의 `AI로 만들기` 자리에 **`내 자산`**을 놓는다.

```
내 자산
  내 B-roll
  내 목소리
  음악·효과음
```

부품은 이미 다 있다 — B-roll·음악·효과음 자동 색인과 의미 검색, Chatterbox
목소리 클론. 흩어져 있는 것을 한 구역으로 모으는 일이다.

## 3. 제품 방향 — B-roll 브이로거용, 구독 판매

> owner: "나는 일단 이걸 만들면 내가 사용할 목적이지만, 나중에 이걸 수익화용으로
> 한달에 2~3만원씩 받으면서 팔거야. 저런 캡컷은 결국 본인 자산을 계속 업로드
> 해야되는데, 내가 만든건 진짜 내 비롤 가지고 쉽게 만드는거잖아. 어찌보면 비롤로
> 영상을 만드는 브이로그 를 하는사람에게 최적화된 버전이야."

### 이게 바꾸는 것

**자산 재사용이 곁다리가 아니라 제품의 중심이다.** 캡컷과의 진짜 차이는 기능
개수가 아니라 여기다.

| | 캡컷 | 우리 |
|---|---|---|
| 자산 | 만들 때마다 다시 올린다 | **한 번 넣으면 계속 재사용** |
| 찾기 | 파일 이름 | **의미 검색** |
| 고르기 | 사람이 매번 | **유진이 대본 읽고 장면마다 고름** |
| 목소리 | 크레딧으로 삼 | **내 목소리 클론, 로컬 무료** |
| 자막 | 크레딧으로 삼(`자동 캡션` 💎) | **로컬 faster-whisper, 무료** |

**설계 판단 기준이 생겼다:** 어떤 화면을 만들 때 "이게 내 자산을 다시 쓰기 쉽게
하는가"를 묻는다. 아니면 우선순위가 낮다.

그리고 **대본 패널이 제품의 심장**이다. 대본을 넣으면 유진이 장면을 나누고
가진 자산으로 채운다 — 캡컷이 못 하는 일이고, 브이로거가 매번 하는 지겨운 일이다.

### 지금 범위가 아닌 것 — 명확히 긋는다

owner가 "나중에"라고 말한 부분이다. `CLAUDE.md` §6은 **SaaS·billing·multi-user
인증을 owner 명시 승인 대상**으로 두고 있고, 이 문서는 그 승인이 **아니다.**

- 결제·구독·요금제 화면 → **안 만든다**
- 다중 사용자 계정·로그인·권한 → **안 만든다**
- 사용자별 자산 격리, 서버 저장 → **안 만든다**

지금은 **owner 1인용 로컬 제품**으로 계속 만든다. 다만 나중에 팔 것을 아니까,
**되돌리기 비싼 결정만 피한다**:

- 자산 색인·세션에 `owner` 개념을 하드코딩하지 않는다(지금 1인이어도 경로를 막지 않는다)
- 로컬 경로를 화면 문구에 노출하지 않는다
- 로컬 모델 교체가 config로 남아 있게 둔다(`videobox-local-model-swap-is-config-not-code`)

이건 **미리 만들라는 뜻이 아니라, 나중에 못 하게 막지 말라는 뜻**이다.
