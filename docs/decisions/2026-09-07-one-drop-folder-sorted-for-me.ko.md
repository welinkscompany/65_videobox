# 자산은 한 폴더에 넣는다 — 분류는 VideoBox가 (2026-09-07, owner 승인)

> owner: "내가 비롤, 사진, 음악, 효과음 같은건 어디에 넣으면 되? 그냥 한 폴더에
> 집어넣으면 너가 알아서 복사해가서 우리 시스템에서 알아서 분류하게 해줘."
>
> owner: "휴대폰에서도 넣을거니까 원드라이브로 해줘.
> `C:\Users\atgro\OneDrive\#_videobox` 이쪽으로 경로 만들었어. … 만약 자산
> 가치가 없으면 원드라이브에 `불필요` 폴더 하나를 만들어서 이쪽으로 파일을
> 옮겨줘. 그러면 내가 확인해서 삭제를 할게"

## 이 결정이 뒤집는 것

2026-08-10 결정은 **"종류는 폴더로 나눈다"**였다(`settings.py`의
`OWNER_AUDIO_WATCH_FOLDER_NAMES` 주석). 근거는 "한 폴더에 다 넣고 프로그램이
내용을 보고 판단하는 방식은 틀릴 수 있어서"였다.

**owner가 그 판단을 뒤집었다.** 폴더 넷을 기억하고 골라 넣는 것보다, 틀리면
고치는 쪽이 낫다는 것이다. 특히 **휴대폰에서 넣을 때** 폴더를 고르는 일이
번거롭다.

## 정한 것

| 항목 | 값 |
|---|---|
| 넣는 곳 | `C:\Users\atgro\OneDrive\#_videobox` (원드라이브, 휴대폰에서도 넣는다) |
| 분류 | VideoBox가 내용을 보고 정한다 -- 영상 / 그림 / 음악 / 효과음 |
| 자산 가치가 없는 것 | 같은 원드라이브의 `불필요` 폴더로 **옮긴다.** 지우지 않는다 |
| 처리 끝난 원본 | 지금처럼 보관함으로 옮긴다 |

**지우지 않는 이유:** owner가 직접 보고 지운다고 했다. 프로그램이 지우면
되돌릴 수 없고, 잘못 분류한 것과 진짜 쓰레기를 구별할 기회가 사라진다.

## 왜 원드라이브인가 (구글 드라이브가 아니라)

실측 2026-09-07:

- **구글 드라이브 `G:`는 스트리밍 드라이브다.** 윈도우에서는 보이지만 Docker가
  마운트하면 **빈 폴더로 보인다**(`compose.yaml` 주석이 같은 사실을 적어 두었다).
  쓰려면 미러링으로 바꿔야 하고, 용량도 37GB 사용 / 70GB 남음이라 비롤에 빠듯하다.
- **원드라이브는 파일이 디스크에 실제로 있다.** 표본 200개 중 클라우드에만 있는
  것이 **0개**였다. Docker가 그대로 읽는다.

## 음악과 효과음을 가르는 기준

이것이 2026-08-10에 "틀릴 수 있다"고 본 바로 그 자리다. 규칙을 여기 못박는다:

- **길이로 가른다.** 짧으면 효과음, 길면 음악.
- **틀리면 owner가 자료실에서 고칠 수 있어야 한다.** 그 길이 없으면 이 결정을
  실행할 수 없다.
- 확신이 없으면 **음악으로 둔다** -- 효과음 목록이 더 좁게 쓰이므로, 잘못 섞였을 때
  음악 쪽이 눈에 덜 거슬린다.

## 자산 가치가 없다고 보는 것

- 미디어가 아닌 파일(문서·압축·실행 파일 등)
- 열리지 않는 파일(길이도 화면도 못 읽는 것)
- 이미 자료실에 같은 내용이 있는 것(내용 해시가 같음)

이 셋 말고는 **옮기지 않는다.** 애매하면 자산으로 받는다 -- owner가 지우는 것이
프로그램이 버리는 것보다 안전하다.
