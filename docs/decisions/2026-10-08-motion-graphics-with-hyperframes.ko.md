# 2026-10-08 — 설명 모션(하이퍼프레임)을 영상에 같이 쓴다 (범위 확장 승인)

**승인:** 루이스 대표님, 2026-10-08, 채팅("그래 진행하자").
**이유(대표님 말):** B-roll 영상을 만들다가 시각화 설명이 필요하면 그 자리를 모션으로 쉽게 이해되게 바꾸려고 한다. 전체 화면도, 오버레이도 좋다.

## 무엇이 바뀌는가
- CLAUDE.md §2.1의 "고급 모션그래픽은 범위 밖"을 **좁게** 푼다. 풀리는 것은 *정해진 템플릿에 숫자·글을 채워 만드는 설명 모션*(막대 비교·금액 카운터·단계 목록 등)뿐이다. 자유 형식 모션그래픽·임의 키프레임·색보정 등은 여전히 범위 밖.
- 엔진은 **하이퍼프레임**(npm `hyperframes`, Apache-2.0) 하나. 리모션(`remotion-dev/remotion`)은 계속 `exclude`(엔진이 둘이 되고 라이선스 확인이 필요) — 하이퍼프레임으로 부족할 때 다시 연다.
- 사람 게이트(제목 선택·대본 확정·업로드)는 그대로. 모션은 유진이 *제안*하고 대표님이 고른다.

## 2026-10-08 측정(스파이크, 코드 변경 없음)
Windows 네이티브에서 WSL·Docker 없이 렌더됨(hyperframes 0.8.140, node 24, ffmpeg 8.1.1). 전부 종료 코드 0.
- 6초 클립 1080p/30fps: 막대 16.2초 · 금액 카운터(5초) 15.0초 · 단계 목록 11.9초. 고정 시작비용 약 4초. 해상도·fps 영향은 작다. 파일 0.3~1MB(H.264).
- 한글: NotoSansKR을 컴포지션 폴더에 @font-face로 넣으면 선명(₩·쉼표 포함). 안 넣으면 Google Fonts를 받으러 간다.
- 오버레이: mp4는 불투명뿐. `--format webm`(VP9 알파) 또는 mov(ProRes4444)로 알파가 나온다. ffmpeg로 전체 화면 삽입·60% 작은 창+0.3초 페이드 둘 다 만들었다(필터 명령은 스파이크 보고서 `artifacts/motion-spike/motion-spike-report.md`).
- 처음 렌더 때 자체 chrome-headless-shell 약 270MB를 `~/.cache/hyperframes`에 받는다. 익명 텔레메트리가 기본 켜짐 → `HYPERFRAMES_NO_TELEMETRY=1`, `DO_NOT_TRACK=1`로 끈다.
- **기본은 오프라인이 아니다.** 컴포지션이 GSAP를 CDN에서 받는다. 제품에서는 폰트·GSAP를 로컬 파일로 같이 두고 **네트워크 0건**으로 렌더해야 한다.
- open-design의 `hyperframes-*` "템플릿"은 에이전트용 프롬프트 json뿐이라 그대로 쓸 수 없다. 템플릿은 우리가 직접 만든다.

## 설계 방침 (구현 때 지킬 것)
1. **모델이 자유 코드를 쓰지 않는다.** 컴포지션은 우리가 검증한 템플릿이고, 모델/유진은 템플릿을 고르고 `--variables` JSON(숫자·글)만 채운다. 인포그래픽 거절기가 스크립트를 막는 것과 충돌하지 않게 하는 방법이기도 하다.
2. **호스트 다리로 돌린다**(목소리·캡컷·그림 다리와 같은 방식, 같은 문지기·토큰). 컨테이너 안에서 Chrome을 띄우지 않는다.
3. 결과는 자료실 자산(mp4/webm)이고, 편집기에서는 B-roll 자리에 **전체 화면** 또는 **오버레이(작은 창+페이드)**로 쓴다. 오버레이 카드는 배경 없는 글자가 아니라 반투명 카드 배경을 둔다(스파이크 프레임에서 테스트 패턴 위 글자 가독성이 낮았다).
4. 화면에 열면 유진도 같은 조각에서 쓸 수 있게 배선한다(상시 지시).

## 단계
1. (끝남) 측정 스파이크.
2. 템플릿 3종(막대·카운터·단계) 파라미터화 + 폰트·GSAP 로컬화 + 모션 다리 + 자료실 "모션 만들기".
3. 유진 연결(장면에 모션 제안·적용·되돌리기).
4. 오버레이 모양 다듬기, 30초 이상·연속 렌더 측정, 필요하면 리모션 재검토.
