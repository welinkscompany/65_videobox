# 여백·글자 크기 척도 (owner 승인 2026-08-19)

## 무엇을 승인했나

owner가 "전체 사이트 여백·디자인·크기를 다시 점검"하라고 했고, 아래 측정 결과를
보고한 뒤 **"끝까지 진행해"로 척도 도입을 승인**했다.

| | 전 | 후 |
|---|---|---|
| 여백에 쓰인 서로 다른 값 | **21가지** | **8단계 토큰** |
| 글자 크기 | **15가지** | **7단계 토큰** |

## 왜 필요했나

색은 `--vb-accent` 같은 토큰이 있는데 **여백·크기는 토큰이 하나도 없었다.**
그래서 컴포넌트마다 자기 숫자를 골랐고, 0.85rem 이하에만 16단계가 몰렸다.
0.05rem은 0.8px이라 **눈으로는 구분되지 않으면서 일관성만 깨뜨린다.**

## 척도

```css
--vb-space-1: 0.25rem;  --vb-space-5: 1.25rem;
--vb-space-2: 0.5rem;   --vb-space-6: 1.5rem;
--vb-space-3: 0.75rem;  --vb-space-7: 2rem;
--vb-space-4: 1rem;     --vb-space-8: 2.5rem;

--vb-text-xs: 0.75rem;  --vb-text-lg: 1.1rem;   --vb-text-2xl: 1.65rem;
--vb-text-sm: 0.85rem;  --vb-text-xl: 1.25rem;  --vb-text-3xl: 2.35rem;
--vb-text-md: 0.95rem;
```

**새 값이 필요하면 여기 한 줄을 더한다.** 화면에서 임의의 숫자를 쓰지 않는다.

## 어떻게 적용했나

기존 값을 **가장 가까운 단계로** 옮겼다. 최대 이동은 2.4px(0.1rem → 0.25rem)이고
대부분 0.8~1.6px이다. 선언 196개가 바뀌었다.

## 한 곳은 예외다 — 미리보기 판

`.vb-preview-stage`만 척도의 **한 단계 아래**(gap `space-1`, padding `space-2`)를
쓴다. 반올림 그대로 적용했더니 여섯 줄의 gap과 상하 padding이 합쳐 **11px**을
먹어 미리보기가 승인된 바닥(작업판의 3분의 1) 아래로 내려갔고 e2e가 잡았다.

이 판의 여백이 촘촘한 것은 취향이 아니라 **측정으로 정해진 제약**이다
(`2026-08-17-editor-capcut-layout-approval`의 "미리보기가 8.5%로 되돌아가지 않게").

## 함께 정리한 것

페이지 여백과 최대 폭의 임자를 **껍데기(`.vb-product-content`) 하나로** 모았다.
카탈로그가 같은 값을 한 벌 더 걸어 제목이 왼쪽에서 80px, 위에서 91px까지 밀려
있었다. 지금은 40px이고 네 화면이 같은 기준을 쓴다.
