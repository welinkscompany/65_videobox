## 결정

**컨테이너에 목소리 엔진을 넣지 않고, 이미 이 컴퓨터에 깔린 것을 부른다.**
owner가 2026-09-02에 승인했다.

그림 생성이 ComfyUI를 `host.docker.internal:8188`로 부르는 것과 **같은 방식**이다
(`docs/development-fast-path.ko.md` §10.14 조항 2-C). 목소리는 **8199**를 쓴다.

| | 값 |
|---|---|
| 호스트 쪽 | `scripts/host_tts_service.py` (127.0.0.1:8199) |
| 컨테이너 쪽 | `HostTTSBridgeProvider` (`VIDEOBOX_TTS_ENGINE=host_bridge`) |
| 띄우는 파이썬 | **저장소 루트 `.venv`** (worktree의 `.venv`가 아니다 — 거기엔 torch가 없다) |
| 기본 엔진 | `local_xtts` (지금 깔린 것) · `VIDEOBOX_HOST_TTS_ENGINE`으로 교체 |

## 왜 이 방식인가

컨테이너에 torch와 2GB 모델을 넣으면 이미지가 3GB 가까이 커지고 재빌드가 매번
길어진다. 그런데 **엔진은 이미 이 컴퓨터에 있다**(XTTS 0.27.5 + torch 2.8.0 +
모델 1.8GB). 없는 것을 새로 넣는 게 아니라 있는 것을 쓰는 쪽이 싸다.

## 목소리 샘플은 경로가 아니라 내용으로 보낸다

컨테이너와 호스트는 같은 경로를 보지 않는다. 경로를 보내면 못 찾거나,
**더 나쁘게는 다른 파일을 찾는다.** 그래서 샘플 오디오를 실어 보낸다.

## 나가는 곳은 이 컴퓨터뿐이다

주소 검사는 ComfyUI 쪽과 같은 규칙이다 — 정해진 호스트(`127.0.0.1`,
`host.docker.internal`)·정해진 포트·경로 없음·리다이렉트 금지. **목소리 샘플이
실려 나가는 요청이라** 더 엄격히 본다. 호스트 서비스도 127.0.0.1에만 묶는다.

## 실측 (2026-09-02)

- 컨테이너 → 호스트 다리 → XTTS 복제 → 영어 음성 (한 장면 24초)
- 제품 경로로 5장면 중 **3장면 더빙 성공**, 만든 소리는 24000Hz(XTTS 특징)
- 나머지 2장면은 **1.25배 규칙에 걸려 정직하게 거절** — 원래 목소리가 남았다

## 알게 된 것: 복제 엔진은 espeak보다 느리게 말한다

같은 문장이 espeak 3.58초, XTTS 6.30초였다. 그래서 **복제로 바꾸면 "너무 길어서
못 넣는" 장면이 늘어난다.** 속도 규칙(1.25배)을 느슨하게 풀지 않았다 — 소리가
우스워지는 선은 엔진이 바뀐다고 달라지지 않는다. 대신 번역을 짧게 하도록 이미
지시하고 있고, 못 넣은 장면은 화면에 그대로 말한다.

## 기본값은 창작자 목소리다 (2026-09-02 후속)

`VIDEOBOX_TTS_ENGINE`의 기본을 `espeak`에서 **`host_bridge`로 바꿨다.**

목소리 프로그램이 안 켜져 있으면 더빙은 **"목소리 프로그램을 켜 주세요"라고
말하고 멈춘다.** 조용히 기계 목소리로 대신 읽지 않는다 -- **내 목소리인 줄 알고
내보내는 것이 못 만드는 것보다 나쁘다.** 켜진 것과 꺼진 것을 화면이 구분할 수
있어야 한다는 §10.14 2-C와 같은 규칙이다.

켜는 법은 한 줄이다. 깔려 있는 것 중 나은 것(chatterbox → XTTS)을 알아서 고른다.

```
pwsh -File scripts/start-voice.ps1
```

기계 목소리로 쓰고 싶으면 `VIDEOBOX_TTS_ENGINE=espeak`으로 바꾼다.

  **`'NoneType' object is not callable`**이라는 엉뚱한 말이 나온다.
