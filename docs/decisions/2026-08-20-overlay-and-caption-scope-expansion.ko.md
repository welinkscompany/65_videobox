# 화면 요소·자막 범위 확장 승인 (2026-08-20)

owner가 명시 승인했다. `docs/implementation-plan.ko.md` §4의 **명시 제외 항목 하나를
푸는** 결정이 포함돼 있으므로 여기 남긴다.

## 승인한 것

1. **아이콘 얹기** — 화살표·동그라미·별 같은 표시를 장면에 얹는다. 글꼴 글자로
   그리므로 새 자산 파일이 없다. 나중에 Material Symbols 글꼴(Apache-2.0) 한 장을
   더해 아이콘 폭을 넓히는 것도 승인 범위다.
2. **자막 배경 상자·그림자** — 캡컷·Vrew에 있는 글자 뒤 상자. 화면에 칸은 있었으나
   완성본에 닿지 않던 것을 실제로 되게 한다(실측으로 확인된 결함).
3. **한국어 무료 글꼴 편입** — 기존 스타터 팩은 CC0 전용 정책이었다. **OFL·ISC 계열
   편입을 승인**한다. 조건: 재배포·임베딩을 명시 허용하는 라이선스만, 근거를
   `THIRD_PARTY_NOTICES.md`에 남긴다. "사용 무료·재배포 금지" 글꼴은 넣지 않는다
   (컨테이너 이미지에 담는 것이 재배포에 해당한다).
4. **라이브러리에 그림 종류 추가** — 사진·일러스트를 여러 프로젝트가 공유한다.
5. **움직이는 도형** — **§4의 "고급 모션그래픽" 제외를 이 범위에서 푼다.**

## 4번에서 이번 범위에 넣지 않은 것 (2026-08-20 구현 시 기록)

**기본 그림 자산(무료 일러스트·사진)은 넣지 않았다.** owner가 자기 그림을 넣을
자리까지만 만들었다.

이유는 라이선스다. Unsplash·Pexels는 **쓰는 것**은 넓게 허용하지만, 사진을 모아
**팩으로 묶어 재배포하는 것**은 각자의 약관이 명시적으로 제한한다(Unsplash는
"경쟁 서비스" 조항, Pexels는 대량 재배포 조항). 컨테이너 이미지에 담는 것은
3번 항목이 이미 정한 대로 **재배포에 해당**하므로, 글꼴과 같은 기준을 그대로
적용하면 이 둘은 지금 상태로는 넣을 수 없다.

넣으려면 별도 판단이 필요하다. 판단 기준은 3번과 같게 두는 것이 일관적이다 --
**재배포·임베딩을 명시 허용하는 라이선스만**, 근거는 `THIRD_PARTY_NOTICES.md`에
남긴다. 후보로는 CC0 전용 출처(예: openclipart, CC0 표기가 붙은 개별 자산)가
조건을 만족할 가능성이 높지만, **자산 단위로 확인해야 한다** -- 사이트 전체가
CC0라고 적혀 있어도 개별 업로드가 그렇지 않은 경우가 있다.

## 5번의 경계 (중요)

전면 해제가 아니다. 승인 범위는 **오버레이 하나가 등장·퇴장·이동하는 정도**이며,
`§4`가 함께 제외한 **임의 키프레임 편집기·멀티캠·전문 색보정·고급 마스크는 그대로
범위 밖**이다. 즉 "타임라인에 키프레임을 찍는 UI"를 만드는 승인이 아니다.

구현은 자막을 굽는 데 이미 쓰는 ASS 경로에 도형 그리기를 얹는 방향을 먼저 잰다 —
새 렌더 체계를 만들지 않는다.

## 왜 지금인가

owner가 캡컷·Vrew와 나란히 놓고 물었고, 재보니 상당수가 **부품은 있는데 화면이
없거나 렌더에 닿지 않는 상태**였다. 없는 기능을 새로 만드는 것보다 이미 있는 것을
잇는 비용이 작다.
