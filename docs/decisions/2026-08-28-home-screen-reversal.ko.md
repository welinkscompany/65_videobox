# `/`를 진짜 첫 화면으로 — 2026-08-19 "열면 바로 편집기" 결정을 뒤집는다

- 결정 상태: **approved**
- 결정 시각: 2026-08-28
- 승인자: owner
- 갱신하는 것: `AppRouter.tsx`의 `indexRoute`. 2026-08-19에 owner가 캡컷을 근거로
  직접 정했던 "프로젝트를 열면 편집 화면이 먼저"(`resolveProjectStage(saved, "edit")`로
  조용히 건너뛰던 동작)를 되돌린다.

## owner가 말한 것

> "나는 너무 답답한게, 왜 처음에 시작할때 로딩이나, 뭔가 시작하는 부분이 없어?
> 지금 너가 만든 페이지에 가장 처음이 어디서부터 시작하는거야?"

확인해 보니 `/`는 프로젝트 목록을 조용히 불러온 뒤 마지막으로 열었던 프로젝트의
편집기로, 없으면 `/projects`로 즉시 건너뛰는 구조였다. 그 사이에는 로딩 표시조차
없어 흰 화면만 보였다. **"시작하는 자리" 자체가 없었다.**

> "첫화면을 만들고, 거기에서 어떤 방식으로 편집을할건지 결정을 해야 되잖아.
> 음성 녹음을 할건지, 음성 녹음해서 클론을 시킬건지, 영상을 바로 편집할건지,
> 영상 기획을 할건지.. 여러가지 범위로 나뉠거 아니야"

## 왜 예전 결정과 부딪히는지 — 숨기지 않는다

2026-08-19 결정(`AppRouter.tsx:529` 주석)의 근거는 "캡컷도 열면 바로 편집판이다"였다.
그 근거 자체는 여전히 유효하다 — **다만 그건 "프로젝트를 하나 골랐을 때"의 이야기고,
"프로그램을 처음 열었을 때"와는 다른 질문이었다.** 캡컷도 프로그램을 열면 홈(최근
작업 목록 + 새로 시작 버튼)이 먼저 뜨고, 그 홈에서 프로젝트를 고르거나 새로 만들면
그제서야 편집판으로 들어간다. 2026-08-19 결정은 이 둘을 하나로 합쳐 버렸다.

**뒤집는 것은 "프로젝트 카드를 누르면 편집기로 간다"가 아니다** — 그건 그대로 둔다
(`ProjectCatalogCard`의 이름 링크, `AppRouter.tsx:538` 참고). 뒤집는 것은 **"프로그램을
열자마자 누구에게 물어보지도 않고 편집기로 건너뛰는 것"**뿐이다.

## 승인된 것

1. **`/`는 이제 항상 `/projects`로 간다.** `opensLastProjectOnStart()`/저장된
   마지막 프로젝트 조회를 이 경로에서 없앴다.
2. **마지막 프로젝트로 빠르게 가는 길은 없애지 않는다** — 이미 위 띠에
   `편집기로 돌아가기`(`onResumeEditor`, `/library`·`/footage`에서도 보임)로
   옮겨져 있던 것을 그대로 쓴다.
3. **로딩 표시를 넣는다.** `rootRoute`에 `pendingComponent`를 붙여, 프로젝트
   목록을 불러오는 동안 "VideoBox를 여는 중이에요…"가 뜬다. (JS 번들 자체가
   로드되기 전의 흰 화면은 `index.html`의 정적 셸 몫이라 이번 범위 밖이다 —
   다음에 필요하면 별도로 다룬다.)
4. **"어떤 방식으로 시작할지" 갈래를 `/projects` 화면에 늘린다.** 기존
   "+ 새 프로젝트 만들기"(이름부터 입력 → 이야기 화면)는 그대로 두고, 이름을
   안 물어도 되는 지름길 둘을 나란히 놓는다.
   - **빈 편집판으로 바로 시작** — 프로젝트를 자동 이름으로 만들고 곧장
     빈 편집판을 열어 편집기로 보낸다.
   - **내 목소리 등록·클론** — 프로젝트를 자동 이름으로 만들고 미디어 단계의
     내레이션 자리로 보낸다.

## "음성 녹음/클론을 프로젝트 없이" 요청과 부딪힌 것

owner가 처음 그린 그림은 프로젝트 없이도 목소리부터 등록하는 것이었다. 확인해 보니
목소리 샘플은 전부 프로젝트 자산으로 저장되는 구조라(`VoiceTtsSettings`가
`projectId`를 필수로 받음, §10.15 자산 검색 체계와 같은 전제) **프로젝트 없이 등록하는
길이 지금 데이터 모델에 없다.** 이걸 만들려면 project-less 자산이라는 새 개념이
필요해 이번 범위를 크게 넘는다.

**owner에게 다시 확인해 대안으로 정한 것**: 버튼을 누르면 프로젝트를 안 보이게
자동으로 하나 만들고 바로 목소리 등록 자리로 보낸다. 사용자에게는 "프로젝트"라는
개념이 앞을 막지 않는다 — 이름을 안 물어보고, 만든 뒤 바로 원하는 화면이 뜬다.

## 함께 감수하는 것

- **"시작할 때 마지막 프로젝트 열기" 설정을 없앴다.** 그 설정이 가리키던 동작
  자체가 없어졌으니 남겨 두면 거짓말하는 토글이 된다. 대신 설정 "일반" 탭은
  당장 조절할 항목이 없다는 짧은 안내로 남겨 뒀다 — 탭 구조(6개) 자체를 없애는
  건 라우팅 여러 곳을 건드리는 별개 작업이라 이번 범위 밖으로 뒀다.
- **자동 생성된 프로젝트 이름이 겹칠 수 있다.** `새 영상 14:32`처럼 시:분만
  붙이므로 같은 분에 두 번 누르면 이름이 같아진다. 프로젝트 이름 자체가 유일해야
  한다는 백엔드 제약이 없어 오류는 안 나고, 언제든 이름 바꾸기로 고칠 수 있다.
- **빈 프로젝트가 쌓일 수 있다.** "빈 편집판으로 바로 시작"을 눌러 보기만 하고
  나가면 이름만 있는 프로젝트가 남는다. 보관함으로 정리하는 기존 흐름을 그대로
  쓴다 — 이번 결정에서 새로 만들지 않는다.

## 확인한 것

브라우저로 실제 컨테이너에서: `/` → `/projects` 리디렉션, "빈 편집판으로 바로
시작" → 프로젝트 생성 → 편집기 진입(실제 편집 작업판 렌더까지), "내 목소리
등록·클론" → 프로젝트 생성 → 미디어 단계 → 내레이션 탭 → 목소리 등록 화면까지
전부 눌러서 확인했다. 프런트엔드 테스트 1345 passed(신규 2개), `tsc` 통과.

## 범위 밖

- `index.html`의 정적 로딩 화면(JS 로드 전 흰 화면)은 이번에 다루지 않았다.
- 설정 "일반" 탭을 완전히 없애고 6개 탭 구조를 다시 짜는 것.
- Vrew 참고: 마케팅 페이지만 봤고 실제 앱(Chrome 전용)은 이 환경에서 못 열어
  깊이 못 봤다. 확인된 것은 Vrew도 큰 선택 화면보다 메뉴(`새로 만들기`/`프로젝트
  열기`) 구조라는 것뿐이다.
