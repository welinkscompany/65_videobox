# 캡컷 벤치마킹 — 버튼 단위까지 확장 (구성·배치·크기) — 승인 기록

- 결정 상태: **approved**
- 결정 시각: 2026-08-30
- 승인자: owner (루이스 대표님)
- 확장하는 것: `2026-08-29-capcut-full-structure-and-dark-theme.ko.md`의
  "메뉴·배치 구조를 캡컷과 완전히 동일하게" 범위를 화면 구조 수준에서
  **컴포넌트 단위**로 좁혀 확정한다. 그 문서를 대체하지 않는다 — 그 문서가
  정한 것(5단계 계획, 다크 팔레트, 기능 제외 목록)은 전부 그대로 유효하다.

## owner가 말한 것 (원문)

> "그리고 캡컷 벤치마킹은 나는 버튼 하나까지도 다 벤치마킹 하라는거야. 버튼
> 구성, 버튼 배치, 크기 등등 모두다 벤치마킹해"

## 승인된 것

**VideoBox에 이미 있는 기능의 화면 요소는 캡컷과 같은 자리·같은 구성·비슷한
크기로 맞춘다.** 화면 구조(메뉴·탭·패널 배치)뿐 아니라 그 안의 버튼 단위까지
내려가서:

- 버튼 구성 — 어떤 버튼들이 한 자리에 같이 있는지, 순서는 어떤지
- 버튼 배치 — 화면의 어느 위치(좌/우/상단바/하단 고정 등)에 놓이는지
- 버튼 크기 — 아이콘 크기, 버튼 높이/폭, 여백

를 캡컷 화면을 근거로 맞춘다.

## 범위 밖 — `2026-08-29` 문서의 원칙을 그대로 유지

- **VideoBox에 없는 기능의 버튼 자리를 만들지 않는다.** 캡컷에 있지만
  VideoBox 범위 밖인 기능(멀티캠, 임의 키프레임, 전문 색보정 등,
  `implementation-plan.ko.md` §4)의 버튼은 이 문서로도 추가하지 않는다.
  이 문서는 **있는 기능을 어떻게 배치할지**를 다루지, 없는 기능을 새로
  만들라는 뜻이 아니다.
- 색상 팔레트는 `2026-08-29` 문서가 이미 확정했다 — 이 문서가 다시 열지 않는다.

## 실행 시 판단 기준 (재사용 게이트용)

- 근거는 `docs/decisions/assets/`에 저장된 캡컷 캡처 3장이다(2026-08-30
  세션에서 과거 대화 로그를 뒤져 파일로 복구, `2026-08-29` 문서에 경위
  기록):
  - `2026-08-29-capcut-home-screen.webp` — 첫 화면(배너·AI 카드·최근 프로젝트)
  - `2026-08-29-capcut-editor-screen.png` — 편집기 화면 전체 배치
  - `2026-08-29-capcut-editor-panel-resize-markup.png` — 크기조절 경계 표시
  화면별로 이 세 장 밖의 영역이 추가로 필요하면 owner에게 새 캡처를 요청한다.
  픽셀 단위로 추출한 정확한 값이 아니라 근사치로 시작하고, 구현 후 실제
  화면을 보고 조정한다 — 다크 팔레트 때와 같은 방식(`2026-08-29` 문서
  56행 참고).
- 화면(컴포넌트)마다 개별 진행 — 한 번에 전체를 다시 짜지 않는다. 어떤
  화면부터 시작할지는 owner 우선순위를 따른다.
- 기존 컴포넌트(shadcn/ui 등) 재사용을 우선한다 — 크기·배치만 캡컷에
  맞추고 컴포넌트 자체를 새로 짜지 않는다.

## 함께 감수하는 것

- 버튼 크기·배치가 바뀌면 관련 스냅샷·접근성(대비, 터치 타깃 크기) 테스트가
  재작성이 필요할 수 있다.
- 범위가 넓다 — 화면이 많아 한 세션에 다 끝내지 못할 가능성이 높다. 어떤
  화면부터 손댈지 우선순위를 owner와 다시 확인한다.
