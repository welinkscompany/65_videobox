> 구성, 버튼 배치, 크기 등등 모두다 벤치마킹해"

## 승인된 것

**VideoBox에 이미 있는 기능의 화면 요소는 캡컷과 같은 자리·같은 구성·비슷한
크기로 맞춘다.** 화면 구조(메뉴·탭·패널 배치)뿐 아니라 그 안의 버튼 단위까지
내려가서:

- 버튼 구성 — 어떤 버튼들이 한 자리에 같이 있는지, 순서는 어떤지
- 버튼 배치 — 화면의 어느 위치(좌/우/상단바/하단 고정 등)에 놓이는지
- 버튼 크기 — 아이콘 크기, 버튼 높이/폭, 여백

를 캡컷 화면을 근거로 맞춘다.

## 범위 밖 — `2026-08-29` 문서의 원칙을 그대로 유지

- **VideoBox에 없는 기능의 버튼 자리를 만들지 않는다.** 캡컷에 있지만
  VideoBox 범위 밖인 기능(멀티캠, 임의 키프레임, 전문 색보정 등,
  `implementation-plan.ko.md` §4)의 버튼은 이 문서로도 추가하지 않는다.
  이 문서는 **있는 기능을 어떻게 배치할지**를 다루지, 없는 기능을 새로
  만들라는 뜻이 아니다.
- 색상 팔레트는 `2026-08-29` 문서가 이미 확정했다 — 이 문서가 다시 열지 않는다.

## 진행 상태

### 1단계 완료 — 편집기 상단 도구줄에서 편집 동작 분리 (커밋 `d5fd8012`)

캡컷 편집기 캡처를 실제로 대조해 보니, 편집 동작(되돌리기·다시 실행·
나누기·앞과 붙이기·빼기·다음 장면에도)은 상단 도구줄이 아니라 **타임라인
바로 위, 확대·축소와 같은 줄**에 있었다. VideoBox는 이 모두가 상단 한
줄에 섞여 있었다 — `TimelineDock`이 이미 갖고 있던 그 줄(줌 조작 자리)에
`editToolbar` 슬롯을 만들어 그대로 옮겼다. 상단은 이제 미디어·세부 정보
토글 + 내보내기만 남았다. 재빌드 후 브라우저에서 실제 위치 확인 완료.

### 판단이 필요해 남긴 것 — 상단 도구줄의 정보 구조 자체

owner에게 물어 **"캡컷처럼 콘텐츠 탭으로 재구성"**을 확인받았다. 다만
이건 1단계보다 훨씬 큰 변경이다: 캡컷 상단 줄(미디어·오디오·텍스트·
스티커·편집효과·전환·캡션·필터·조정·템플릿·AI 아바타)은 **왼쪽 패널에
늘 떠 있는 콘텐츠 카테고리 탭**이고, VideoBox의 미디어·세부 정보는
**패널을 열고 닫는 토글 버튼**이다(패널 안에 미디어·오디오·자막·전환
탭이 한 단계 더 들어가 있다). 캡컷처럼 만들려면 지금의 서랍(drawer)/
도크(dock) 열고 닫기 모델 자체를(반응형 폭 대응 포함) 상시 노출형 패널 +
최상위 탭 전환 모델로 바꿔야 한다 — 리사이즈 가능 패널·좁은 화면 서랍
전환 로직까지 얽혀 있어 1단계보다 위험이 훨씬 크다.

**owner 확인**: "결국은 다 바꿀 건데 어떤 걸 먼저 하는 게 나아?"라고
물어, 구조부터 먼저 하는 게 낫다는 답(작은 단위를 먼저 다듬으면 구조가
바뀔 때 이중 작업이 된다)과 함께 "제대로 확실하게 짚어가며 진행"을
지시받아 착수함.

### 2단계 완료 — 왼쪽 패널 콘텐츠 탭을 편집기 맨 위로 승격 (커밋 `56511c0c`)

`EditorAssetBrowser`가 2026-08-27에 이미 만들어 둔 탭(미디어·오디오·자막·
전환, `vb-editor-assets__panes`)이 패널 **안**에 있던 것을 패널 **바깥**,
편집기 맨 위로 옮겼다. 예전 "미디어" 아이콘 하나가 패널을 열고 닫기만
했다면, 이제 이 네 탭이 늘 보이고 누르면 그 내용으로 패널이 열린다 —
캡컷과 같은 동작이다. `EditorAssetBrowser`의 탭 상태를 제어 가능(controlled)
하게 바꿔서(`pane`/`onPaneChange`/`renderPaneTabs`), 패널 내용 로직은
그대로 재사용하고 탭 버튼만 `EditorWorkbench` 맨 위로 옮겼다 — 두 번
짜지 않았다.

**한 가지 조심한 것**: 데스크톱 모드에서는 같은 탭을 다시 누르면 패널이
접힌다(전체 화면 미리보기, owner 승인 2026-08-17을 여전히 쓸 수 있게).
**서랍(좁은 화면) 모드는 이 접기를 안 한다** — 예전 단추도 서랍에서는
항상 열기만 했지 닫은 적이 없어서, 접는 동작을 더했다가 시험 4건이
실패하며 그 차이를 실측으로 확인했다.

재빌드 후 브라우저에서 실제로 "미디어 / 오디오 / 자막 / 전환 / 세부 정보 /
내보내기"가 맨 위에 늘 보이고, "오디오"를 누르면 패널이 곧바로 음악
목록으로 열리는 것을 확인했다.

### 3단계 완료 — 오른쪽 패널("세부 정보")도 상시 노출로 전환

owner 확인 후("오른쪽 패널도 이어서 상시 노출로 바꿔줘") 착수. 왼쪽과 달리
오른쪽은 탭이 하나뿐이라(선택한 클립 속성 + 유진 AI 대화가 한 패널 안에
같이 있음) 전환할 대상이 없다 — 그래서 왼쪽처럼 탭을 패널 밖으로 승격하는
작업은 필요 없었고, **이미 열려 있어도 다시 눌러 닫을 수 있던 것만** 캡컷과
다른 점이었다.

`EditorWorkbench.tsx`에 `openRightPane` 함수를 추가해 "세부 정보" 단추의
동작을 바꿨다: 안 보이면 열고(중간 폭 화면에서 왼쪽이 보이고 있었다면
`toggleDock`의 기존 `closesTheOther` 조정이 왼쪽을 대신 접는다), 이미
보이면 아무 것도 하지 않는다 — 캡컷의 정보 패널처럼 자기 단추로는 못
닫는다. 서랍(좁은 화면) 모드는 손대지 않았다: `openDrawer`를 그대로 불러
열고, 닫기는 여전히 서랍의 `닫기` 단추·Esc로만 한다.

`EditorAssetBrowser`처럼 패널 안 내용을 다시 짜지 않았다 — 단추 하나의
클릭 동작만 바꿨다. 재빌드 후 브라우저에서 실제로 확인: 데스크톱
단일-도크 폭에서 "세부 정보"를 열고 다시 눌러도 안 닫히고, 좁은 화면
서랍 모드에서는 열기·`닫기` 단추 닫기가 그대로 동작했다. 프런트엔드
전체 시험 1,371개 통과.

**감수한 것**: 왼쪽·오른쪽이 동시에 열리는 `desktop-both` 모드로 가는
폭 기준 자체는 이번에 바꾸지 않았다 — persisted `leftOpen`/`rightOpen`이
둘 다 참이어야 하는 기존 규칙 그대로다. 이번 지시는 "닫을 수 없게"였지
"기준 폭을 넓혀라"가 아니었다.

### 4단계 착수 — 첫 화면("프로젝트" 목록), 실측 중 시스템 버그 발견해 먼저 고침

owner "진행해" 지시로 다음 화면(`/projects`)의 버튼 단위 대조를 시작했다.
`docs/decisions/assets/2026-08-29-capcut-home-screen.webp`(캡컷 첫 화면)의
"+ 프로젝트 만들기" 배너는 두드러지게 큰(약 140px 높이 추정) 둥근 CTA인
반면, VideoBox의 "+ 새 프로젝트 만들기"는 실측 결과 높이 35px, 모서리
반지름 0px로 렌더링되고 있었다 — `.vb-catalog-create`의 CSS 소스는
`min-height: 5rem`(80px)·`border-radius: var(--vb-radius-md)`를 이미
지정하고 있었는데도(캡컷 대조를 이미 염두에 둔 값), 실제로는 전혀
반영되지 않고 있었다.

**원인은 CapCut 대조와 무관한 기존 CSS 결함 두 가지였다** (개발자 도구로
`getComputedStyle`·`document.styleSheets` 직접 대조해 확인, 화면 느낌이
아니라 실측):

1. `styles/product-shell.css`의 "Intranet DS normalization" 블록이
   `.vb-product-shell [data-slot=button][data-variant="default"]`에
   `border-radius: var(--radius-2xl)`를 걸고 있었는데, `--radius-2xl`은
   **정의된 적이 없는 변수**였다 -- 반지름 척도를 셋(`--vb-radius-sm/md/lg`,
   owner 결정 2026-08-27)으로 줄이면서 이 두 줄만 옛 이름 그대로 남았다.
   정의 안 된 `var()`는 선언 자체를 무효로 만들어 초기값(0)으로 떨어진다 --
   그래서 **이 화면 전체의 default·outline 버튼이 전부** 모서리 없이
   각지게 그려지고 있었다. `features/footage/footage.css`에도 같은
   패턴이 두 줄 더 있었다(그중 하나는 `footage-design-system.test.ts`가
   깨진 값 그대로를 "정답"으로 박아 두고 있었다 -- 그 시험도 함께 고쳤다).
2. 같은 블록의 `.vb-product-shell [data-slot=button] { min-height:32px; }`은
   속성 선택자를 써서 특정도가 `.vb-catalog-create`(클래스 하나)보다 높다.
   그래서 이 버튼만 크게 만들려던 `min-height: 5rem`이 이 일반 규칙에
   조용히 눌려 한 번도 반영된 적이 없었다.

**고친 것**: `--radius-2xl` 두 자리를 전부 `--vb-radius-md`로 바꾸고,
`.vb-product-shell [data-slot=button].vb-catalog-create { min-height:5rem; border-radius:var(--vb-radius-md); }`를
같은 특정도로 뒤에 추가해 이 버튼만 이긴다. 다른 버튼(일반 default·outline)의
`min-height:32px`는 그대로 뒀다 -- 그건 버그가 아니라 "Intranet DS h-8
역할 높이" 의도된 값이다(`footage-design-system.test.ts`의 "keeps ...
h-8 role height" 시험이 그 의도를 명시).

**검증 완료** (커밋 `9378c5c0`): 백엔드 전체 pytest 4193 passed·56
skipped·0 failed, 프런트엔드 전체 1,371 passed. 재빌드 후 브라우저
`getComputedStyle` 실측 — "+ 새 프로젝트 만들기"는 높이 80px·모서리
반지름 10px(`.625rem`)로 확인, 옆의 일반 버튼("격자로 보기")은 높이
35px를 그대로 유지하면서 모서리만 10px로 고쳐졌다 — 의도한 대로 이
CTA만 커지고 나머지 버튼 높이는 안 건드렸다.

### 5단계 완료 — 보기전환·보관함 단추를 아이콘으로, 더 큰 시스템 결함 하나 더 발견 (커밋 `521f3c67`)

`docs/reference/capcut-observed-2026-08-22.ko.md` §1을 먼저 확인 —
"보기전환이 있어야 한다"는 이미 정해졌지만 **아이콘이냐 텍스트냐는
그 기록이 정한 적이 없었다**(캡컷은 "오른쪽에 검색·보기전환·휴지통·
프로젝트 동기화"라고만 적혀 있고, 실제로는 좁은 아이콘 줄이다). 그래서
재승인 없이 기존 결정을 덮어쓰는 문제는 아니었다.

"격자로 보기"·"줄로 보기"·"보관함 보기"를 전체 폭 텍스트 단추에서
아이콘 단추(`LayoutGrid`·`List`·`Archive`)로 바꿨다. 접근성 이름은
그대로 유지(`title` + `sr-only`) — 기존 시험 57개가 코드 수정 없이
그대로 통과했다.

**이 과정에서 더 큰 결함을 하나 더 발견했다**: 아이콘이 축소되지
않고 원본 크기(24px)로 나왔고, 세 단추 크기도 서로 달랐다(48x40 /
40x32). 원인을 실측으로 확인 — **이 빌드는 Tailwind의 번호 척도
유틸리티(`size-4`·`size-9`뿐 아니라 `h-9`·`gap-2`·`px-4`까지) 자체를
한 번도 컴파일한 적이 없다**(컴파일된 CSS 12만 자를 전부 뒤져도 이
문자열들이 안 나온다). 에디터 툴바가 이미 같은 문제를 겪고
`.vb-editor-workbench__toolbar [data-slot="button"] svg { width:1rem; height:1rem; }`로
우회해 뒀던 것을 발견해, 같은 값으로 `.vb-catalog` 범위에 맞춰
추가했다. 정사각형 아이콘 단추 크기(`width:2rem`)도 같이 정리.

**여기서는 안 고친 것**: 번호 척도 유틸리티가 이 빌드 전체에서 왜
한 번도 안 만들어지는지는 훨씬 큰 별도 조사거리다 — `.vb-*` 수기
CSS가 없는 자리는 전부 이 결함의 영향권일 수 있다는 뜻이라, 원인을
고치면 화면 전체에 걸쳐 파급 효과가 클 수 있다. 이번 범위(버튼 단위
벤치마킹)를 넘는 별도 점검·owner 확인이 필요해서, 이번엔 두 화면
(에디터 툴바·이 화면)에 필요한 만큼만 우회 규칙을 추가했다.

**남은 것**: 첫 화면의 퀵스타트 카드 2장은 대체로 이미 맞아 있다
(2026-08-29 결정 문서가 이미 다뤘음). 검색창 자체(입력칸 폭·자리)는
버튼이 아니라서 이번 범위 밖으로 남겨 뒀다.
