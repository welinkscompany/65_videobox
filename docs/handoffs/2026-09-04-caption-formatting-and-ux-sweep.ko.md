# 인계 — 자막 서식 · 목소리 파일 업로드 · UX 실측 점검 (2026-09-04)

**대체됨:** `docs/handoffs/2026-09-04-capcut-parity-autonomous-run.ko.md`

앞 인계: `2026-09-03-voice-cloned-dubbing-end-to-end.ko.md`

## 한 줄

owner가 밤사이 자율 진행을 요청했다. 두 가지 직접 지적(자막 세부 정보 칸에
탭이 없다, 자막 서식이 부족하다, 목소리도 파일 업로드가 있어야 한다)을
처리했고, 그 과정에서 **진짜 결함 셋을 화면 실측으로 더 찾아 고쳤다** — 셋
다 이름만 봐서는 못 잡고 실제로 눌러 봐서 나왔다. 마지막에 4개 에이전트로
종합 코드리뷰를 한 번 더 돌려 **결함 셋을 추가로 잡았다**(§8 참고) — 그중
하나는 유진의 자막 모양 제안이 창작자가 방금 켠 굵게·자간을 조용히 지울
뻔한, 진짜 위험한 것이었다.

## 오늘 다룬 것 (커밋 순서대로)

### 1. 자막 세부 정보 칸을 스타일·번역 두 탭으로 나눔

owner 지적: "글꼴 있는 박스... 탭 영역같은곳에 분리해야 되는데 아직도 그냥
스크롤 밑으로 때려박아 놓고." 실측하니 스크롤 전체 길이가 보이는 높이의
3.5배였고 `자막 스타일` 혼자 1223px(절반)이었다. 미디어 칸에 이미 있던
`.vb-inspector-tabs` 무늬를 재사용해 `스타일`/`번역·더빙` 둘로 갈랐다.

**첫 지적("미디어·오디오·자막·전환 버튼이 안 바뀐다")은 재확인하니 정상이었다**
— 아마 글꼴 상자(탭이 아예 없던 오른쪽 칸)와 왼쪽 네 탭을 같은 것으로 보신
듯하다. 진짜 결함은 오른쪽 세부 정보 칸에 탭이 없었던 것이었다.

### 2. 자막 굵게·기울임·자간 추가

owner 지적: "글꼴, 자막크기, 색깔 등등 이거 외에 글자를 수정하는 컴포넌트가
모두 있어야지." `CaptionStyle` 정본에 세 칸을 더하고 두 렌더 경로(ASS,
CapCut 내보내기) 모두에 이었다. `test_caption_style_fields_reach_the_render.py`
(ffmpeg로 실제로 굽고 픽셀 해시를 비교하는 장치, 2026-08-20부터 있었다)가
새 칸도 진짜로 화면을 바꾸는지 자동으로 재 준다.

**실기계에서 결함 하나 더 잡음**: 체크박스는 화면에 뜨는데 **저장 요청을
만드는 함수**(`editorCommandPort.ts`)가 따로 있었고 거기서 세 칸이 빠져
있었다 — 화면 상태는 바뀌는데 서버로 가는 요청엔 안 실렸다. ffmpeg 픽셀
시험은 `render_editing_session_ass`를 직접 부르므로 이 함수를 안 거쳐서
못 잡았다. 브라우저에서 체크박스를 직접 눌러 보고서야 나왔다.

### 3. 목소리로 시작하는 길에 파일 업로드 추가

owner 지적: "녹음 한 파일을 업로드하면 자동으로 음성을 읽어서 자막으로
깔아주는 이 방식도 있어야하는 기준이야." 찾아보니 **이미 절반은 있었다** —
`upload_source_voice` 엔드포인트(2026-08-29부터, 진짜 faster-whisper)와
`VoiceRecordStart.tsx`의 `upload()` 함수는 이미 어떤 File이든 받았는데,
화면에는 **그 자리에서 마이크로 녹음하는 버튼만** 있었다. 짝인
`SourceVideoStart.tsx`는 처음부터 파일 선택이 있었는데 목소리 쪽만 빠져
있었다. 파일 선택 칸을 더했다.

**실기계 검증**: chatterbox로 "안녕하세요. 오늘은 파일 업로드로 자막을
만드는 기능을 확인합니다."를 합성한 wav를 실제 엔드포인트에 올렸다 —
**한 글자도 안 틀리고** 그대로 받아써졌다.

### 4. 유진의 자막 모양 제안이 조용히 막히던 문제

2번 작업 뒤 전체 백엔드 시험(단독 실행)이 잡았다. 유진이 자막 모양을
제안하면 그 제안을 그대로 다시 보내는 요청만 통과시키는 증명 절차가 있는데,
**저장된 자막 모양(정본을 거쳐 이제 14칸)과 유진이 보내는 자막 모양(고정
스키마 11칸, 일부러 안 건드렸다)을 그대로 맞대 비교**하고 있었다. 칸 수가
달라지자 **유진의 모든 자막 모양 제안이 막힐 뻔했다** — 새 칸을 만들
때마다 반복될 함정이다. 비교 전에 유진이 보낸 쪽도 같은 정규화를 거치게
고쳤다. 자세한 원인·수정은 커밋 `0ed6a463b` 참고.

### 5~7. UX 실측 점검 — 이름만 있고 스타일 규칙 없는 화면 요소 감사

지난 세션에서 "vb- 클래스는 쓰는데 CSS 정의가 없는" 후보 37개를 문자열
대조로 뽑았었다(16개는 헛것, 21개가 진짜 의심). 오늘 그 21개를 하나씩
**실제로 열어서** 셋을 진짜 결함으로 확정했다:

5. **타임라인 트랙 잠금·눈·음소거 버튼 13개가 하나도 안 눌렸다.** 클립
   층이 트랙 전체를 `inset:0`으로 덮어 버튼이 안 보이고 안 눌렸다.
   owner가 2026-08-22에 지시한 기능인데 만든 뒤로 화면에서 못 썼다.
   (커밋 `ea95e332`)
6. **대화상자 안 버튼이 브라우저 기본 테두리·회색으로 샜다.** Radix
   Dialog는 `document.body` 직계 자식으로 포털돼 `.vb-product-shell`
   조상이 없다 — 그 안에서는 버튼 테두리를 지우는 CSS가 하나도 안
   먹었다. `ghost`·`secondary`·`destructive`·`link` 네 변형은 애초에
   그 규칙 자체가 없었다(default·outline만 있었다). `:where()`로 특정도
   0인 백스톱을 더해 포털 안팎 모두 커버했다. (커밋 `1248cc6f`)
7. **실행 취소·자르기 아이콘 단추 여섯 개가 간격 0px로 붙어 있었다.**
   `.vb-timeline-edit-toolbar`에 CSS가 아예 없었다. 옆 확대·축소 묶음과
   같은 무늬(`inline-flex` + 척도 간격)를 얹었다. (커밋 `05e4fcdd`)

**오탐 하나**: 자막 프리셋 목록이 겹친 것처럼 보였는데, 세로로 쌓인 목록을
가로 좌표만으로 잘못 재서였다(각 줄이 다른 세로 위치). 보고 전에 다시
확인해서 걸러냈다.

## 8. 종합 코드리뷰(4개 에이전트, `ea95e3323~1..HEAD`)로 잡은 것 셋

owner 요청으로 오늘 밤 전체 커밋(9건)을 line-by-line·removed-behavior·
cross-file·reuse/simplification/efficiency·altitude·conventions 8개 각도로
훑었다(4개 에이전트가 각도를 나눠 병렬로). 커밋 `db5ffb7c`.

1. **[높음] 유진의 자막 모양 제안이 굵게·기울임·자간을 조용히 지웠다.**
   3개 각도(A·B/C·conventions 아님, B/C가 가장 강하게)가 독립적으로 잡음.
   유진의 제안 스키마는 열한 칸뿐이라 세 칸을 모르고, 저장은 통째로
   덮어써서 창작자가 방금 켠 값이 유진의 색 제안 하나에 지워질 뻔했다.
   **증명 절차도 같이 걸려 있었다** — 어제 낸 정규화 수정("양쪽 다 기본값
   채워 비교")이 저장이 실제로 창작자의 값을 지워야만 통과하는 모양이었다.
   대조를 "유진이 보낸 칸만"으로 좁히고, 쓰는 쪽은 유진이 관여하는 칸만
   갈아 끼우도록 고쳤다. 수동 편집(전체 칸을 매번 보냄)은 영향 없음을
   실기계로 재확인(저장→새로고침 왕복 정상).
2. **[중간] 자간이 세로 영상에서 화면 크기에 비례하지 않았다.** `font_size_px`는
   `video_height/1080`을 타는데 자간(ASS `Spacing`)은 안 탔다. 같은 비율을
   태웠다.
3. **[낮음] 목소리 파일 올리기 실패 안내가 "다시 녹음해 주세요"라고 말했다.**
   파일을 올린 사람은 마이크를 쓴 적이 없다. 소스별로 안내를 나눴다.

**리뷰에서 나왔지만 안 고친 것(참고, 다음 세션 후보)**:
- **더 넓은 문제의 일부일 뿐일 수 있다** — `apps/web/src/ui-system.css`는
  Tailwind Preflight(기본 리셋)를 아예 안 쓰고 `.vb-product-shell` 스코프
  CSS로 대신한다(`ui-system.test.tsx`에 그렇게 하기로 한 시험 이름까지
  있다). 오늘 고친 대화상자 버튼 테두리 결함은 그 설계의 **증상 하나**였다 —
  리뷰가 확인한 바로는 `Select`·`DropdownMenu`·`Sheet`·`Tooltip` 전부 같은
  포털 방식을 쓰고, 바로 옆 `focus-visible` 규칙(line 220 근처)도 여전히
  `.vb-product-shell` 조상을 요구한다. 다음에 "포털 안에서 초점 링/다른
  버튼 기본값이 이상하다"는 제보가 오면 이 근본 원인부터 볼 것.
- 재사용/단순화 지적 몇 건(파일 선택 UI가 `SourceVideoStart.tsx`와
  `VoiceRecordStart.tsx`에 중복, 자막 탭 목록이 미디어 탭 목록과 중복,
  캡션 스타일 기본값 리터럴이 두 곳) — 전부 사실이지만 지금 동작을 안
  깨고, 고치는 게 오늘 밤 검증 범위를 넘어서 미룸.
