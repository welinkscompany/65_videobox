## 2. 새로 찾은 결함 둘과 원인 (이번 마감에서 실기로 잡았다)

1. **742e1924를 열면 편집기가 `화면을 그리다 멈췄어요`로 죽음(`6d7939a27`로 고침).**
   콘솔 `RangeError: Rectangle width and height must be positive`. 원인은 **잠복해 있던 부동소수 결함**이다. 보이는 창의 끝이 `60.00000000000001초`로 계산돼, 정확히 60초에 시작하는 클립의 폭이 0이 되고, 클립 투영(`deriveClipRect`)이 폭 0을 오류로 던졌다. 이 결함은 `18b3821a7`이 넣은 "잰 칸 폭이 들어오면 처음 배율을 다시 맞추는" 효과가 창 끝 계산을 바꿔 **드러낸** 것이다(그 전에도 값만 맞으면 죽을 수 있었다). 폭 0 클립은 이제 오류 대신 건너뛰고, 다시 맞추는 효과도 굳혔다. 120초·15클립 실제 모양을 처음 열 때마다 시험한다(작업자 보고: 4개 화면 크기 240회 콜드 오픈 0건).
2. **영상 길이가 칸 폭보다 늦게 정해질 때 처음 배율이 안 맞음(`3d104a221`로 고침).**
   다시 맞추는 기준이 `폭` 하나였다. 칸 폭이 먼저 들어오고 영상 길이가 나중에 들어오면(`/projects`에서 눌러 들어가는 길) 길이가 바뀌어도 다시 안 맞췄다. 기준을 `(폭, 길이)` 쌍으로 바꿨다. 같은 커밋에서 **겹친 클립을 누르면 누른 쪽(맨 위 클립)이 골라진다.**

참고: 내장 브라우저는 그림이 한 번도 그려지지 않으면 크기 관찰·프레임이 멈춘다(2026-09-04 메모). 그래서 이번 처음 열기 측정은 **열고 작게 한 번 화면을 찍은 뒤** 쟀다. 실제 브라우저와 같은 조건이라고 보면 안 되지만, 찍지 않고 잰 값(1358px, 잘림)은 같은 코드가 그림이 없는 환경에서 멈춘 것으로 본다(추정 — 사람 눈으로 확인하지 못했다).

- **CapCut은 투명 모션을 못 받는다**(겹 webm의 알파).
- **위쪽 스크롤 동기화**(세로 스크롤)는 안 만들었다. 머리 칸 폭은 9rem(계획 7.5rem) — 밀도는 계획 I 소관.

## 4. 기본 모드에서 사용자가 보게 되는 변화

1. **CapCut 내보내기가 뺀 장면의 자막을 싣지 않는다.** 전에는 구멍 위에 뺀 장면의 말이 되살아났다(완성본 자막 경로와 같아짐). 계획서 파일 목록 밖의 변경(`pycapcut_adapter` 쪽)이라 눈에 띄게 적는다.
2. **장면을 빼면 구멍이 `뺀 장면 자리`로 보이고 구멍 개수에 센다**(머리 `빈 구간 1개`). 이어 붙이는 모드는 준비만 돼 있고 꺼져 있다.
3. **뺀 장면을 되살릴 자리가 이웃에게 막혀 있으면** 쉬운 말로 알린다: "옆 장면이 이 자리를 쓰고 있어요. 옆 장면을 줄이거나 되돌리기를 눌러 주세요."(이 막힘은 이어 붙이는 모드에서만 생긴다.)
4. 화면이 세션을 읽을 때 `?include_history=false`를 붙인다(서버 기본값은 그대로 `true`라 다른 호출은 안 바뀐다).
5. 처음 열 때 배율이 칸 폭에 맞고, 클립 몸통을 끌면 옮기기, 가장자리 띠를 끌면 자르기, 끌 때 옆 클립에 붙는다. 눈금 간격이 확대에 따라 바뀐다.

## 5. 알려진 결함·위험 (고치지 않았다)

- **트랙 `잠금`은 실행 취소 단계가 아니다.** 잠근 직후 `실행 취소`를 누르면 잠금이 아니라 **서버의 더 오래된 편집이 되돌려진다.** 점검 중 실제로 그래서 **대표님 프로젝트 0907 장면 1의 B-roll이 바뀌었다**: 지금 `asset_f33e61007e2d`(warm 필터)이고 원래는 `asset_f0c0ca611b44`(3초 영상, 원래 소리 켬, 필터 없음, `expected_content_sha256 ecd8b111…2f84`)다. **대표님이 다시 적용하거나 복구를 승인해 주셔야 한다**(점검 도구 권한이 같은 값을 API로 되돌리는 것을 막았다). 0907의 `다시 실행` 칸에도 점검 편집 하나가 남아 있다(내레이션 음소거).
- **742e1924에서 겹친 영상 클립(11·12·13번째)**: 이 프로젝트는 장면 1의 영상이 90~102초에 놓여 있어 84–96, 96–105.58 클립과 겹친다(오염된 데이터). 이 겹친 구간을 누르면 맨 위 클립이 골라지고(11번째는 12번째가, 12–13이 겹친 곳은 13번째가 잡힌다), **오른쪽 편집 항목·캡션 선택이 눌린 클립이 아니라 이전 장면에 남는 경우가 있다**(11번째 클릭 때 108–120초 / 105.58–108초가 그대로). 겹치지 않은 영상 12/15와 캡션 15/15는 맞다. **이 겹침 데이터 단서는 받아들이기로 했다**(코디네이터 지시). 이 상태에서 한 번 이렇게 클릭하면 같은 화면에서 캡션 클릭도 한동안 이전 장면에 남았고 새로고침하니 풀렸다.
- 점검 때 남긴 시험 항목: 자료실 모션 항목(점검 보고서 목록), 742 프로젝트 자료 `검증-막대`(`asset_47c65188b00f`). 742의 되돌리기(redo) 칸이 점검 편집으로 2칸→1칸이 됐다(이전 점검에서 남긴 오버레이 편집 2개가 사라짐).
- **리플(당겨 붙이기)은 켜지 않았다.** 켜기 전에 풀 조건 다섯(`task-12-report.md`): ① 자동 자막이 원본 시각이 아니라 `source_slices` 기준이어야 함 ② 리플 배속이 배치(override)를 안 옮김 ③ 겹친 배치(뺀 자리 안/걸친 것)가 뺀 자리에 남음 ④ 뺀 자리에 B-roll을 덮어도 구멍으로 셈 ⑤ 유진 화면의 `segment_restore_overlaps_neighbour` 설명.
- **데이터 수리 도구(`scripts/repair_session_projection_timelines.py`)는 있지만 `--apply`를 한 번도 안 돌렸다.** 실제 데이터에 돌리기 전에 보안·데이터 검토와 대표님 승인이 필요하다(`--undo`가 기록의 경로를 믿는 점도 검토 대상). 0907은 아직 오염 클립 15개를 안고 있지만 지금은 해롭지 않다.
- 보류 중 사소한 것: 고른 클립이 좁을 때 Shift·Ctrl 누르기가 안 먹음, 끌기 끝 클릭 무시가 50ms 시간 기준, 정지 화면을 `seeked`마다 JPEG로 인코딩, 미리보기 지켜보기가 계획과 달리 상한 3초·240회(약 12분), 여러 개 고른 클립에 테두리가 안 보임.
