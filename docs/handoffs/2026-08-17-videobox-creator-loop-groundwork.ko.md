## 만든 것

### T4 — 완성본이 어땠는지 기록에 남는다 (`42cd0ad25`)

렌더마다 `duration_sec · scene_count · average_scene_sec · caption_count ·
caption_overlap_count · width · height · has_sound`가 쌓인다. 출력 화면에서
**"이 완성본 좋아요 / 아쉬워요"**를 누르면 그 판단이 함께 남는다.

**기계가 잰 것(`quality_facts`)과 사람이 정한 것(`owner_verdict`)을 갈라서 저장한다.**
나중에 무엇을 근거로 배웠는지 구분해야 한다. 판단하지 않은 것은 `null`이지 나쁨이 아니다.
낡은 완성본에는 평가 단추가 뜨지 않는다 — 어느 편집본에 대한 판단인지 모르면 라벨이 쓸모없다.

### T1 — 포맷 템플릿 (`7d2e05602`, `778de063f`, `4fd027b12`)

마음에 든 완성본의 **만드는 방식**을 이름 붙여 저장하고 다음 영상에서 쓴다.
저장은 출력 화면(완성본을 판단하는 순간), 불러오기는 편집기의 자막 프리셋 옆.

- **템플릿은 내용을 나르지 않는다.** 장면·대본·촬영본은 그 영상의 것이다.
- **크기·음악은 보여만 주고 적용하지 않는다.** 가로 포맷을 세로 영상에 눌렀다가
  나중에 알게 하지 않는다.
- 적용은 **기존 자막 스타일 변경 경로**를 지난다. 저장소를 따로 부르면 같은 변경이
  두 경로를 갖는다.

**여기서 크게 틀렸다가 고쳤다.** 편집본 구조를 짐작으로 코딩했더니 **아무것도 안 담긴
포맷이 저장됐다.** 실제로는 음악이 `music_override.asset_id`, 자막 스타일은 장면이
들고 있을 수 있고, **화면 크기는 편집본이 아니라 타임라인에 있다.** 셋 다 틀렸다.
실제 앱에서 눌러 보고서야 알았다.

### 목소리 엔진 교체 — 라이선스 때문 (`778de063f`)

XTTS-v2는 **Coqui CPML, 비상업용**이라 매출과 충돌한다.
**Chatterbox Multilingual(Resemble AI, MIT, 한국어)**로 바꿨다. XTTS는 남겨 뒀다.
잘못된 엔진 이름은 렌더 도중이 아니라 **설정할 때** 걸린다.

**아직 한 번도 실제로 돌려 본 적이 없다.** 자세히는 memory
`videobox-voice-cloning-engine-licence`.

### 내레이션이 재료가 됐다 (`4e2a4d98c`, `4f33ee427`, `687417644`)

자산 단계 탭이 `내 영상 · 음악 · 효과음 · **내레이션** · 가져오기`가 됐다.

목소리 작업은 **장면을 고르고 내레이션을 만들고 들어보고 승인하는 편집 작업**인데
설정 서랍에 있었다. 그래서 자산 단계에 사람 목소리만 빠져 있었고, **첫 완성본이
-91dB로 나간 것도 같은 뿌리**다. 설정은 이제 길만 알려 준다(옛 주소는 살아 있다).

그리고 **내레이션은 넣을 수만 있고 볼 수가 없었다.** 조회 API 자체가 없었고 넣는 길도
프로젝트 만들 때 경로 타이핑 하나뿐이었다. 조회·업로드를 만들고 **재생기와 함께** 붙였다 —
목록만으로는 파일이 비었는지 모른다.

**배포하고 열어 보니 이 프로젝트의 내레이션 이름이 `asset_silence_*`였다.**
무음 완성본을 만든 그 파일이 이제 자산 단계에서 보인다.

### owner-ready 거짓 실패 수정 (`687417644`)

**원인은 타임아웃이 아니었다.** nginx가 API보다 먼저 뜨고 그 사이 `/health`가 502를
돌려주는데, 프로브가 그걸 실패로 보고 **대기 루프를 즉시 빠져나왔다.** 실측: 1~3초 502,
4초부터 200. 타임아웃을 300초로 줘도 실패했을 것이다.

이제 502·503·504는 기다린다. **실제 재빌드에서 `[PASS]`가 뜬다 — 이제 FAIL이 보이면
진짜 실패다.**

## 화면을 캡처해서 훑었다 — 시각 결함 3건 (`ac8a49e6`, `46bf4e50`, `197950b0`)

owner가 "대시보드는 캡처해서 확인해 보라"고 해서 12개 화면을 전부 찍었다.
**자동 검사는 전부 초록인데 못 볼 수준인 화면이 있었다.**

| 화면 | 무엇이 | 왜 안 잡혔나 |
|---|---|---|
| 자산 › 내레이션 | 목소리 화면 전체가 **한 줄에 눌려** 제목 글자가 세로로 한 자씩 쌓임 | 글자·제목 단계·넘침 다 정상이었다 |
| 자산 › 내레이션 | 입력·선택 상자가 1104px까지 늘어남 | 넘치지는 않으니 아무 검사도 안 걸린다 |
| 검토와 출력 | `검토 다시 열기`가 64rem을 가로질러 **띠처럼** 보임 | 〃 |
| 편집 | 제목 2개가 **대비 1.04** — DOM에 있는데 화면에 없음 | 〃 |

**원인이 두 종류였다.**

1. **설정 화면용 스타일을 그대로 들고 옴.** 목소리 화면 루트가 `vb-setting-control`
   (설정의 *한 줄짜리 행*, `display:flex; align-items:center`)이었다. 폭도
   `.vb-settings`의 42rem에 기대고 있었는데 자산 화면은 1440px이다.
2. **grid가 자식을 늘린다.** `.vb-review-page` 등 grid 루트에서 단추 하나가 열 폭을
   가로챈다. 직계 단추만 `justify-self:start`로 되돌렸다 — 장면 목록 같은 블록은
   폭을 그대로 써야 하므로 전체에 걸지 않았다.

**고치지 않기로 한 것도 기록한다.** 기획 화면의 832px 단추는 바로 위 입력과 같은 폭이라
"이 입력의 제출"로 읽히고, 자산 카드의 640px 단추는 카드 폭이다. 편집기 미리보기의
나머지 글자 3.49는 보조 설명에 쓰는 의도된 흐린 톤이다. **넓다고·흐리다고 다 고치면
위계가 사라진다.**

**Tailwind `max-w-2xl`이 적용되지 않았다.** 같은 클래스 문자열의 `grid`·`justify-items`는
먹었는데 이것만 `maxWidth: none`이었다. 원인을 더 파지 않고 저장소가 원래 쓰던 CSS
방식(`.vb-voice-workspace`)으로 잡았다. **다음에 Tailwind 폭 유틸리티가 안 먹으면
이 사례를 떠올려라.**
