# 전환 잔여 버그 + 자가 진단 시스템 구축 (2026-09-20)

이 문서가 `2026-09-20-full-feature-qa-sweep.ko.md`를 대체한다. 그 문서에 적힌
"이번 세션에서 못 다한 것" 세 항목 중 둘(전환, 미디어 검색 태그)을 이번에 마저
봤고, 그 과정에서 대표님이 요청한 자가 진단 시스템(스키마 이탈 잠금 + 인계 문서
갱신 훅 + 정기 실행 패키지)을 새로 만들었다.

## 이번 세션에서 고친 것 (main에 병합·푸시 완료)

1. **프로젝트 내 미디어 검색이 vision 분석 태그를 못 찾던 문제** (`499304be7` →
   `b9177c757` 병합) — 이전 인계 문서의 "남겨둔 것" 항목. 원인은 `complete_media_analysis()`가
   `review_media_analysis()`와 달리 분석 성공 태그를 `asset.metadata.tags`에 다시
   안 쓰던 것 — 배선 누락이었다(의도된 설계 아님). `_merge_analysis_tags_onto_asset()`
   헬퍼를 공유해서 고쳤다.
2. **전환 탭이 `session.segments` 저장 순서로 "앞 장면 있음"을 잘못 판단** (`bac6e9c47`
   → `501601a52` 병합) — 장면을 나눈 뒤 시간순 두 번째 장면을 골라도 배열 위치상
   앞이면 "첫 장면"으로 잘못 떴다. `view.tracks`(narration, startSec순)에서
   `orderedSegmentIds`를 새로 만들고 `indexOf`로 판단하도록 고침.
3. **HTTP 응답 모델이 `owning_segment_id`를 조용히 잘라내던 것** (`14161ccf1`) — 위
   2번을 고치고도 화면에서 여전히 재현돼서 더 파보니, `EditorCaptionResponse`에
   `owning_segment_id` 필드가 아예 없어서 Pydantic 기본 동작(`extra="ignore"`)이
   HTTP 응답에서 그 필드를 통째로 버리고 있었다. 내부 dict엔 있는데 화면이 받는
   JSON엔 없었던 것 — 그래서 2번 수정 이후에도 화면은 여전히 낡은 값을 썼다.
   필드를 추가하고, **실제 Pydantic 모델을 통과시켜서** 검증하는 시험
   (`test_owning_segment_id_survives_the_actual_http_response_model`)을 추가했다
   (원래 있던 시험은 raw dict만 검사해서 이 구멍을 못 잡았었다).
4. **전환 탭이 장면을 고른 직후 미리보기의 낡은 재생 위치로 되돌아가던 문제**
   (`99689f6b7` → `3418373da` 병합) — 클립을 클릭해 선택한 직후 `<video>` 요소가
   그 전 재생 위치의 `timeupdate` 신호를 뒤늦게 흘려서 방금 만든 선택을 덮어쓰고
   있었다. 프로그램적 seek 직전 재생 위치를 기록해 두고, 그 값과 일치하는 낡은
   `timeupdate`는 무시하도록 고침.

5. **[이어서 실측 확인·수정 완료] 리비전이 바뀌면 분할된 캡션 선택이 조용히
   첫 장면으로 되돌아가던 문제** (`fb810658`) — 위 4번(타임업데이트 레이스)까지
   고치고도 브라우저에서 계속 재현되던 **네 번째 원인**을 이번에 찾았다.
   분할된 캡션은 `owningSegmentId`로 골라지는데(`TimelineDock.selectClip`),
   같은 경로에서 `view.expectedRevision`만 바뀌는 재검증이 오면
   `EditorWorkbench.tsx`가 "아직 존재하는 선택인지" 검사하는 집합
   (`segmentIds`, 306~309행)이 `segmentId`만 모아서 `owningSegmentId`를 못
   찾고 선택을 버렸다 — 화면 요소(`<video>`) 유무와 무관하게, 패널 전환이
   배경 재검증을 유발할 때마다 재현된 이유가 이것이다. `segmentIds` 집합에
   `owningSegmentId`도 넣는 한 줄로 고치고 RED→GREEN 테스트로 잠갔다.

**브라우저 재검증 결과 (컨테이너 재빌드 후, 이 세션에서 실제로 확인함) — 최종 완료:**
캡션 2(2.5초)를 고른 뒤 전환 탭을 열어도 재생 위치가 더 이상 0초로 안
되돌아간다 — 5번 수정 전에는 매번 0초로 리셋됐다. 처음 쓴 테스트 프로젝트
(`10-06-da081c96`)는 내레이션 트랙이 실제로 분할된 적이 없어(캡션 2·영상 2가
세션 단위로는 여전히 같은 장면 하나에 얹힌 배치라서) `hasPrevious`의 "있음"
판정까지는 그걸로 못 봤는데, **이어서 대본 붙여넣기 → 무음 초안(`01-52-31dcbcec`,
2문장 → 2장면)으로 새 프로젝트를 만들어 진짜 두 장면(0~5초, 5~10초)으로
끝까지 확인했다.** 결과: 1번째 장면(0초)에서 전환 탭을 열면
"첫 장면에는 넘어올 앞 장면이 없어요"(맞음), 2번째 장면(5초)에서 열면
실제 전환 목록(바로 넘기기·서서히 겹치기·검게 저물기 등)이 정상적으로
뜬다. **전환 탭 잔여 버그, 완전히 해결·검증 완료.**

## 새로 만든 자가 진단 시스템

대표님 지시("자체 진단 검증 시스템을 만드는건 어때" → "자가진단 부족한거 다
추가해서 정기적으로 돌리자")에 따라 세 가지를 만들었다.

1. **응답 모델 스키마 이탈 방지** (`4649a8892`, `f84d5c29b`) — `owning_segment_id`
   사고의 재발 방지. Editor* 응답 모델 12개를 `extra="forbid"`로 잠가서
   "모델에 없는 필드는 조용히 버려짐"이 아니라 "그 자리에서 검증 에러"가 나게
   했다. 나머지 ~97개 모델은 한 번에 다 잠그면 검증 안 된 위험이라(레거시
   TimelineClipResponse 등은 실제로 초과 필드를 의도적으로 통과시킨다 — 시도해서
   `test_atomic_draft_bundle.py` 다수 실패로 확인 후 되돌림), **기준선을
   ratchet 테스트로 고정**해서 앞으로 안 늘어나게만 막았다
   (`tests/test_response_model_extra_forbid_ratchet.py`).
2. **인계 문서 최신화 리마인더 훅** (`07a625dfa`) — `scripts/guard_router.py`의
   Stop 훅에 `needs_handoff_reminder()`를 추가. 제품 코드를 고쳤는데
   `docs/handoffs/`를 안 건드린 세션이면 비차단 알림을 띄운다. **이 문서 자체가
   이 훅이 지키려는 규칙을 따른 결과다.**
3. **정기 자가 진단 패키지** (`4e8c30d4` + 예약 작업 `videobox-self-diagnostics`) —
   `scripts/guard_router.py --all`을 추가해 바뀐 파일과 무관하게 등록된 가드
   15개 전부를 돈다(약 12~13분, `owner-ready-script`가 8분으로 가장 느림).
   매일 새벽 4시 9분에 이걸 돌리고 전체 백엔드 pytest까지 합쳐 한국어로
   보고하는 예약 작업을 등록했다. **이 작업은 점검 전용이라 스스로 코드를
   고치지 않고 결과만 보고하도록 프롬프트에 명시했다.**

전환 배열 순서 회귀도 소스 검사 시험(`apps/web/.../transitionOrderRegression.test.ts`,
`f84d5c29b`)으로 잠갔다 — `hasPrevious`가 다시 `session.segments` 배열 위치로
재는 코드로 돌아오면 여기서 걸린다.

  이미지에서 다시 확인해 사라진 것을 봤다(위 5번 참고).

## 자가 진단 패키지 실측 결과 (`guard_router.py --all`, 이번이 첫 실행)

15개 가드 중 14개 통과, 1개 실패 — **`editor-e2e`**의
`workbench dock drag has fixed warmup and five-sample local performance evidence`
(대시보드 오른쪽 패널 드래그 성능 시험)가 기준선(2026-07-23 측정, 중앙값
92ms, 허용 한도 +20%)을 초과했다. 단독 재실행 2회 모두 123~136ms로 재현됐다
— 기계 부하 우연(flake)이 아니다.

**이번 세션 변경 때문이 아니다:**
- 이 시험/기준선 파일은 2026-09-10 커밋(`ab5bb1cc4`)이 마지막 변경이고
  이번 세션과 무관하다.
- 이 기계에 현재 도커 컨테이너가 25개 떠 있다(다른 프로젝트 스택 포함) —
  7월 기준선을 잴 때보다 훨씬 무거워졌을 가능성이 크다.

**[해결 완료, `717ff6f6`] 재캘리브레이션했다.** 이 기계에서 25회 측정(5회
독립 실행 x 5샘플: min 90.9, median 107.1, p95 134.8, max 155.8ms)을 모아
median 92→107ms, p95 108→135ms로 다시 쟀다. 코드 회귀가 아니라 기계 환경
드리프트로 판단한 근거(2026-09-10 이후 이 시험/기준선 파일 변경 없음, 현재
도커 컨테이너 25개 상시 실행)를 `capture_intent` 필드에 그대로 남겼다.
재확인 6/6 통과.
