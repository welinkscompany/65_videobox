# 대표를 실제로 막고 있는 것 — 다시 잰 우선순위 (2026-08-23)

이 문서는 **계획서를 중요도 순으로 다시 정렬한 것**이다. 이번 세션에서 실제로 잰
것만 근거로 쓴다. 안 잰 것은 안 잰다고 적었다.

## 0. 한 줄

**기능은 대체로 있다. 대표가 그걸 못 찾고, 시험이 없는 기능을 있다고 말한다.**
이 둘이 지금 가장 비싼 문제다. 캡컷과의 기능 차이는 그다음이다.

## 2. 문제 분석 — 무엇이 실제로 막고 있나

### 2.1 대표가 기능을 못 찾는다 (가장 비쌈)

2026-08-22에 **대표가 직접 말한 막힌 지점**이다: "어떤 버튼을 눌러야 할지
모르겠다." 같은 세션에서 **문구를 키워드 중심으로 바꾸라고 시켰는데 하지 않았다.**

이게 왜 가장 비싼가: 기능을 아무리 더 만들어도 대표가 못 찾으면 없는 것과 같다.
오늘 색감 9개와 배속 버튼을 붙였는데, 그것도 **세부 정보 탭을 열어야** 보인다.

**아직 안 잰 것**: 화면 문구 중 몇 개가 키워드가 아닌 문장인지 세지 않았다.
다음 세션에서 먼저 세라. 모수 없이 "많다"고 적지 않는다(`§10.8`).

### 2.2 시험이 없는 기능을 있다고 말한다

**오늘 하루에 다섯 건.** 전부 시험은 초록불이었고 실제로는 아무 일도 안 했다.

| 무엇이 | 왜 통과했나 |
|---|---|
| 자막 숨기기 | 자막은 트랙이 아니라 **파일 하나로** 넘어간다 |
| 오버레이 숨기기 | 오버레이는 `export_overlays`에 있다 — 셋째 길 |
| 음소거 (4개 레인 중 3개) | `volume`은 B-roll 전용. 나머지는 다른 손잡이를 쓴다 |
| 오타난 키 (`hiden`) | pydantic이 조용히 버리고 200을 돌려줬다 |
| 캡컷 숨김 | **캡컷 가는 길이 둘**인데 화면이 안 쓰는 쪽만 고쳤다 |

**하나의 원인**: 시험 입력을 내가 만들면 **내 가정을 시험하게 된다.**
`test_track_states.py`는 실제 만듦새가 절대 만들지 않는 모양을 손으로 넣고 있었다.

**효과가 있었던 검증**:
- 실제 만듦새(`materialize_editing_session_timeline`)를 지나게 한다
- 켠 것과 끈 것을 **둘 다 만들어 맞대어** 본다
- 실물을 렌더해서 **픽셀을 잰다**

### 2.3 대표에게 화면을 못 보여 준다

**두 세션째 화면 캡처를 못 했다.** 2026-08-22에는 브라우저가 5173 접근을 거부했고,
오늘은 브라우저 창이 화면에 안 떠 있어 캡처가 안 됐다(DOM으로는 확인함).

대표가 "나아졌는지"를 판단하려면 봐야 한다. 내가 "됐다"고 적은 것은 그 판단을
대신하지 못한다.

### 2.4 배속의 뜻이 캡컷과 다르다 (대표 지적, 2026-08-23)

캡컷에서 2배속 = **클립이 짧아져 영상이 줄어든다.**
우리는 장면 길이를 내레이션이 정하므로 2배속 = **그 시간 동안 원본을 두 배 빨리 훑는다.**
실측: 2배속을 걸어도 완성본은 25초 그대로였다.

대본 기반 편집에서는 우리 쪽이 맞다. 다만 **숏폼에서 "빨리 감아 짧게"** 를
기대하면 어긋난다. 대표가 숏폼을 이유로 물으셨다.

## 3. 중요도 순 계획

### P0 — 대표가 못 쓰는 것을 없앤다

**P0-1. 화면 캡처를 되살려 대표에게 보여 준다.**
이게 안 되면 나머지 P0의 결과를 대표가 확인할 수 없다. 그래서 첫째다.
- 브라우저 창을 실제로 띄운 상태에서 `computer{action:"screenshot"}`
- 안 되면 컨테이너 안에서 headless 캡처로 우회
- **막히면 그 사실부터 보고하라.** 두 세션째 조용히 못 하고 넘어갔다

**P0-2. 화면 문구를 키워드 중심으로.**
대표가 2026-08-22에 시켰고 아직 안 했다. 대표의 실제 막힘과 직접 연결된다.
- 먼저 **센다**: 문장형 문구가 몇 개인지, 어느 화면인지
- `§10.13` creator-language 규정 안에서 바꾼다
- 승인된 색·배치는 건드리지 않는다

**P0-3. 오늘 만든 것을 대표가 실제로 찾을 수 있는지 본다.**
색감 9개와 배속 버튼은 `세부 정보` 탭 안에 있다. 캡컷은 클립을 고르면 바로 보인다.
- 대표가 클립 하나 골라 색감을 거는 데 몇 번 눌러야 하는지 세라
- 캡컷과 차이가 크면 자리를 옮긴다

### P1 — 같은 실패를 다시 내지 않는다

**P1-1. 기존 시험 중 "제 가정을 확인하는 것"을 찾아낸다.**
오늘 다섯 건이 나온 자리는 우연이 아니다. 같은 모양이 더 있다.
- 손으로 만든 타임라인을 쓰는 시험을 전부 찾는다
- 실제 만듦새를 지나게 바꾼다
- **한 번에 다 하지 말고**, 렌더에 닿는 것부터

**P1-2. 숏폼 배속 — "빨리 감아 짧게"를 만들지 결정받는다.**
만들기 전에 대표께 물어라. 내레이션 길이를 줄이는 일이라 **대본·음성까지 닿는다.**
계획서 §2.1의 경계에 걸리는지 먼저 확인할 것.

### P2 — 열려 있는 것

**P2-1. 얼굴 LoRA 닮은 정도 확인** (2026-08-21부터 열림)
학습은 됐는데 **닮았는지 아무도 안 봤다.** 시간·닮은 정도 표를 만들어라.

**P2-2. 부르는 화면이 없는 백엔드 22개**
오늘 잼: `api.ts` 메서드 196개 중 22개가 화면 코드에 이름조차 없다.
- 2026-08-07: 144개 중 37개 (25.7%)
- 2026-08-09: 147개 중 31개 (21.1%)
- 2026-08-23: 196개 중 22개 (11.2%)
줄고 있다. **급하지 않다.** 다만 새 백엔드를 만들 때 부르는 화면을 같이 만들어야
이 숫자가 안 는다.

### 일부러 안 하는 것

- **캡컷 효과·필터·스티커 탭**: 캡컷 서버에서 받아 두는 자원이라 우리 렌더러가
  그 이름으로 아무것도 못 그린다. 흉내 내면 빈 탭이 생긴다(`§2.1`).
- **전문 색보정·곡선 변속·LUT**: 계획서 §2.1 범위 밖.

## 4. 이번 세션에 배운 함정

**1. `-Rebuild` 없이 재시작하면 옛 화면이 나온다.**
`scripts/owner-ready.ps1 -Mode Start`만 하면 이미지를 다시 안 만든다. `/app`은
이미지에 박혀 있어서 worktree를 고쳐도 화면은 그대로다. **결함으로 오진할 뻔했다.**
```powershell
./scripts/owner-ready.ps1 -Mode Start -Rebuild -WithYujinMemory
```
그리고 재빌드한 뒤에도 **브라우저가 옛 `index.html`을 캐시**한다. 주소에 아무
질의문자를 붙여 다시 열어라.

**2. 짝을 이룬 자리는 셋일 수도 있다.**
B-roll 조각을 만드는 곳이 둘인 줄 알고 가드를 썼는데 셋이었다. 세 번째는 검은
여백이라 색감을 얹으면 **안 되는** 자리였다. 가드가 찾아냈다.

**3. 시험이 낡은 예시를 붙들고 있으면 그건 시험이 일한 것이다.**
`sepia`를 "모르는 값" 예시로 쓰던 시험이, `sepia`를 실제로 만들자 붉어졌다.
시험을 고치는 게 맞다 — 다만 **왜 붉어졌는지 보고** 고쳐라.

**4. 캡컷 필터 이름표는 캡컷 서버 자원이다.**
`pycapcut`의 `FilterType`에 454개가 있지만 그건 이름표일 뿐 우리 ffmpeg 그림과
같지 않다. 옮기되 **다르다는 사실을 화면에 적었다.**
