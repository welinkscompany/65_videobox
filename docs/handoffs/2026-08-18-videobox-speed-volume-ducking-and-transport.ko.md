## 이번 세션에 닫은 것

캡컷 대비 "기능 목록"이 아니라 **배선**을 훑어서 나온 셋이다.

| | 무엇 | 어떤 종류의 구멍이었나 |
|---|---|---|
| **1** | B-roll `재생 속도`·`소리 크기`가 실제 영상에 반영된다 | 화면에 있는데 **결과에 닿지 않았다** |
| **2** | `말할 때 배경 음악 낮추기` 토글 | 백엔드는 되는데 **부를 자리가 없었다** |
| **3** | 스페이스 전역 재생, 타임라인 `전체` 보기 | 자리를 타던 조작 |

## 1번 — 기능이 없는 것보다 나빴다

inspector에 `재생 속도`(0.25~4)와 `소리 크기`(0~2) 입력이 **처음부터 있었고
저장도 성공했다.** 그런데 `normalize_media_controls()`가 broll 경로에서 두 값을
버렸고, 렌더러에는 해당 필터가 없었다. API 응답 모델에는 필드가 살아 있어서
"연결돼 있다"고 착각하기 딱 좋았다.

고친 곳이 네 군데다. **한 군데만 고치면 안 된다:**

1. `media_controls.py` — 값을 지키고, 화면 입력과 **같은 범위**로 거절한다.
2. `composition_plan.py` — 배속은 원본을 얼마나 먹는지를 바꾼다. 2배속으로 4초를
   채우려면 원본 8초다. "원본이 모자라다"는 판정도 화면 시간으로 재야 0.5배속
   클립을 잘못 막지 않는다.
3. `ffmpeg_final_renderer.py` — **두 경로가 있다.** `build_plan_filter_graph`는
   미리보기 쪽이고, 완성본 MP4는 `_extract_segment`로 나간다. 그래프만 고치고
   다 됐다고 할 뻔했다.
4. `pycapcut_adapter.py` — 캡컷 초안도 같은 배속·음량을 싣는다. 안 하면 캡컷에서
   열었을 때 다른 영상이 된다.

**소리는 `atempo`를 나눠서 태운다.** 한 번에 0.5~2.0배만 받으므로 4배를 그대로
주면 ffmpeg가 필터를 거절하고 **렌더가 통째로 실패한다.**

## 2번 — 사이드체인은 처음부터 돌고 있었다

`ffmpeg_final_renderer`가 `sidechaincompress`로 내레이션 밑에서 음악을 낮추는
일을 이미 하고 있었다. API 필드도, 프런트 커맨드 포트의 "숨은 ducking 값 보존"도
있었다. **켜고 끄는 자리만 화면에 없었다.**

- **배경 음악에만** 붙였다. 렌더러가 bgm에만 사이드체인을 걸기 때문이다 --
  효과음에 스위치를 주면 눌러도 아무 일이 없는 단추가 된다.
- 문구는 `덕킹`·`사이드체인` 대신 **무슨 일이 일어나는지**로 적었다(§10.13).

## 3번 — 자리를 타던 조작 둘

- **스페이스**: 미리보기 판에 포커스가 있을 때만 들었다. 타임라인을 만지다
  누르면 아무 일도 없었다. 플레이어를 가진 `PreviewStage`가 직접 window에서
  듣는다 -- 소유자에게 올리면 재생 상태가 두 군데 생긴다. 글 쓰는 중·단추 위에서는
  비켜선다(거기서 가로채면 접근성이 깨진다).
- **`전체` 단추**: 축소를 열 번 누르는 대신 한 번에 처음으로. 확대와 **같은
  reducer**를 타므로 배율 계산이 두 벌이 되지 않는다.

## 이번에 배운 것

- **`_extract_segment`가 완성본 경로다.** 그래프 테스트가 초록인데 실제 mp4는
  안 바뀌어 있었다. 색이 1초마다 바뀌는 원본을 만들어 **나온 파일의 프레임을
  읽어서** 알았다.
- **한 시각을 찍어 비교하지 마라.** 처음에 0.5초 한 점을 찍었는데 하필 색 경계라
  "배속이 안 걸렸다"고 오판했다. `setpts` 뒤 `-r`은 경계를 한두 프레임 민다.
  **프레임 순서**를 보면 그 흔들림에 흔들리지 않는다.
- **native-control 단추를 새로 만들면 `task22-parity-owners.test.ts` allowlist에
  등록해야 한다.** 이번에도 `timeline-fit`이 걸렸다. 체크박스는 소유 컴포넌트
  `Input type="checkbox"`를 쓰면 애초에 안 걸린다(`CreationInterview`가 선례).
- **성능 게이트는 단독으로 재라.** `release-gates`의 dock drag가 중간값 115ms로
  한 번 깨졌는데, 그때 전체 vitest와 컨테이너 재빌드를 같이 돌리고 있었다.
  단독으로 다시 재니 104ms로 통과다. 부하 중 측정을 회귀 근거로 쓰지 마라.

## 검증

- 백엔드 99개 통과(신규 16개 포함, 실제 MP4 색 검증 포함)
- 웹 단위 1,069개 전부 통과, `tsc --noEmit` 깨끗
- e2e 48개 통과(성능 게이트는 단독 재실행에서 통과)
- **컨테이너 재빌드 후 실제 화면에서 확인:** 배속 2배 저장→서버 왕복 유지,
  덕킹 토글 저장→유지, `전체` 단추(확대 156.25 → 전체 56.95), 타임라인에 포커스를
  둔 채 스페이스로 재생·정지 토글.

## 남은 사람 확인

- **미리보기 전체화면 실제 진입**(앞 세션에서 넘어온 것). 브라우저가 실제 마우스
  클릭에서만 허용해서 자동 확인으로는 단추 렌더·상태 동기화까지만 봤다.
- **배속을 실제로 걸고 완성본을 뽑아 눈으로 보기.** 자동 검증은 색 순서로 했고,
  사람 눈의 "빠르기가 자연스러운가"는 여전히 사람 몫이다.
