# 처음 쓰는 사람처럼 밟아 본 결과 — owner 말이 맞았다

- 점검일: 2026-08-17
- 계기: owner — *"프로그램 자체가 작동하는 법도 모르겠고, 인터페이스도 너무 헷갈리고,
  작동도 안 하고, 완전 총체적 문제네."*
- 방법: API를 부르지 않고 **화면만** 써서 새 프로젝트를 만들고 편집까지 가 봤다.

## 그동안 왜 못 봤나

나는 오늘 하루 **API 호출과 캡처로만** 확인했다. 처음 열어서 따라가 본 적이 없다.
그래서 "전부 초록"이라고 보고하는 동안 owner는 시작조차 못 하고 있었다.

## 가장 큰 것 — 편집기가 집이 아니라 마법사의 3번째 칸이다

새 프로젝트를 만들면 `/create`(기획)로 간다. **편집 화면에 직접 들어가면 이렇게 뜬다.**

```
먼저 영상 초안을 만들어 주세요.  [새 영상 만들기]
```

즉 **기획을 통과하지 못하면 편집기를 열 수 없다.** 영상 편집 프로그램인데
편집기가 잠겨 있고, 설문 같은 단계를 먼저 밟아야 한다.

owner가 "캡컷처럼 만들어야겠다"고 한 것이 이 지점이다. **캡컷은 열면 바로 편집판이다.**

**다행인 것:** 편집기 자체는 이미 캡컷 배치다 — 위 툴바, 가운데 미리보기, 아래 타임라인,
오른쪽 패널. **뜯어고칠 대상은 편집기가 아니라 그것을 감싼 마법사다.**

## 첫 화면이 앱처럼 안 보이는 이유 — 껍데기 밖이다

`/projects`(첫 화면)에는 **사이드바가 없다.** 프로젝트를 하나 만들고 나서야 나타난다.
그래서 처음 여는 사람에게는 프로그램이 아니라 **웹페이지 한 장**으로 보인다.

첫 화면에서 확인한 것들:

- **새 프로젝트 입력이 페이지 맨 아래.** 카드 6개를 지나 스크롤해야 나오고,
  대화상자가 아니라 라벨+입력+단추가 날것으로 붙어 있다.
- **링크가 파란색 밑줄.** `계속 만들기`·`완성본 보기`·`검토 문제 해결`.
  승인된 팔레트(주황 `#C2410C`)와 무관하다.
- **날짜가 기계 형식 그대로.** `2026-08-17T06:13:40.438824+00:00` — 카드 폭에서
  줄바꿈돼 `+00:0 0`으로 잘린다.
- **상태에 내부 단계 이름이 그대로.** `기획 · 준비됨`, `검토 · 막힘`.
- 썸네일이 있는 카드와 없는 카드가 섞여 **높이가 어긋난다.**

## 그 밖에 관찰된 것

- 새 프로젝트에서 편집 화면을 열면 `editing-sessions/latest`가 **404**를 내고
  콘솔 오류가 남는다. 화면은 안내로 처리하지만, 정상 흐름에서 404를 내는 것은
  나중에 진짜 오류를 가린다.
- **자산 화면에 분류가 없다.** 종류 탭은 있지만 그 안은 그냥 나열이다 —
  폴더도, 정렬도, 즐겨찾기 묶음도 없다. owner 지적대로다.

## 결론 — 웹이라서가 아니다

owner가 "웹이라서 복잡한 것 같다"고 했는데, **위 문제 중 웹 때문인 것은 없다.**
데스크톱으로 다시 만들어도 마법사는 마법사고, 첫 화면은 여전히 껍데기 밖이고,
날짜는 여전히 기계 형식이다.

**웹이라서 생기는 진짜 불편은 따로 있다** — 도커를 띄우고 주소를 쳐야 켜지는 것,
파일 경로를 타이핑해야 하는 것. 그건 **데스크톱 껍데기**로 풀린다(안쪽 화면은 그대로).

## 고칠 순서 (제안)

1. **편집기를 집으로.** 프로젝트를 열면 편집 화면이 먼저. 기획·자산·검토는
   단계가 아니라 **패널·메뉴**로 접어 넣는다. 편집기는 이미 그 모양이라 새로 안 만든다.
2. **첫 화면을 껍데기 안으로.** 사이드바가 처음부터 보이게. 새 프로젝트는 대화상자로.
3. **읽을 수 있는 표기.** 날짜·상태를 사람 말로.
4. **자산 분류.** 종류 안에서 최근·즐겨찾기·검색.
5. **데스크톱 껍데기.** 아이콘 하나로 켜지고 파일을 그냥 고르게.

## 나중에 남들도 쓰게 할 계획 (owner 확인, 2026-08-17)

owner가 **"나중에 남들도 쓰게 할 계획"**이라고 답했다. 지금 저장소는 1인용·내 PC
전용 전제이고 `CLAUDE.md` §6이 `SaaS, billing, multi-user 인증`을 승인 항목으로 둔다.

**지금 만들지는 않는다.** 다만 위 재배치를 할 때 **나중에 계정·권한·데이터 분리를
넣을 자리를 막지 않도록** 한다. 특히 프로젝트 목록과 라이브러리가 "이 사람의 것"이라는
개념을 나중에 받을 수 있어야 한다.

# 편집기 점검 — owner: *"컷편집이 되는지도 모르겠다"*

실제로 편집기를 열어 컨트롤을 하나하나 세어 봤다.

## 1. 편집기를 열면 단추가 4개다

```
[툴바] 실행 취소 / 다시 실행 / 자산과 대본 / 유진과 편집 항목
```

**자르기도, 나누기도, 붙이기도, 삭제도 없다.** 영상 편집기를 열었는데 편집하는
단추가 하나도 안 보인다. 캡컷은 열자마자 타임라인 위에 자르기·분할·삭제가 있다.

## 2. 장면을 골라야 3개가 나온다 — 그것도 내부 ID를 달고

```
clip_narration_7568b55139 시작 자르기
clip_narration_7568b55139 끝 자르기
clip_narration_7568b55139 순서 바꾸기
```

**사용자에게 내부 clip ID를 그대로 보여 준다** (`§10.13` 위반). 그리고 여기에도
나누기·붙이기·삭제는 없다.

## 3. 나누기·붙이기는 있는데 `선택 구간 편집` 안에 숨어 있다

기능은 **다 구현돼 있다.** `splitNarration`·`mergeNarration`·`setCutAction`·
`setNarrationBounds`·`reorderNarration`·`setTimelinePlacements` 전부 동작하고
테스트도 있다.

그런데 화면에서 그 자리에 닿으려면 **`선택 구간 편집`이라는 이름의 컨트롤**을
찾아야 한다. `자르기`도 `나누기`도 아닌 이름이라, 찾을 수가 없다.

## 결론

**컷편집 기능이 없는 게 아니라, 부를 수 있는 자리가 없다.**

- 엔진: 자르기·나누기·붙이기·삭제·순서·트림 **전부 있음**
- 화면: 툴바에 편집 단추 **0개**, 장면 선택 시 **3개**, 나머지는 이름으로 못 찾음

owner가 "그냥 막 집어넣은 것 같다"고 한 것이 정확하다. **기능을 만든 순서대로
아무 데나 붙였고, 캡컷처럼 묶어서 보여 준 적이 없다.**

## 캡컷을 기준으로 하면 이렇게 된다

| 캡컷 | 지금 우리 | 할 일 |
|---|---|---|
| 타임라인 위 편집 막대 (분할·삭제·복제·속도) | 없음 | **툴바에 컷 도구를 올린다** |
| 왼쪽 재료 탭 (미디어·오디오·텍스트·효과) | 자산이 **다른 단계**에 있음 | 편집기 왼쪽 패널로 |
| 오른쪽 속성 (선택한 것에 따라 바뀜) | 인스펙터에 섞여 있음 | 유지하되 이름 정리 |
| 클립을 끌어서 자르기 | `시작 자르기` 단추 | 유지 + 이름 정리 |

**우리만의 것**은 `유진과 편집 항목` 하나면 된다. 나머지는 캡컷 배치를 따른다.

## 첫 조각 완료 — 툴바에 컷 도구를 올렸다 (2026-08-17)

```
[전] 실행 취소 / 다시 실행 / 자산과 대본 / 유진과 편집 항목
[후] 실행 취소 / 다시 실행 / 나누기 / 앞과 붙이기 / 빼기 / 자산과 대본 / 유진과 편집 항목
```

`cutToolbar.ts`는 **무엇을 누를 수 있는지만** 정하고, 실제 변경은 이미 있던
`InspectorAction` 경로가 한다 — 같은 편집이 두 경로를 갖지 않게 했다.

**만들다가 되돌린 것 하나.** 처음에는 `빼기`가 뺀 장면에서 `다시 넣기`로 바뀌게 했는데,
실제 앱에서 확인해 보니 **뺀 장면은 타임라인에서 사라져 다시 고를 수가 없었다.**
세션에는 `remove`로 남아 있지만 클립이 없으니 그 단추는 영원히 못 누른다. 지웠다.
되돌리기는 `실행 취소`가, 다시 넣기는 인스펙터의 `유지`가 맡는다.

**실제로 눌러 보고 잡은 것 하나.** 장면을 골랐는데도 `나누기`가 회색이었다. 로직은
맞았다 — 고른 장면이 5~10초인데 재생 위치가 0초였다. 문제는 **화면이 이유를 말해 주지
않는다**는 것이었다. 이유 없이 회색인 단추는 사용자에게 고장으로 읽힌다. 그래서 각
도구가 `hint`를 함께 갖게 하고, 잠긴 단추에도 뜨도록 감싸는 자리에 걸었다(잠긴 단추는
마우스 이벤트를 받지 않아 자기 title을 못 띄운다).

## 그리고 실제로 눌러 봤더니 컷편집이 아예 막혀 있었다

단추를 붙이고 실제로 밟아 보니 **재생 위치가 첫 클릭 자리에 붙박였다.**

```
10% 클릭 → 1.45초   30% 클릭 → 1.45초   50% 클릭 → 1.45초
```

재생 위치가 안 움직이니 `나누기`는 영원히 잠긴 채였다. **컷편집을 부를 자리를
만들었는데도 여전히 쓸 수 없었던 것이다.** 원인은 두 겹이었고, 둘 다 "위치를
서로 되돌려 주는" 같은 모양이었다.

**첫째 — 타임라인과 소유자가 서로를 되돌렸다** (`TimelineDock.tsx`). 타임라인이 위치를
올려보내는 effect와 밖에서 온 위치를 따라가는 effect가 **둘 다 `state.playheadSec`을
보고 있었다.** 내가 위치를 옮기면, 아직 갱신 안 된 옛 `playbackSec`이 나를 도로
끌어당긴다. 고리가 돌다가 옛 자리에서 멈춘다. 고침: 따라가는 쪽은 **밖에서 온 값만**
보게 하고(`deps: [playbackSec]`), 방금 내가 올려보낸 값이 되돌아오면 무시한다.

**둘째 — 미리보기가 자기 구간 밖 재생 위치를 도로 밀어 올렸다** (`preview-stage.tsx:78`).
`선택 구간 미리보기`는 타임라인 일부만 담는데, 재생 위치가 그 밖으로 나가면 자기 구간
안으로 **되돌려 올려보내고** 있었다. 테스트가 이걸 의도된 계약으로 못박고 있었다
(*"returns the effective selected-range position when an external seek is out of range"*).

의도는 이해된다 — 보이는 화면과 알려진 위치를 맞추려던 것이다. 하지만 그러면 **재생
위치가 미리보기 구간의 포로가 된다.** 구분해야 할 것은 이 둘이다.

- 미리보기가 **스스로 알리는** 위치(`timeupdate`) → 올려보내는 게 맞다. 그대로 뒀다.
- 사용자가 **못 보여 주는 자리로 옮긴 것** → 되밀면 안 된다. 이걸 걷어냈다.

대신 말없이 다른 순간을 보여 주지 않도록, 화면과 재생 위치가 갈리면 그 사실을 적는다.
*"이 화면은 타임라인 8.0초의 모습입니다. 재생 위치는 그보다 바깥에 있어 아직 볼 수 없어요."*

**고친 뒤 실제 확인:**

```
10% → 1.45초   30% → 4.36초   50% → 7.28초      (자유롭게 움직인다)
7초에서 나누기 = 누를수있음 → 눌렀더니 내레이션 클립 2개 → 3개
```

**교훈은 이번에도 같다.** 단추를 붙이고 테스트가 초록이어도, **실제로 눌러 보기 전까지는
쓸 수 있는지 알 수 없다.** 컷 도구 단위 테스트는 처음부터 통과하고 있었다 — 막고 있던
것은 그 단추가 읽는 재생 위치가 움직이지 않는다는, 전혀 다른 곳의 사실이었다.

## 캡컷 벤치마킹 다섯 조각 — 실행 결과 (2026-08-17)

### 1. 재생 위치를 눈으로 찾을 수 있게

재생 위치는 **맨 아래 숫자 하나**뿐이었다. 이제 눈금부터 트랙 아래까지 관통하는
세로선이다(승인된 accent `--vb-accent`, 새 색 없음). 클립과 **같은 좌표계**로 놓아
확대하거나 옆으로 밀어도 어긋나지 않는다.

### 2·3. 편집기를 집으로, 첫 화면을 껍데기 안으로

- 프로젝트를 열면 **편집 화면이 먼저** 뜬다. 사이드바 순서도 `편집 · 이야기 · 재료 ·
  확인과 내보내기`로 바꿨다 — 기획은 편집 앞의 관문이 아니라 편집으로 가는 길이다.
- `/projects`가 **앱 껍데기 안**으로 들어왔다. `ProductShell`이 이미 `hasProject`로
  프로젝트 없는 상태를 다루고 있어서 새로 만들지 않고 그것을 썼다.
- 새 프로젝트 입력이 **목록 위**로 올라왔다(예전엔 카드 여섯 개를 지나 맨 아래).
- 편집기 빈 상태 문구가 `먼저 영상 초안을 만들어 주세요`(잠긴 문)에서
  `아직 편집할 영상이 없어요...`(시작하는 자리)로 바뀌고, 갈 곳을 두 개 준다.

**빈 편집판 — owner 지시로 이어서 했다 (2026-08-17).**

편집 세션을 만드는 길이 둘뿐이었고 둘 다 기획을 먼저 통과해야 했다(`timeline_job_id`
또는 `script_asset_id`). 이제 셋째 길이 있다 — `POST .../editing-sessions/blank`.

**완전히 빈 세션은 만들지 않는다.** 장면이 하나도 없으면 그릴 것도, 고를 것도,
나눌 것도 없어서 "편집판이 열렸다"고 할 수 없다. **비어 있는 5초 장면 하나**로 연다.
그 장면은 `review_required`로 표시한다 — 아직 아무것도 안 들어 있으므로 채우기 전에
조용히 완성본으로 나가면 안 된다.

**만들어 놓고 안 열렸다.** 세션만 만들었더니 화면이 `재생 내용을 불러오지 못했어요`만
띄웠다. 편집기는 재생 목록을 만들려고 **짝이 되는 타임라인**을 찾는데 없었던 것이다.
세션과 타임라인을 함께 만들도록 고쳤고, 그 계약을 테스트로 못박았다
(`test_the_editor_can_actually_draw_the_blank_board`). **만드는 것과 열리는 것은
다르다**(§4 완료의 정의) — 이 저장소가 가장 자주 걸리는 자리다.

실제 컨테이너 확인:

```
새 프로젝트 → 편집기 → `빈 편집판으로 시작` 누름
→ 타임라인 열림 · 0-5초 장면 하나
→ 툴바: 실행 취소 / 다시 실행 / 나누기 / 앞과 붙이기 / 빼기 / 자산과 대본 / 유진과 편집 항목
```

### 4. 날짜·상태를 사람 말로

`2026-08-17T06:13:40.438824+00:00` → `2시간 전`. `기획 · 준비됨`(내부 단계 이름) →
`이야기를 정하는 중`. 새 `readableMoment`는 **읽을 수 없으면 아무 말도 하지 않는다** —
틀린 시각을 자신 있게 보여 주는 것보다 낫다. 대표 이미지 유무로 들쭉날쭉하던 카드
높이도 맞췄다.

### 5. 자산 분류

종류 탭 안에 **이름 검색 · 정렬(최근/이름) · 즐겨찾기만 보기**를 넣었다.
**즐겨찾기는 이미 다 있었다** — 백엔드도 단추도 정렬도. 없던 것은 "즐겨찾기만 보기"
하나뿐이라 그것만 얹었다. 프로젝트 전용 영상은 `library_asset_id`가 없어 즐겨찾기를
달 수 없다(일부만 별이 붙는 상태가 되어 넣지 않았다). 거기는 검색·정렬만 된다.

## 그리고 리뷰·갭·역방향 검증에서 나온 것 셋

**갭 검증 — raw clip ID가 아직 화면에 있었다.** `clip_narration_7568b55139 시작 자르기`.
계획서에 §10.13 위반으로 적어 놓고도 안 고쳤던 것이다. 같은 자리에 이미 사람이 읽는
이름(`clipDisplayName`)이 있었다. 이제 `내레이션 1번째 장면, 5초부터 시작 자르기`다.

**역방향 검증 — 한 장면을 골랐는데 두 개가 골라져 있었다.** 클립을 고르면
`onSelectSegment`가 그 클립을 고르는데, **바로 뒤의 seek이 선택을 다시 유도하면서
덮어썼다.** 순서를 뒤집어 고른 클립이 마지막 말이 되게 했다.

**역방향 검증 — 7초를 눌렀는데 5~7초 장면이 골라졌다.** 선택을 **자막에서** 유도하고
있었는데, 장면을 나누고 나면 자막 구간과 장면 구간이 어긋난다. 컷 도구가 다루는
단위는 장면이므로 장면에서 고르게 바꿨다. 다만 **내레이션이 긴 통짜 하나일 때는**
(원본 영상 소리로 만든 초안) 장면이 하나뿐이라 구분이 안 되므로 그때는 자막을 쓴다 —
기존 테스트가 이 경우를 붙잡아 줘서 알았다.

고친 뒤 실제 컨테이너에서:

```
8.5초 눌렀다 → 재생 위치 8.5초 · 7-10 장면이 골라짐 · 나누기 누를수있음
눌렀더니   5-7 | 7-8.5 | 8.5-10 | 10-15     (3개 → 4개)
```

**한 번의 동작으로 컷편집이 된다.** 이게 캡컷이 하는 일이다.

## 남은 것

- **타임라인 패널이 12rem으로 잘려 있다.** 눈금과 트랙이 자체 스크롤 안에 숨는다.
  캡컷은 아래쪽 전체를 타임라인이 쓴다. 다만 편집 작업판 높이는 승인된 시각 결정
  (`2026-07-20`)에 묶여 있어 **재승인 없이 바꾸지 않는다.**
- 데스크톱 껍데기(아이콘 하나로 켜기, 네이티브 파일 고르기).

## 캡컷 대비 다시 세어 본 결과 (2026-08-17)

| 캡컷 | 우리 | |
|---|---|---|
| 열면 바로 편집판 | 프로젝트 열면 편집 화면이 먼저 | 됨 |
| 빈 편집판에서 시작 | `빈 편집판으로 시작` | 됨 |
| 타임라인 위 컷 도구 | 나누기 / 앞과 붙이기 / 빼기 | 됨 |
| 재생 위치 세로선 | 눈금~트랙 관통, 클릭으로 이동 | 됨 |
| 오른쪽 속성 패널 | 인스펙터 | 됨 |
| 실행 취소/다시 실행 | Ctrl+Z / Ctrl+Y | 됨 |
| 클립 끌어서 자르기 | `시작`·`끝` 단추 + 드래그 + 화살표 키 | 부분 |
| 왼쪽 재료 탭 | 자산이 별도 화면(`재료`) | 부분 |
| **단축키** | **Ctrl+Z·Ctrl+Y 둘뿐** | **미흡** |
| **재료 끌어다 놓기** | **저장소에 `onDrop`이 하나도 없다** | **없음** |
| 미리보기 조작 | 재생/정지만 | 미흡 |

**직접 세어 본 것:** `apps/web/src` 전체에 `onDrop`·`draggable`이 **0건**이다. 자산을
넣으려면 별도 화면으로 가서 단추를 눌러야 한다. 캡컷의 핵심 동작이 빠져 있다.

## 그 세 가지도 했다 (2026-08-17, owner 지시)

**① 단축키 — 됐다.** `Ctrl+B` 나누기, `Delete`/`Backspace` 빼기. 무엇을 할 수 있는지는
**툴바가 정한 것을 그대로 쓴다**(`cutShortcuts.ts`) — 다시 계산하면 단추는 잠겼는데
키로는 통하는 일이 생긴다. 실제 확인: `10-15` → `10-12.3 / 12.3-15`.

**② 끌어다 놓기 — 됐다.** 재료 카드를 집어 장면 위에 놓으면 **이미 있는 `적용`
경로를 그대로 탄다**. 같은 편집이 두 경로를 갖지 않게. 고유 드래그 타입을 써서
파일 탐색기에서 끌어온 것은 받지 않는다(받을 것처럼 커서를 바꾸면 거짓말이 된다).
`적용` 단추는 남겼다 — 끌기가 안 되는 환경에도 길이 있어야 한다.

**③ 레이아웃 — 절반만.** `docs/decisions/2026-08-17-editor-capcut-layout-approval.ko.md`
참조. 타임라인 높이는 들어갔고(1500px 미만에서 122px→372px), 넓은 화면에서는
기존 e2e 가드 때문에 거의 못 키웠다. 왼쪽 재료 패널 기본 펴기는 두 번 시도해
두 번 되돌렸다 — 단위 테스트 해법은 확인됐고 e2e 3건이 남았다.

## 지금 남은 것 (2026-08-17 기준)

1. **왼쪽 재료 패널 기본 펴기** — 승인 있음. 단위 테스트 해법은 결정 문서에 적어 뒀고,
   남은 것은 **e2e 3건 + 편집 작업판 스냅샷 재생성·재승인**이다.
2. **미리보기/타임라인 비율 재정의** — 캡컷처럼 아래 절반을 타임라인이 쓰려면
   `exact-preview.spec.mjs:94`("1920 미리보기가 1440보다 작으면 안 된다")와
   2026-07-22 결정을 **함께** 다시 열어야 한다. 지금 상태로는 1440에서 타임라인이
   4rem으로 눌리는 탓에, 1920에서 타임라인을 키우면 미리보기가 되레 작아진다.
3. **데스크톱 껍데기** — 아이콘 하나로 켜기, 네이티브 파일 고르기. 안쪽 화면은 그대로.
   **웹이라서 생기는 진짜 불편은 이것뿐**이라는 것이 이 문서 위쪽의 결론이다.

## 2026-08-18 후속 — 5번(데스크톱 껍데기)을 다시 재 봤다

위 `고칠 순서`의 5번은 "아이콘 하나로 켜지고 파일을 그냥 고르게"였다. 둘 중 **하나는
이미 되고 있었다.**

**파일 고르기 — 이미 네이티브다.** 화면을 세어 보니 자산 추가·내레이션·장면
영상·음성 파일 전부 `<input type="file">`을 쓰고, 끌어다 놓기와 **폴더째 고르기**도
된다. 경로를 치는 칸은 음성 설정에 하나 남아 있는데 바로 옆에 파일 업로드가 같이
있다. 위에서 "파일 경로를 타이핑해야 한다"고 적은 것은 **틀린 관찰이었다.**

**켜기 — 이건 진짜였고, 풀었다.** `VideoBox.cmd`(바탕화면 아이콘) →
`scripts/Start-VideoBox.ps1`. Docker Desktop을 대신 켜고, `owner-ready.ps1`에 시작을
넘기고, 응답할 때까지 기다린 뒤 **주소창 없는 앱 창**으로 연다.

즉 **5번에 남은 웹 특유의 불편은 없다.** Electron/Tauri 같은 네이티브 껍데기는
새 런타임·빌드·배포 경로가 붙는 큰 작업인데, 그게 풀어 줄 문제가 이제 없다.
하려면 범위를 owner와 먼저 맞춘다.

1~4번(편집기를 집으로 / 첫 화면을 껍데기 안으로 / 읽을 수 있는 표기 / 자산 분류)은
`2026-08-17` closeout에서 닫혔다.
