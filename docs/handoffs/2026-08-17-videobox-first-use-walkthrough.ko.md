# 처음 쓰는 사람처럼 밟아 본 결과 — owner 말이 맞았다

- 점검일: 2026-08-17
- 계기: owner — *"프로그램 자체가 작동하는 법도 모르겠고, 인터페이스도 너무 헷갈리고,
  작동도 안 하고, 완전 총체적 문제네."*
- 방법: API를 부르지 않고 **화면만** 써서 새 프로젝트를 만들고 편집까지 가 봤다.

## 그동안 왜 못 봤나

나는 오늘 하루 **API 호출과 캡처로만** 확인했다. 처음 열어서 따라가 본 적이 없다.
그래서 "전부 초록"이라고 보고하는 동안 owner는 시작조차 못 하고 있었다.

## 가장 큰 것 — 편집기가 집이 아니라 마법사의 3번째 칸이다

새 프로젝트를 만들면 `/create`(기획)로 간다. **편집 화면에 직접 들어가면 이렇게 뜬다.**

```
먼저 영상 초안을 만들어 주세요.  [새 영상 만들기]
```

즉 **기획을 통과하지 못하면 편집기를 열 수 없다.** 영상 편집 프로그램인데
편집기가 잠겨 있고, 설문 같은 단계를 먼저 밟아야 한다.

owner가 "캡컷처럼 만들어야겠다"고 한 것이 이 지점이다. **캡컷은 열면 바로 편집판이다.**

**다행인 것:** 편집기 자체는 이미 캡컷 배치다 — 위 툴바, 가운데 미리보기, 아래 타임라인,
오른쪽 패널. **뜯어고칠 대상은 편집기가 아니라 그것을 감싼 마법사다.**

## 첫 화면이 앱처럼 안 보이는 이유 — 껍데기 밖이다

`/projects`(첫 화면)에는 **사이드바가 없다.** 프로젝트를 하나 만들고 나서야 나타난다.
그래서 처음 여는 사람에게는 프로그램이 아니라 **웹페이지 한 장**으로 보인다.

첫 화면에서 확인한 것들:

- **새 프로젝트 입력이 페이지 맨 아래.** 카드 6개를 지나 스크롤해야 나오고,
  대화상자가 아니라 라벨+입력+단추가 날것으로 붙어 있다.
- **링크가 파란색 밑줄.** `계속 만들기`·`완성본 보기`·`검토 문제 해결`.
  승인된 팔레트(주황 `#C2410C`)와 무관하다.
- **날짜가 기계 형식 그대로.** `2026-08-17T06:13:40.438824+00:00` — 카드 폭에서
  줄바꿈돼 `+00:0 0`으로 잘린다.
- **상태에 내부 단계 이름이 그대로.** `기획 · 준비됨`, `검토 · 막힘`.
- 썸네일이 있는 카드와 없는 카드가 섞여 **높이가 어긋난다.**

## 그 밖에 관찰된 것

- 새 프로젝트에서 편집 화면을 열면 `editing-sessions/latest`가 **404**를 내고
  콘솔 오류가 남는다. 화면은 안내로 처리하지만, 정상 흐름에서 404를 내는 것은
  나중에 진짜 오류를 가린다.
- **자산 화면에 분류가 없다.** 종류 탭은 있지만 그 안은 그냥 나열이다 —
  폴더도, 정렬도, 즐겨찾기 묶음도 없다. owner 지적대로다.

## 결론 — 웹이라서가 아니다

owner가 "웹이라서 복잡한 것 같다"고 했는데, **위 문제 중 웹 때문인 것은 없다.**
데스크톱으로 다시 만들어도 마법사는 마법사고, 첫 화면은 여전히 껍데기 밖이고,
날짜는 여전히 기계 형식이다.

**웹이라서 생기는 진짜 불편은 따로 있다** — 도커를 띄우고 주소를 쳐야 켜지는 것,
파일 경로를 타이핑해야 하는 것. 그건 **데스크톱 껍데기**로 풀린다(안쪽 화면은 그대로).

## 고칠 순서 (제안)

1. **편집기를 집으로.** 프로젝트를 열면 편집 화면이 먼저. 기획·자산·검토는
   단계가 아니라 **패널·메뉴**로 접어 넣는다. 편집기는 이미 그 모양이라 새로 안 만든다.
2. **첫 화면을 껍데기 안으로.** 사이드바가 처음부터 보이게. 새 프로젝트는 대화상자로.
3. **읽을 수 있는 표기.** 날짜·상태를 사람 말로.
4. **자산 분류.** 종류 안에서 최근·즐겨찾기·검색.
5. **데스크톱 껍데기.** 아이콘 하나로 켜지고 파일을 그냥 고르게.

## 나중에 남들도 쓰게 할 계획 (owner 확인, 2026-08-17)

owner가 **"나중에 남들도 쓰게 할 계획"**이라고 답했다. 지금 저장소는 1인용·내 PC
전용 전제이고 `CLAUDE.md` §6이 `SaaS, billing, multi-user 인증`을 승인 항목으로 둔다.

**지금 만들지는 않는다.** 다만 위 재배치를 할 때 **나중에 계정·권한·데이터 분리를
넣을 자리를 막지 않도록** 한다. 특히 프로젝트 목록과 라이브러리가 "이 사람의 것"이라는
개념을 나중에 받을 수 있어야 한다.

# 편집기 점검 — owner: *"컷편집이 되는지도 모르겠다"*

실제로 편집기를 열어 컨트롤을 하나하나 세어 봤다.

## 1. 편집기를 열면 단추가 4개다

```
[툴바] 실행 취소 / 다시 실행 / 자산과 대본 / 유진과 편집 항목
```

**자르기도, 나누기도, 붙이기도, 삭제도 없다.** 영상 편집기를 열었는데 편집하는
단추가 하나도 안 보인다. 캡컷은 열자마자 타임라인 위에 자르기·분할·삭제가 있다.

## 2. 장면을 골라야 3개가 나온다 — 그것도 내부 ID를 달고

```
clip_narration_7568b55139 시작 자르기
clip_narration_7568b55139 끝 자르기
clip_narration_7568b55139 순서 바꾸기
```

**사용자에게 내부 clip ID를 그대로 보여 준다** (`§10.13` 위반). 그리고 여기에도
나누기·붙이기·삭제는 없다.

## 3. 나누기·붙이기는 있는데 `선택 구간 편집` 안에 숨어 있다

기능은 **다 구현돼 있다.** `splitNarration`·`mergeNarration`·`setCutAction`·
`setNarrationBounds`·`reorderNarration`·`setTimelinePlacements` 전부 동작하고
테스트도 있다.

그런데 화면에서 그 자리에 닿으려면 **`선택 구간 편집`이라는 이름의 컨트롤**을
찾아야 한다. `자르기`도 `나누기`도 아닌 이름이라, 찾을 수가 없다.

## 결론

**컷편집 기능이 없는 게 아니라, 부를 수 있는 자리가 없다.**

- 엔진: 자르기·나누기·붙이기·삭제·순서·트림 **전부 있음**
- 화면: 툴바에 편집 단추 **0개**, 장면 선택 시 **3개**, 나머지는 이름으로 못 찾음

owner가 "그냥 막 집어넣은 것 같다"고 한 것이 정확하다. **기능을 만든 순서대로
아무 데나 붙였고, 캡컷처럼 묶어서 보여 준 적이 없다.**

## 캡컷을 기준으로 하면 이렇게 된다

| 캡컷 | 지금 우리 | 할 일 |
|---|---|---|
| 타임라인 위 편집 막대 (분할·삭제·복제·속도) | 없음 | **툴바에 컷 도구를 올린다** |
| 왼쪽 재료 탭 (미디어·오디오·텍스트·효과) | 자산이 **다른 단계**에 있음 | 편집기 왼쪽 패널로 |
| 오른쪽 속성 (선택한 것에 따라 바뀜) | 인스펙터에 섞여 있음 | 유지하되 이름 정리 |
| 클립을 끌어서 자르기 | `시작 자르기` 단추 | 유지 + 이름 정리 |

**우리만의 것**은 `유진과 편집 항목` 하나면 된다. 나머지는 캡컷 배치를 따른다.

## 첫 조각 완료 — 툴바에 컷 도구를 올렸다 (2026-08-17)

```
[전] 실행 취소 / 다시 실행 / 자산과 대본 / 유진과 편집 항목
[후] 실행 취소 / 다시 실행 / 나누기 / 앞과 붙이기 / 빼기 / 자산과 대본 / 유진과 편집 항목
```

`cutToolbar.ts`는 **무엇을 누를 수 있는지만** 정하고, 실제 변경은 이미 있던
`InspectorAction` 경로가 한다 — 같은 편집이 두 경로를 갖지 않게 했다.

**만들다가 되돌린 것 하나.** 처음에는 `빼기`가 뺀 장면에서 `다시 넣기`로 바뀌게 했는데,
실제 앱에서 확인해 보니 **뺀 장면은 타임라인에서 사라져 다시 고를 수가 없었다.**
세션에는 `remove`로 남아 있지만 클립이 없으니 그 단추는 영원히 못 누른다. 지웠다.
되돌리기는 `실행 취소`가, 다시 넣기는 인스펙터의 `유지`가 맡는다.

**실제로 눌러 보고 잡은 것 하나.** 장면을 골랐는데도 `나누기`가 회색이었다. 로직은
맞았다 — 고른 장면이 5~10초인데 재생 위치가 0초였다. 문제는 **화면이 이유를 말해 주지
않는다**는 것이었다. 이유 없이 회색인 단추는 사용자에게 고장으로 읽힌다. 그래서 각
도구가 `hint`를 함께 갖게 하고, 잠긴 단추에도 뜨도록 감싸는 자리에 걸었다(잠긴 단추는
마우스 이벤트를 받지 않아 자기 title을 못 띄운다).

## 그리고 실제로 눌러 봤더니 컷편집이 아예 막혀 있었다

단추를 붙이고 실제로 밟아 보니 **재생 위치가 첫 클릭 자리에 붙박였다.**

```
10% 클릭 → 1.45초   30% 클릭 → 1.45초   50% 클릭 → 1.45초
```

재생 위치가 안 움직이니 `나누기`는 영원히 잠긴 채였다. **컷편집을 부를 자리를
만들었는데도 여전히 쓸 수 없었던 것이다.** 원인은 두 겹이었고, 둘 다 "위치를
서로 되돌려 주는" 같은 모양이었다.

**첫째 — 타임라인과 소유자가 서로를 되돌렸다** (`TimelineDock.tsx`). 타임라인이 위치를
올려보내는 effect와 밖에서 온 위치를 따라가는 effect가 **둘 다 `state.playheadSec`을
보고 있었다.** 내가 위치를 옮기면, 아직 갱신 안 된 옛 `playbackSec`이 나를 도로
끌어당긴다. 고리가 돌다가 옛 자리에서 멈춘다. 고침: 따라가는 쪽은 **밖에서 온 값만**
보게 하고(`deps: [playbackSec]`), 방금 내가 올려보낸 값이 되돌아오면 무시한다.

**둘째 — 미리보기가 자기 구간 밖 재생 위치를 도로 밀어 올렸다** (`preview-stage.tsx:78`).
`선택 구간 미리보기`는 타임라인 일부만 담는데, 재생 위치가 그 밖으로 나가면 자기 구간
안으로 **되돌려 올려보내고** 있었다. 테스트가 이걸 의도된 계약으로 못박고 있었다
(*"returns the effective selected-range position when an external seek is out of range"*).

의도는 이해된다 — 보이는 화면과 알려진 위치를 맞추려던 것이다. 하지만 그러면 **재생
위치가 미리보기 구간의 포로가 된다.** 구분해야 할 것은 이 둘이다.

- 미리보기가 **스스로 알리는** 위치(`timeupdate`) → 올려보내는 게 맞다. 그대로 뒀다.
- 사용자가 **못 보여 주는 자리로 옮긴 것** → 되밀면 안 된다. 이걸 걷어냈다.

대신 말없이 다른 순간을 보여 주지 않도록, 화면과 재생 위치가 갈리면 그 사실을 적는다.
*"이 화면은 타임라인 8.0초의 모습입니다. 재생 위치는 그보다 바깥에 있어 아직 볼 수 없어요."*

**고친 뒤 실제 확인:**

```
10% → 1.45초   30% → 4.36초   50% → 7.28초      (자유롭게 움직인다)
7초에서 나누기 = 누를수있음 → 눌렀더니 내레이션 클립 2개 → 3개
```

**교훈은 이번에도 같다.** 단추를 붙이고 테스트가 초록이어도, **실제로 눌러 보기 전까지는
쓸 수 있는지 알 수 없다.** 컷 도구 단위 테스트는 처음부터 통과하고 있었다 — 막고 있던
것은 그 단추가 읽는 재생 위치가 움직이지 않는다는, 전혀 다른 곳의 사실이었다.

**남은 것:** 재생 위치를 옮기려면 타임라인을 눌러야 하는데, **눈금 위에 재생 위치 표시가
잘 안 보인다.** 캡컷은 눈금에 붙은 세로선이 뚜렷하다. 다음 조각이다.
