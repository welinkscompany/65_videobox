## 내가 틀렸던 것 (같은 함정 반복 금지)

1. **"세로 띠로 옮기면 스크롤이 풀린다" -- 틀렸다.** 탭은 도구줄에 있었지 패널
   안이 아니었다. 옮겨 비운 건 도구줄 공간이었다. 재보고 진짜 원인을 따로 찾았다.
2. **왼쪽 패널만 계속 쟀다.** owner가 보낸 화면(`편집 항목`)은 **오른쪽**이었고
   그쪽이 4.25배로 훨씬 나빴다. **지적받은 자리를 먼저 확인하라.**
3. **"배속은 길이를 안 바꾼다"는 기억이 낡았다.** 엔진은 이미 캡컷과 같이
   동작했다(`set_segment_ripple_playback_rate`). 없던 건 화면 표시뿐이었다.
   기억 메모를 고쳤다.
4. **`display:contents`로 접근성을 깰 뻔했다.** `role="group"`이 접근성 트리에서
   사라진다. 되돌렸다.
5. **특정도 경쟁으로 고친 것은 다음 변경에 진다.** 어제 부모 선택자로 올린
   `height:auto`가 오늘 32px 통일에 밀려 촬영본 12칸이 다시 잘렸다.
   `data-multiline` 고리로 바꿨다.

## 일부러 안 한 것

- **`대본` 탭.** owner는 6개를 말했지만 5개로 했다. 캡컷의 `대본`은 우리에게 없는
  기능이고, 우리 `이야기` 내용을 옮기는 건 5단계다. 지금 탭만 만들면 막다른 자리다.
- **자료실 첫 호출 2초.** 검증 캐시가 프로세스 안에만 있어서다. DB에 남기면
  없앨 수 있지만 저장 스키마 변경이라 범위 밖.
- **결제·다중 사용자.** §6 승인 대상. 이음매만.

2. **재생줄을 타임라인으로** -- 미리보기 실패와 무관하게 늘 보이게. 스페이스바 문제의 뿌리.
