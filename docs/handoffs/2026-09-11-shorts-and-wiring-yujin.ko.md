# 인계 — 숏폼 세로 영상과 유진 배선 (2026-09-11)

상태: 출력 구간 세 조각 마감, 세로 영상 마감, 숏폼 판단 배선 진행 중.
이 문서가 **현재 인계**다. 앞 문서(`2026-09-08-hermes-egress-and-multitrack-plans.ko.md`)는 대체됐다.

## 1. 대표님이 이 세션에 새로 준 상시 지시 셋

이 셋은 한 번짜리 요청이 아니라 **계속 적용되는 기본값**이다.

1. **검증 넷은 조각마다 고정이다** — 갭·역방향·동작·배선. `CLAUDE.md` §3과
   `development-fast-path.ko.md` §10.2를 그렇게 고쳤다. 이전 규정("리스크 기반 선택")은
   더 이상 유효하지 않다.
2. **화면으로 되는 일은 전부 유진에게 말해서도 되어야 한다.** 앞선 "화면에 열면 유진도
   같이 열어라"보다 세다 — **이미 있는 빈 곳도** 메운다.
3. **숏폼이 제품 범위다.** 세로 영상을 만들 수 있어야 하고, 롱폼을 주면 마케팅용으로
   판단해 자동으로 잘라 줘야 한다.

## 2. 끝난 것 — 실물에서 잰 값만 적는다

### 출력 화면 세 조각 (계획서 `2026-09-11-render-progress-and-variants.md`)

| 무엇 | 실물 측정 |
|---|---|
| 만드는 동안 진행이 보인다 | 렌더 도는 28초 내내 화면이 스스로 갱신, 단추가 `완성본 만드는 중`. MutationObserver로 깜빡임 **0회** |
| 변형본을 파일로 가져간다 | 단추 없이 11초→37초에 스스로 완료로 바뀌고 내려받기 문이 떴다 |
| 실패하면 할 일을 보여준다 | 실제 실패에서 `검토에서 아직 승인하지 않았어요. 검토를 마치면 완성본을 만들 수 있어요.` |

### 세로 영상 (계획서 `2026-09-11-the-vertical-output-is-not-vertical.md`)

**네 겹이 걸려 있었다.** 크기를 kind에서 다시 정하지 않은 것 → 같은 조립 코드가 두
자리에 있어 한쪽만 고치면 무효가 되던 것 → 검은 띠가 화면의 68%를 먹던 것 →
**캐시 때문에 고쳐도 대표님이 못 받던 것**.

화면에서 눌러 나온 파일: **1080×1920**, md5가 마스터와 다름, 검은 띠 없음
(위 37 / 가운데 40 / 아래 52 — 띠면 위아래가 0), 이름 `…세로 영상.mp4`.

### 숏폼 판단 (계획서 `2026-09-12-tell-yujin-to-cut-a-short.md`)

`243-ab10834c` 프로젝트(243장면)에서 **실제 로컬 모델**로 밟았다:

- 45.2초, `judged_by: "yujin"`
- 안내문이 **48/243을 정확히 셌다** — 통조림 문장이 아니다

- 영상 5등분 분포 앞 3/1/1/1/뒤 2 — **전 구간**. 앞부분만이 아니다

## 3. 실물에서만 나온 결함 — 이 세션에 **일곱**

전부 시험은 초록이었다. 재빌드하고 브라우저·`ffprobe`로 재서 나왔다.

1. 화면이 서버의 진짜 실패 사유를 버리고 `renderer_failed`로 덮었다
2. 완성본·가로·세로 내려받기 이름이 셋 다 같아 서로 덮어썼다
3. 5초 폴링이 검토 영역을 5초마다 로딩 표시로 되돌렸다 (합쳐진 화면에서만 드러난다)
4. 가로·세로 카드가 얼어 있어 새로 만든 내려받기 문이 클릭 전엔 안 보였다
5. 세로 영상이 세로가 아니었다 (완성본·가로·세로 md5가 전부 같았다)
6. 유진의 출력 모양 조정이 **항상 422**였다 — 스키마도 실행기도 있는데 못 썼다
7. 숏폼이 장면을 골라도 **안 짧아졌다** (원본 좌표를 그대로 들고 있었다)

## 4. 다음 세션이 먼저 알아야 할 함정

- **같은 로직이 두 자리에 있는 패턴에 하루 세 번 걸렸다.** 고치기 전에 두 번째 자리를
  grep해라. 땜질을 두 번 하게 되면 멈추고 한 함수로 묶어라.
- **변형본 타임라인의 `output_mode`는 제품에서 `review`다.** 종류는 `source_variant_id`로
  읽어라. 파일 저장소 시험은 초록인데 Postgres에서는 안 통한다.
- **값을 적는 것과 결과가 그렇게 되는 것은 다른 주장이다.** 오늘 결함 다섯이 이것이었다.
  크기는 `ffprobe`로, 길이는 `duration`으로, 소리는 음량으로 재라.
- **"유진은 장면을 48개만 읽는다"는 경로를 안 밝히면 틀린 문장이다**(2026-09-12 정정).
  두 경로가 서로 다르다.
  - **단추 경로**(`숏폼 만들기` → `POST /output-variants` → `pick_short_form_scenes`):
    기계가 영상 전체에서 고르게 **48개를 추리고**(`MAX_JUDGED_SCENES`) 유진이 12개씩
    나눠 읽는다. 안내문이 몇 개 중 몇 개를 읽었는지 말한다. 243장면 실측이 이 경로다.
  - **채팅 경로**(유진에게 "숏폼으로 잘라줘"): 추리기를 **안 탄다.** 유진은 창작 맥락에
    담긴 장면만 보고, 그 목록은 `MAX_SEGMENTS = 32`에서 잘리며(`_fit_context`가 더
    떨어뜨릴 수도 있다) 앞 장면부터 채워진다 — 즉 **롱폼이면 앞 32장면 안에서만** 고른다.
    2026-09-12에 정직하게 만들어 뒀다: 응답 후보가 `scenes_read_by_yujin`/`scenes_total`을
    싣고, 화면이 "장면 243개 중 32개만 보고 골랐어요"라고 말하며, 프로필이 유진에게도
    그 사실을 답변에 적으라고 한다. **추리기를 채팅 경로에 태우는 일은 아직 안 했다**
    (다음 조각). 전 구간 판단을 원하면 단추 경로를 써야 한다.

## 5. 남은 것

### 실물로 못 잰 채 남는 것 (정직하게)
- **유진이 답 못 할 때의 대비책 표시.** 확인하려면 모델을 일부러 꺼야 하고 대표님이 다른
  프로젝트에서 같은 LM Studio를 쓰고 있다. 시험 5개(변형 탐침 포함)가 화면이 실제로 받는
  응답에 대고 단언한다 — 근거가 약하지는 않지만 **실물 확인은 아니다**.
- **롱폼 판단을 대표님 실제 영상으로.** 243장면 시험 입력을 **내가 만들었고**, recall
  휴리스틱이 찾는 단어를 내가 넣었으므로 부분적으로 순환이다. 실제 영상 하나가 필요하다.

### 안 한 것 (일부러, 다음 조각)
- **출력 화면에 유진 진입점.** `OutputsPage.tsx`에 `유진`·`Yujin`이 **0건**이다.
  완성본 만들기·CapCut 내보내기·검토 승인을 유진에게 못 시킨다. 화면을 새로 짓는 크기다.
- **유진 배선의 나머지 빈칸** — 장면 분할/합치기, 도형 오버레이, 트랙 숨김, 자막 번역·더빙,
  TTS 후보 지우기. 목록과 근거는 `docs/surveys/2026-09-11-yujin-command-gap.ko.md`.
- 옛 변형본 소급 수리 — 안 한다. 캐시 수정 덕에 다음 materialize에서 저절로 고쳐진다.
- CapCut 초안 내려받는 라우트.

### 치울 것
- `243-ab10834c` "롱폼 243장면 실측" 프로젝트는 **내가 만든 검증용**이다. 롱폼 경로를
  다시 잴 때 쓸 수 있어 남겼다. 필요 없으면 지워도 된다.
