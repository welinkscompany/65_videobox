## 검증 완료 (정상 동작 확인)

- **컷 편집**: 촬영본 가져오기 → 적용(타임라인 배치) 정상.
- **배속**: 2배 적용 시 길이 자동 연동(5.0→2.5초) 정상, 1배 복귀도 정상.
- **자막**: 수동 입력 → 저장 → 미리보기 화면에 실제로 번인되는 것까지 확인.
- **유진 대화 명령**: 채팅으로 "배속을 1배로 되돌려줘" → 확인 클릭 없이 즉시 적용,
  "모든 작업 완료 1/1" 확인. 2026-09-01 결정("말하면 바로 적용") 그대로 동작한다.
- **콘텐츠 자산화(자료실 의미검색)**: `/library` 페이지에서 종류 탭(영상/음악·효과음/
  그림)을 고르고 검색하면 실제 임베딩 기반 의미검색이 동작한다 — "공원" 검색 시
  "뜻으로 찾음" 배지, 실제 한국어 장면 설명·스코어(0.44~0.49) 확인.
- **숏폼 자동 변환**: 검토 승인 → "숏폼으로 변환" → 실제 렌더 완료까지 확인. 결과
  영상을 캔버스로 픽셀 샘플링해 1080×1920 해상도·검은 띠 없음·실제 화면 내용(밝기
  90~196, 블랙아웃 아님)까지 확인했다 — 단색/블랙 결함을 숨기지 않으려고 실제 픽셀을
  쟀다.
- **트랙 잠금/숨김/음소거**: 브라우저 좌표 클릭으로는 계속 반영이 안 돼 처음엔
  버그로 의심했으나, DOM 요소를 정확히 지정해 재시험하니 PATCH 저장·재로드 반영
  전부 정상이었다. **내 좌표 기반 클릭의 오차였다** — 제품 결함 아님(자기 오진 방지
  원칙에 따라 기록만 남긴다).

## 남겨둔 것 (제품 판단 필요, `task_e74e2d5d`로 분리)

프로젝트 안 "미디어" 패널의 검색창은 순수 클라이언트 필터라, 방금 분석이 끝난
자산도 못 찾는다. `EditorAssetBrowser.tsx`의 `filterEditorAssets`가 자산의
`metadata.tags`를 훑는데, vision 분석이 성공(`status: succeeded`, 태그 다수)해도
`GET .../assets/broll-video`의 `metadata.tags`는 계속 `[]`로 비어 있다 — 분석 결과가
asset metadata로 다시 안 쓰인다. 의도된 설계(프로젝트 내 검색은 원래 이름만, 의미검색은
자료실 전용)인지 배선 누락인지 이번 세션에서 결론 못 냈다.
