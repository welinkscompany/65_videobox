## 0. 사전 정정 — 이전 분석에서 과장·오판한 항목

첫 분석에서 아래 항목을 "치명적 버그"로 보고했으나, `docs/development-fast-path.ko.md` §10과
`docs/decisions/creator-workspace-visual-approval.ko.md`를 확인한 뒤 판정을 정정한다.

| 최초 보고 | 정정된 판정 |
|---|---|
| "색상 시스템 2개 충돌 = 구조적 결함" | 원래는 변수·하드코딩 모두 indigo 계열로 일관됐다. 변수만 오렌지로 바꾸면서 생긴 충돌이다. 단, 하드코딩이 변수를 참조하지 않는 것 자체는 실제 부채로 유지 |

## 1. 검증된 실제 결함

### F-1. 편집 화면 데드엔드 (심각도: 높음)

- 위치: `apps/web/src/app/AppRouter.tsx:308` `CanonicalEditorEntry`
- 증상: 초안이 없는 프로젝트에서 `/projects/{id}/editor` 진입 시
  사이드바·헤더 없는 흰 화면에 문장 한 줄만 렌더된다. 되돌아갈 조작 수단이 없다.
- 재현: 새 프로젝트 생성 직후 편집 메뉴 진입
- 근거: `<main aria-live="polite"><p>{message}</p></main>` 단독 렌더. ProductShell 미적용
- 수정 방향: ProductShell 유지 + "초안 만들기"로 유도하는 액션 제공

### F-2. 타임라인에 내부 식별자 노출 (심각도: 중간)

- 증상: 클립 접근성 이름이 `broll:session-broll-segment_draft_1726b9574a-0 클립 선택` 형태로
  내부 ID를 그대로 노출한다. 자막 클립도 동일하다.
- 근거: 브라우저 접근성 트리 실측
- 규정 연계: `§10.13.3`이 dashboard copy에서 개발·시스템 내부 용어 노출을 금지한다.
  내부 ID 노출도 같은 취지에 어긋난다.
- 수정 방향: 사람이 읽는 라벨(예: `B-roll 1번 장면`)로 치환

### F-3. 프로젝트 삭제 경로 부재 (심각도: 중간)

- 위치: `services/api/src/videobox_api/routers/projects.py`
- 증상: `POST/GET`만 있고 삭제 라우트가 없다. UI에도 삭제 수단이 없다.
- 영향: 테스트·오조작으로 만든 프로젝트가 목록에 영구 잔존한다.
  실제로 이번 세션에서 만든 `my-project`가 잔존 중이다.
- 수정 방향: 삭제 API + 확인 절차가 있는 UI. 데이터 보존 정책과 함께 설계 필요

### F-4. 테마 하드코딩 부채 (심각도: 중간)

- 위치: `apps/web/src/styles/product-shell.css`
- 증상: 하드코딩 색상 19종이 CSS 변수를 전혀 참조하지 않는다.
  이 때문에 토큰을 바꿔도 셸 전체 색이 바뀌지 않는다.
- 실측: `--primary`를 바꿔도 기본 버튼은 `rgb(91,74,200)` 유지
- 수정 방향: 하드코딩 → CSS 변수 일원화. 승인된 팔레트 값과 1:1 대응시킨다

### F-5. 중복 액션 노출 (심각도: 낮음)

- 증상: `새 영상 만들기`가 사이드바·헤더·본문 카드 3곳에 동시 존재한다.
- 수정 방향: 주 진입점 1개로 정리하고 나머지는 맥락 의존으로 축소

## 4. 재점검 시 사용법

개발 환경 재정비가 끝난 뒤 이 문서를 다시 열어 아래 순서로 처리한다.

1. `F-1` 편집 데드엔드 — 사용 흐름을 막는 결함이므로 최우선
2. `F-4` 테마 하드코딩 — `D-1` 팔레트 결정의 선행 조건
3. `D-1` 팔레트 재승인 절차 진행
4. `F-2`, `F-3`, `F-5` 순차 처리
5. `D-2`는 별도 설계 문서를 먼저 만든 뒤 착수

각 항목 착수 시 `§10.1`에 따라 공식 계획서 상 귀속 Task를 먼저 식별하고,
계획서 밖 작업이면 그 사실과 진행률 비포함 여부를 명시한다.
