## C에서 확인한 것 — 절반은 이미 돼 있었다

`2026-08-17` 첫 사용 점검이 데스크톱 껍데기로 풀 문제를 둘로 정리했다.

**"파일 경로를 타이핑해야 하는 것" — 이미 안 그러고 있다.** 화면을 세어 보니 자산
추가·내레이션·장면 영상·음성 파일 전부 네이티브 파일 선택창(`<input type="file">`)을

**"도커를 띄우고 주소를 쳐야 켜지는 것" — 이걸 풀었다.**


바탕화면 아이콘을 만들려면 한 번만:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Install-VideoBoxShortcut.ps1
```

창**으로 연다. 실제로 켜서 확인했다(Edge 앱 창, 제목 `VideoBox`).

**컨테이너는 직접 다루지 않는다.** `owner-ready.ps1`에 넘긴다 — `CLAUDE.md` §3이

## 프레임 이동·장면 반복 — 목록의 마지막 미착수 항목

재생 줄에 `◀｜` `｜▶` `반복`을 넣었다.

- **프레임 폭은 타임라인이 실제로 쓰는 프레임률에서 뽑는다.** 30fps를 박아 두면
  25fps 소재에서 프레임이 어긋난다.
- **반복 구간을 새로 만들지 않았다.** 화면이 이미 `적용 구간`으로 보여 주는 그
  구간(`assetTarget`)이다. 그래서 고른 장면이 없으면 단추 자체가 없다.
- **구간 밖으로는 안 움직인다.** 미리보기는 자기 구간 밖의 순간을 갖고 있지 않다.

단추는 재생 줄 **안에** 넣었다. 미리보기 판의 글자·단추 줄이 이미 세로 공간을 가장
많이 먹는 쪽이라 줄을 새로 만들지 않았다.

### 이걸 만들다 오래된 결함이 하나 나왔다

화면에서 `다음 프레임`을 눌러 보니 **한 번은 먹고 두 번은 안 먹었다.** 단위 테스트도
e2e도 전부 초록이었다. 브라우저에서 `currentTime`에 누가 쓰는지 찍어 보니 이랬다.

```
click → set 5.166665 (프레임 이동)
      → set 5.133332 (효과)      ← 옛 위치로 되돌림
      → set 5.166665 (효과)
      → set 5.133332 (효과)
```

**자리를 옮겨 달라고 하면 플레이어는 잠깐 옛 위치를 그대로 알려 준다.** 그 값을 위로
올리니 소유자가 옛 위치를 되돌려 보내고, 두 쪽이 서로 밀며 제자리를 맴돌았다.
가라앉은 뒤에 오는 `seeked`만 믿도록 고쳤다.

2026-08-17에 고친 `재생 위치가 첫 클릭 자리에 붙박였다`와 같은 집안이다. 그때는
타임라인과 소유자 사이의 고리였고 이번은 플레이어와 소유자 사이의 고리다.
**프레임 이동이 없었으면 계속 안 보였을 것이다** — 0.03초짜리 이동이라야 되돌려진
것이 눈에 띈다. 프로그램으로 재생 위치를 옮기는 곳은 전부 이 고리를 타고 있었다.

### 이번에 확인하며 **내가 틀렸던 것**

- `B-roll·음악·자막을 타임라인에서 못 옮긴다`고 적었는데 **틀렸다.** 영상·음악은
  고르면 이동·시작·끝 손잡이가 나온다. 앞서 셀 때 내레이션만 골라 놓고 세었다.
- `선택 구간 편집`이 툴바와 **같은 편집을 두 경로로** 제공한다고 적었는데 절반만
  맞다. 툴바 `나누기`는 재생 위치에서 자르므로 재생 위치가 장면 밖이면 꺼진다.
  인스펙터 것은 그때도 되는 대체 경로이고, `유지/삭제`는 뺀 장면을 되살리는
  유일한 길이다. 지우지 않고 이름만 `고른 장면`으로 바꿨다.

## 코드리뷰에서 내 변경에서 나온 것 다섯

내 diff(49파일)를 한 번에 훑었다. 앞의 셋은 실제 결함이다.

1. **반복이 재생을 붙박이게 했다.** 부분 구간 미리보기(4~8초) 중에 9~12초 장면을
   고르고 반복을 켜면, 되감을 자리가 미리보기 안에 없어 매 tick마다 닿을 수 없는
   곳을 노렸다. 담고 있지 않은 구간은 반복하지 않도록 막았다.
2. **장면을 바꿀 때마다 묻지도 않은 음성 조회가 나갔다.** 초기화를 effect에서 하니
   조회 effect가 같은 commit에서 아직 켜져 있는 옛 값을 읽었다. "부를 때만 부른다"가
   두 번째 장면부터 무너지고 있었다. 요청을 **장면과 묶어** 들고 있게 고쳤다.
3. **Docker 확인이 호출마다 임시 파일 2개를 남겼다.** 2초마다 불리므로 도커가 느린
   날 `%TEMP%`에 수백 개가 쌓인다.
4. 배율 방식으로 바꾼 뒤 `anchorPx`가 죽은 코드로 남아 있었다.
5. `실패한 정비가 다시 안 걸린다`를 시간으로만 기다려, 부하가 걸린 날 **한 바퀴도
   안 돈 채로** 통과할 수 있었다. 정비 고리가 실제로 세 바퀴 돈 것을 확인하게 했다.

## 갭 검증에서 나온 것 — 두 가드가 서로를 배제한다

실제 컨테이너에서 재니 기본 배치는 미리보기 27~28%인데 **오른쪽 도크까지 열면
20.9%**로 하한 20.8% 바로 위였다. 가드에 그 조합을 넣으니 e2e에서 **18.9%**가 나왔다.

1920x1080에서 오른쪽 도크가 폭 320px를 가져가면 `눈금과 트랙이 다 보인다`와
`면적 20.8%`는 **동시에 만족시킬 수 없다.** 타임라인을 도로 줄이면 owner가 승인한
것이 무너지고, 하한을 낮추면 승인 기록을 마음대로 고치는 것이 된다.

20.8%는 2026-07-22에 **기본 배치에서** 되찾은 값이다. 오른쪽 도크를 여는 것은
창작자가 폭을 참고 패널과 바꾸겠다고 고른 것이므로, 기본 배치에는 20.8%를 그대로
두고 두 도크 조합에는 8.5% 시절과 확실히 떨어진 선을 뒀다. **둘 다 이제 실제로 잰다.**

## 타임라인 클립에 그림이 붙었다 — 캡컷 대비 가장 컸던 차이

클립이 `내레이션 1번째 장면, 5초부터` 같은 **글자뿐**이라 어디가 어느 장면이고
어디서 소리가 커지는지 화면만 보고는 알 수 없었다. 눈으로 자를 자리를 고르는 것이
캡컷의 타임라인이다.

**엔진을 새로 만들지 않았다.** 영상 썸네일은 프로젝트 자산에 이미 있는
`/assets/{id}/thumbnail`을 그대로 쓰고, 소리 파형은 라이브러리 자산이 이미 쓰던
ffmpeg `showwavespic`을 프로젝트 자산에도 열어 준 것이다.

한 번 만들고 다시 쓴다. 실제 화면에서 재 보니 **클립 12개가 자산 2개를 가리켰다** --
첫 화면에서 같은 파일을 동시에 만들려 들므로, 따로 쓰고 통째로 바꿔 끼운다.

## `다음 장면에도` — 캡컷의 `복제`를 이 모델로 옮긴 것

**캡컷의 복제는 우리 모델에 그대로 없다.** 타임라인 배치는 장면에서 파생되고 따로
만드는 길이 없다 -- `apply_placement_changes`는 있는 배치를 옮기고 자를 뿐,
없는 것을 만들면 `timeline_placement_unknown`으로 거절한다.

같은 화면을 한 번 더 쓰는 **실제** 방법은 그 재료를 다음 장면에도 적용하는 것이고
그건 이미 있는 명령(`save-media`)이다. 새 편집 명령을 만들지 않고 그 길을 한 번에
갈 수 있게만 했다.

**이것은 내가 고른 해석이다.** 원했던 것이 다르면 되돌리기 쉽다 -- 새 명령이 없으므로
단추와 상태 계산만 빼면 된다.

## 전환(디졸브) — 내가 처음 판단을 틀렸고, 다시 재니 작았다

처음에 "파이프라인 전체의 시간 계산을 다시 맞추는 일"이라며 미뤘다. **렌더러를
concat 모델로 읽었기 때문이다.**

실제로는 `색 캔버스 위에 각 클립을 자기 타임라인 위치에 올리는` **오버레이 모델**
이고, 겹침을 이미 지원한다 -- 기존 테스트
(`test_plan_renderer_explicitly_preserves_gaps_and_later_broll_wins_overlap`)가
그것을 고정하고 있다.

그래서 디졸브는 길이를 건드리지 않는다. 겹치는 구간에서 **위 클립의 투명도만**
0에서 1로 올리면 아래가 비친다. 자막·소리·재생 위치는 그대로다.

**알파를 태우는 것이 핵심이다.** `alpha=1` 없이 fade를 걸면 아래가 비치는 게 아니라
**검은색으로 가라앉는다.** 그래서 `format=yuva420p`를 함께 건다.

`B-roll에는 소리가 없으니 페이드도 의미 없다`며 빼 두었던 자리를 다시 열었다.
그 문장은 **소리** 페이드 이야기였다. 화면에서는 `서서히 나타나기/사라지기`로
부른다 -- 소리 페이드와 같은 이름을 쓰면 무엇이 바뀌는지 알 수 없다.

**완성본까지 가는 것을 실제 mp4로 확인했다.** 필터 문자열만 보는 테스트는 ffmpeg가
그 필터를 거부해도 통과한다. 두 클립을 겹쳐 놓고 디졸브를 걸어 렌더한 뒤,
파일이 나오고 길이가 6초 그대로인 것을 ffprobe로 본다(`tests/test_broll_dissolve.py`).

**쓰는 법:** 타임라인에서 두 클립이 겹치게 놓고, 위 클립의 속성에서
`서서히 나타나기`에 초를 넣는다.
