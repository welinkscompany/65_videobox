## A에서 배운 것 — 세 번 되돌린 이유

기본값 자체는 한 줄이었다. 막고 있던 것은 **그 기본값을 전제로 쓰인 테스트들**이다.

세 번째 시도가 "조건부 클릭을 넣었더니 오히려 실패가 늘었다"고 기록돼 있었는데,
원인이 나왔다. **첫 프레임에는 작업판 폭이 아직 0이라 잠깐 `drawer`로 잡히고, 그
순간에는 펴져 있는 도크도 DOM에 없다.** 그때 "열려 있나"를 재면 열린 것을 닫힌
것으로 읽고 눌러서 닫아 버린다. 폭이 측정된 뒤에 재면 된다.

```js
await expect.poll(async () => Number(await workbench.getAttribute("data-available-workbench-width")))
  .toBeGreaterThan(0);
```

## B에서 나온 것 — 초록불이 또 안 지키고 있었다

원래 목표는 "타임라인을 더 키운다"였는데, 재 보니 **키우는 게 문제가 아니라 폭
경계가 깨져 있었다.**

같은 900px 높이에서 **1600px 화면이 1440px 화면보다 미리보기를 107px 작게** 그리고
있었다(407 → 300). 타임라인 상한이 1499px를 경계로 두 벌이었고 서로 맞지 않았다.

그걸 막으라고 있던 e2e 가드는 1440x900과 1920x**1080**만 비교했다. 늘어난 화면
높이(+180px)가 차이를 가려서 못 봤다. **높이를 고정하고 폭을 비교해야 보인다.**

CSS 본문을 글자로 대조하던 단위 테스트 3개는 이름에 "a bigger screen never shrinks
the preview"라고 적혀 있었지만, 실제로 줄고 있는 동안 초록이었다. 숫자 대신 형태를
보도록 다시 썼다.

**재다가 나온 결함 셋 — 전부 이번 변경 이전 것이다.**

1. 390x844에서 **미리보기 영상이 0px**였다. 2026-08-17에 상한을 40vh로 올렸을 때
   타임라인이 364px를 먹고 미리보기를 밀어냈다. 승인된 스냅샷은 미리보기가 빈
   상태라 무너질 영상이 없었고, 그래서 아무도 못 봤다.
2. 툴바 버튼 일곱 개 중 **뒤 여섯 개가 화면 밖**이었다. 작업판이 `overflow:hidden`
   이라 밀어 볼 수도 없으니, 폰에서는 재료 열도 유진이도 열 수 없었다.
3. 그 툴바가 `min-width:auto`로 부풀어 **작업판 전체가 390px보다 넓었다.**

셋 다 고쳤고 가드를 붙였다. 폰 미리보기는 이제 60px다 — 0은 아니지만 넉넉하지도
않고, 더 키우는 건 위 `비율 정책`과 같은 결정이다.

## C에서 확인한 것 — 절반은 이미 돼 있었다

`2026-08-17` 첫 사용 점검이 데스크톱 껍데기로 풀 문제를 둘로 정리했다.

**"파일 경로를 타이핑해야 하는 것" — 이미 안 그러고 있다.** 화면을 세어 보니 자산
추가·내레이션·장면 영상·음성 파일 전부 네이티브 파일 선택창(`<input type="file">`)을
쓰고, 끌어다 놓기와 **폴더째 고르기**도 된다. 경로를 치는 칸은 음성 설정에 하나
남아 있는데 바로 옆에 파일 업로드가 같이 있다.

**"도커를 띄우고 주소를 쳐야 켜지는 것" — 이걸 풀었다.**

```
VideoBox.cmd                          ← 바탕화면 아이콘이 가리키는 것
scripts/Start-VideoBox.ps1            ← 실제 순서
scripts/Install-VideoBoxShortcut.ps1  ← 바탕화면 아이콘 만들기 (한 번만)
```

바탕화면 아이콘을 만들려면 한 번만:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\Install-VideoBoxShortcut.ps1
```

하는 일: 이미 켜져 있으면 그냥 연다 → 아니면 Docker Desktop을 켜고 기다린다 →
`owner-ready.ps1 -Mode Start`에 넘긴다 → 응답할 때까지 기다린다 → **주소창 없는 앱
창**으로 연다. 실제로 켜서 확인했다(Edge 앱 창, 제목 `VideoBox`).

**컨테이너는 직접 다루지 않는다.** `owner-ready.ps1`에 넘긴다 — `CLAUDE.md` §3이
그렇게 못박고 있고, 시작 방법이 두 벌이 되면 그중 하나가 조용히 낡는다. 테스트가
이 경계를 지킨다.

**안 한 것: 진짜 네이티브 껍데기(Electron/Tauri).** 새 런타임·빌드·배포 경로가
붙는 큰 작업이고, 위에서 보듯 **그게 풀어 줄 문제가 이제 없다.** 하려면 범위를
owner와 먼저 맞춰라.
