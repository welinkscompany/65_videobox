# VideoBox 2026-08-25 전역 이동·조밀한 조작 인계

**대체됨:** 최신 재개 정보는 `docs/handoffs/2026-08-25-videobox-e2e-closeout-deployment-handoff.ko.md`를 먼저 읽습니다.

## 실제로 한 일

- 상세 설계는 `docs/superpowers/specs/2026-08-25-videobox-navigation-compact-controls-design.ko.md`, 구현 순서는 `docs/superpowers/plans/2026-08-25-videobox-navigation-compact-controls.md`에 남겼습니다.
- 전역·프로젝트 화면의 현재 위치와 안전한 이전 목적지를 `routeManifest.ts` 한 곳에서 계산하게 했습니다. `프로젝트 → 내 라이브러리 → 촬영본 정리`, 프로젝트 단계, 설정, 옛 출력 경로를 모두 포함합니다.
- 모든 정상 화면의 공통 상단에 현재 위치 경로와 작은 `이전 화면` 아이콘을 연결했습니다. 실제로 방문한 경로가 있으면 브라우저 기록으로, 직접 URL을 열었으면 화면별 안전한 상위 화면으로 돌아갑니다. `/projects`를 직접 연 경우에는 동작하지 않는 이전 버튼을 보이지 않습니다.
- 상단 브랜드는 프로젝트 목록으로 이동하게 했고, 프로젝트 선택·단계·메뉴 버튼은 작은 보조 조작으로 조밀하게 바꿨습니다. 주 작업 버튼은 작게 만들지 않았습니다.
- 작은 아이콘 조작에는 키보드 초점과 마우스 올림에서 설명이 나오는 툴팁을 넣었습니다. 승인된 색 토큰과 큰 화면 배치는 바꾸지 않았습니다.
- 공유 `ProductShell.tsx`를 바꾸면서 OSS 출처 무결성 계약의 `normalized_sha256` 두 항목도 실제 파일 해시로 갱신했습니다.
- 전체 Playwright에서 드러난 16건의 실패를 다시 분류했습니다. 제품이 이미 승인된 현재 화면을 내고 있는데 시험이 예전 화면(긴 도크 이름, 항상 펼친 메뉴, 결과 영역 탭, 첫 화면의 옛 행동 문구)을 찾는 불일치였습니다. 제품 UI를 되돌리지 않고 E2E가 현재 계약을 검증하도록 고쳤습니다.
- 1280px에서는 양쪽 도크를 열 때 720px 미리보기 최소 폭이 보장되지 않아 단일 도크가 정상이라는 폭 조건을 명시했고, 전체화면 도크 시험은 레이아웃 폭 측정 뒤에만 토글하도록 바꿨습니다. 라이브러리 필터·설정 버튼은 범위가 좁은 선택자로 바꿔 짧은 이름이 다른 버튼과 부분 일치하지 않게 했습니다.
- 코드리뷰 뒤 `Escape`로 접힌 전체 메뉴가 닫히지 않는 실제 조작 결함을 재현했습니다. 상단바가 메뉴와 프로젝트 전환 목록을 Escape로 닫게 고쳤고, 메뉴의 `aria-expanded` 전환과 트리거 초점 복귀를 브라우저 시험으로 확인했습니다. URL 문자열은 제외하되 실제 접근성 이름·연결 텍스트에서 내부 식별자가 보이지 않는지도 다시 검사합니다.

## 검증 근거

- 웹 전체: `apps/web`에서 `npx vitest run --silent` — 96개 파일, 1,282개 통과.
- 웹 타입: `apps/web`에서 `npx tsc --noEmit` — 통과.
- 이동 단위 시험: 경로 계산 9건, 상단바 17건, 라우터 50건, CSS 계약 3건을 RED→GREEN으로 확인했습니다.
- 컨테이너: `./scripts/owner-ready.ps1 -Mode Start -Rebuild -WithYujinMemory`로 재빌드·기동 후 `/health`와 `/api/projects`가 200인 것을 확인했습니다.
- 실제 브라우저: 직접 연 `/footage`의 이전 버튼이 `/library`로 가는 것, 프로젝트 목록에서 라이브러리로 이동한 뒤 이전 버튼이 목록으로 돌아가는 것, `/projects` 직접 진입 시 이전 버튼이 없는 것, 375px 폭에서 조밀한 상단 조작이 유지되는 것을 확인했습니다. 툴팁 문구 `프로젝트와 도구 메뉴 열기`도 노출을 확인했습니다.
- 백엔드 전체(해시 갱신 뒤 재실행): `.venv\\Scripts\\python.exe -m pytest` — 4,046 통과 / 56 건너뜀 / 경고 1건. 출처 무결성 포함 전체 회귀를 통과했습니다.
- 배선 정적 점검: `api.ts` 메서드 197개 중 화면 생산 코드에서 이름이 닿는 것은 175개, 닿지 않는 것은 22개입니다. 이 수치는 "모든 백엔드 기능이 화면에 연결됐다"는 뜻이 아닙니다.
- 컨테이너 역방향: 공식 재빌드 뒤 `/health` 200, `/api/projects` 200과 실제 15개 프로젝트 응답을 확인했습니다. 브라우저에서 `프로젝트 → 내 라이브러리 → 이전 → 프로젝트`, `편집 → 확인과 내보내기(/review) → 이전 → 편집`, 직접 연 `촬영본 정리 → 이전 → 내 라이브러리`, 목록 보기 방식 변경 뒤 새로고침 유지까지 확인했고 콘솔 오류는 없었습니다.
- 브라우저 전체 회귀(수정 뒤 단독 실행): `apps/web`에서 `npx playwright test --reporter=line` — 47개 통과. 처음 확인한 16건의 실패는 남지 않았습니다.
- 웹 전체 재확인: `npx vitest run` — 96개 파일, 1,282개 통과. `npx tsc --noEmit` — 통과.

## 검증했지만 못 끝낸 것

- 화면 생산 코드에 이름조차 없는 API 22개는 대표님 결정에 따라 `화면에 붙일 것 / 지울 것 / 그대로 둘 것`으로 분류해야 합니다. 이 검증 턴에서는 구현·삭제하지 않았습니다.
- 컨테이너 기동 직후 첫 `/api/projects` 요청에서 502가 한 번 있었고, 재시도 뒤에는 200이었습니다. 이번 이동 기능의 재현 결함으로 단정하지 않았으며, 다음 컨테이너 기동에서도 반복되는지 관찰이 필요합니다.
- 외부 게시·업로드와 provider/live 환경은 실행하지 않았습니다.

## 목요일에 화면으로 확인해야 할 것

- 실제 대표님 프로젝트에서 상단 경로와 작은 이전 버튼이 찾기 쉬운지, 버튼 밀도가 과하지 않은지 확인합니다.
- 좁은 화면에서 경로가 긴 프로젝트 이름과 함께 잘려도 현재 위치를 오해하지 않는지 확인합니다.
- 툴팁 지연 시간과 문구가 마우스 작업을 방해하지 않는지, 키보드 초점 사용자에게도 충분히 설명되는지 확인합니다.
- 기존 승인 팔레트·상단 배치가 의도치 않게 달라지지 않았는지 확인합니다. 이는 브라우저 DOM·동작 검증만으로 수용 완료라고 할 수 없습니다.
